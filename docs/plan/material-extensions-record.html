glTF 재질 확장 구현 기록

2026-11-16 · 알파 로메오와 USN-Hornet 같은 Blender 모델이 쓰는 glTF 확장 KHR_materials_ior, specular, clearcoat, transmission 과 알파 블렌드(alphaMode BLEND)를 엔진이 읽고 그리게 한 작업의 기록입니다.

기준: 작업 트리(아직 커밋하지 않음). 경로는 SherlockEngine/ 기준입니다. D3D11·D3D12 에서 Debug 로, Release 는 D3D11·D3D12 로 씬을 열어 오류 없이 그려지는 것까지 확인했습니다.

1. 출발점

  • 모든 모델이 Blender 의 glTF 익스포터가 내보낸 pbrMetallicRoughness 라서 "두 가지 형식"을 따로 지원할 필요는 없었습니다. 셰이더는 이미 계수 × 텍스처 를 계산하고, 텍스처가 없으면 흰색이라 계수만 쓰입니다.
  • 임포터가 읽지 않던 것은 확장입니다. 모델 14개 중 확장을 쓰는 것은 3개입니다.
모델확장값
AlfaRomeo_1933clearcoat, transmission, alphaMode BLEND 5개clearcoat 1.0 / 거칠기 0.04, transmission 1.0 (각 2개 재질)
USN-Hornetspecular, ior, alphaMode BLEND 5개ior 1000 (83개), specularColorFactor 0.05, specularColorTexture 6개
DarkDragonspecularspecularTexture 2개
그 밖의 11개없음—
ior 1000 은 specular 와 함께 읽어야 합니다. Blender 는 Principled 의 Specular 를 ior 1000 + specularColorFactor 로 내보냅니다. ior 만 읽으면 F0 = ((ior−1)/(ior+1))² ≈ 0.996 이 되어 비금속이 거울처럼 보입니다.

2. 구현 순서와 내용

1ior + specular

비금속의 반사율을 three.js 와 같은 식으로 계산합니다.

f0Ior   = ((ior − 1) / (ior + 1))²
F0      = lerp( min(f0Ior · specularColor, 1) · specularWeight,  baseColor,  metallic )
F90     = lerp( specularWeight,  1,  metallic )          // specularWeight = specularFactor · specularTexture.a
  • 기본값(ior 1.5, specular 1, 흰색)은 F0 = 0.04, F90 = 1 로 이전 결과와 같습니다.
  • 프레넬 함수(직접광, IBL)와 BRDF LUT 항이 F90 을 쓰도록 바꿨습니다: F0 · A + F90 · B.
  • 텍스처: specularTexture(t5, 선형, A 채널), specularColorTexture(t6, sRGB).

2clearcoat

  • 코팅은 F0 0.04 의 두 번째 GGX 로브입니다. 직접광마다 코팅 노멀로 D · G · F / (4 · NdotL · NdotV) 를 더하고, 기본 층은 1 − clearcoat · Fc 만큼 줄입니다. IBL 은 같은 split-sum 을 코팅 노멀·코팅 거칠기로 한 번 더 계산합니다 (EnvironmentClearcoat).
  • 코팅 노멀 맵이 없으면 평평한 노멀이 꽂혀 기하 노멀과 같아집니다. glTF 규격대로 코팅은 기본 층의 노멀 맵을 따르지 않습니다.
  • 텍스처 3장(세기 R, 거칠기 G, 코팅 노멀)은 재질 셋의 t0~t7 이 차서 t16~t18 에 둡니다. SRV 레지스터 상한은 32 이고 프레임 셋이 t8~t15 를 씁니다.
  • 셰이더에서 분기 안에서 샘플하지 않고 항상 샘플합니다 (그래디언트 계산은 균일한 흐름에서만 안전).

3alphaMode BLEND + transmission

  • 엔진에는 블렌딩 경로가 없었고 BLEND 를 MASK(알파 0.5 컷아웃)로 처리했습니다. 이제 Material::alphaBlend 로 보관하고, IsBlended(material)(alphaBlend 또는 transmission > 0)인 재질은 별도 PSO 로 그립니다.
  • PSO: 블렌드 One / InvSrcAlpha(셰이더가 rgb 에 알파를 미리 곱해 내보냄), 깊이는 테스트만 하고 쓰지 않습니다. PSO 키에 비트 11 을 추가했습니다.
  • 그리기 순서: 불투명 → 하늘 → 블렌딩 항목을 카메라에서 먼 것부터(오브젝트 경계 구 중심 기준) → 디버그 선. 하늘 패스가 PSO 를 바꾸므로 직전 상태 기억을 비우고 프레임·오브젝트 셋을 다시 꽂습니다. BuildDrawList 의 정렬 키 맨 앞에 blended 를 두어 불투명이 앞에 옵니다.
  • 블렌딩 재질은 그림자를 만들지 않습니다. 그림자 맵은 불투명한 차폐만 담고, 반투명은 알파가 없어 통째로 가리기 때문입니다.
  • transmission 은 근사입니다. 배경을 굴절시키지 않고, 비금속의 확산을 transmission 만큼 줄이는 대신 알파를 1 − transmission · (1 − 시선 프레넬) 로 낮춰 뒤가 그대로 비치게 합니다. 반사(스페큘러)는 줄이지 않고, 틴트는 없습니다.

4. 검증

  • 솔루션 전체 Debug·Release 빌드 통과.
  • Debug 실행 로그의 바인딩 대조 70건이 모두 OK, cbuffer 'Material' 크기 112 바이트 일치.
  • 임포트 값: 모델을 새 씬에 놓아 저장한 JSON 으로 확인했습니다. Hornet 은 ior 1000 이 83개, specularColor 0.05 가 82개, specularColorTexture 가 6개. DarkDragon 은 specularTexture 2개. 알파 로메오는 clearcoat (1.0, 0.04) 2개, transmission 1.0 이 2개, alphaBlend 3개.
  • 화면: 알파 로메오에서 clearcoat 를 켠 씬과 끈 씬을 같은 카메라로 비교하면 씬 뷰 픽셀 13,393개가 달라졌고, D3D11 과 D3D12 의 수가 같았습니다. 클리어코트 디버그 뷰에서 차체 재질이 세기 1 로 표시됩니다.
  • 블렌딩 패스: 알파 로메오의 BLEND·투과 재질 5개가 D3D11·D3D12 에서 오류 없이 그려지고, 이전에 컷아웃으로 단단해 보이던 부분이 비칩니다.
  • Release 로 MasterChiefWalk 씬을 D3D11·D3D12 에서 열어 오류 로그가 없는 것을 확인했습니다.
확인하지 못한 것
  • 기존 모델이 이전과 픽셀 단위로 같다는 비교는 하지 않았습니다. 이전 빌드를 보관하지 않았고, 기본값이 F0 0.04·F90 1 로 수식이 같다는 점으로 갈음합니다.
  • SherlockGame.exe(게임 모드)는 실행해 보지 않았습니다.
  • specularTexture 와 클리어코트 텍스처의 화면 효과는 눈으로 확인하지 못했습니다(알파 로메오의 clearcoat 는 계수만 있음).

5. 알아 둘 점 · 남은 일

  • 기존 씬은 재임포트 전까지 값이 비어 있습니다. 씬 JSON 이 재질을 통째로 저장하므로 MasterChiefWalk.json 의 모델 재질에는 새 필드가 없어 기본값으로 그려집니다. 또 BLEND 재질은 이전에 저장된 alphaCutoff 0.5 가 그대로 남아 컷아웃으로 그려집니다. 모델을 다시 놓거나 에디터에서 Alpha blend 를 켜야 새 경로를 탑니다.
  • 씬 값이 원본에서 벗어나는 문제. 알파 로메오 재질 89개가 전부 roughness 0.5 / metallic 0(Material 의 기본값)이었던 원인은 찾지 못해 이번에는 스크립트로 glTF 값을 다시 써 넣었습니다(MasterChiefWalk.json.bak 에 원본). 같은 어긋남이 SiegeTank·Tychus_Gun·Viking·BlackDragon 에 재질 2개씩 남아 있으나 의도한 편집일 수 있어 건드리지 않았습니다. "모델 값으로 되돌리기" 명령을 엔진에 넣는 것이 근본 해결입니다.
  • IOR 슬라이더 범위는 1~3 이라 Hornet 의 1000 을 드래그하면 3 으로 잘립니다. Ctrl+클릭으로 직접 입력하거나 범위를 넓혀야 합니다.
  • 투과는 근사입니다. 굴절·거칠기에 따른 흐림·틴트·볼륨(KHR_materials_volume)이 없습니다. 제대로 하려면 불투명 씬 컬러의 복사본(밉 포함)을 만들어 읽어야 하는데, RHI 에 텍스처 복사·밉 생성 명령이 없어 양쪽 백엔드에 추가가 필요합니다.
  • 블렌딩 정렬은 오브젝트 단위 입니다. 한 오브젝트 안의 반투명 삼각형끼리는 정렬하지 않습니다.
  • 디퍼드와의 관계. 다음 순서가 디퍼드라서, clearcoat 는 G-buffer 채널이 더 필요하고 transmission·블렌딩 재질은 포워드로 남겨야 합니다. 이 때문에 디퍼드를 만들 때 이 기록의 클리어코트 부분을 다시 손봐야 합니다.
  • 아직 읽지 않는 확장이 더 있습니다: KHR_materials_volume, sheen, anisotropy, iridescence 등. 지금 모델들에는 쓰이지 않습니다.
