2. 개념: 속도 버퍼 · 모션 블러 · TAA

2.1 속도 버퍼

픽셀마다 "이 표면이 지난 프레임에는 화면 어디에 있었나"를 담는 텍스처입니다. 정점 셰이더가 같은 정점을 이번 프레임 행렬과 지난 프레임 행렬로 두 번 투영해 클립 좌표 두 개를 넘깁니다. 픽셀 셰이더가 둘을 NDC 로 나눈 차이를 UV 단위로 씁니다. 값은 velocity = uv현재 − uv이전 이고, 받는 쪽은 uv이전 = uv − velocity 로 히스토리를 찾습니다.

2.2 카메라 속도와 오브젝트 속도

깊이 재투영(깊이 → 월드 → 이전 ViewProj)은 "모든 픽셀이 월드에 정지해 있다"고 가정합니다. 그래서 움직이는 오브젝트의 속도는 틀립니다. 속도 버퍼는 정점마다 이전 World(스킨이면 이전 팔레트)를 쓰므로 두 움직임이 합쳐진 결과가 나옵니다. 카메라와 같이 움직이는 캐릭터는 화면 속도가 0이 되어 번지지 않습니다. 정지한 물체라면 두 방법의 값이 같아야 합니다. 1단계의 "속도 오차" 뷰는 이 성질로 속도 버퍼를 검사합니다.

2.3 모션 블러 재구성

속도 방향으로 픽셀 앞뒤를 N번 샘플해 평균합니다. 가운데 픽셀의 속도만 쓰면 빠른 물체가 정지한 배경 위로 번져 나가지 못하고(실루엣 안에서만 번짐), 배경이 전경 위로 새어 들어옵니다. McGuire 2012 의 샘플 가중치를 씁니다. 샘플이 가운데보다 앞에 있으면 샘플의 속도를, 뒤에 있으면 가운데의 속도를 기준으로 "이 샘플이 가운데 픽셀까지 번져 오는가"를 따집니다. 원 논문의 타일 최대 속도(TileMax/NeighborMax) 패스는 2단계에서 선택으로 남깁니다.

2.4 TAA

투영을 프레임마다 픽셀보다 작게 흔들어(지터) 같은 픽셀이 매번 다른 위치를 샘플하게 하고, 지난 결과(히스토리)와 섞어 여러 프레임에 걸친 슈퍼샘플링을 얻습니다. 히스토리는 속도로 재투영해서 읽습니다. 가려졌다가 드러난 곳이나 속도가 틀린 곳에서는 히스토리 색이 맞지 않으므로, 이번 프레임 3×3 이웃의 색 범위로 히스토리를 잘라 냅니다(이웃 클램프·분산 클리핑). 잘라 내기가 약하면 고스팅이 생기고, 강하면 깜빡임과 흐림이 남습니다.

2.5 지터와 속도를 떼어 두기

래스터화에는 지터를 넣은 ViewProj 를 쓰고, 속도 계산에는 지터 없는 현재·이전 ViewProj 를 씁니다. 지터를 속도에 넣으면 정지한 화면에서도 속도가 0이 아니게 됩니다. 그러면 모션 블러가 떨리고, TAA 가 지터를 되돌려 버려 수렴하지 않습니다.

3.7 리뷰 때 특히 볼 곳

테스트가 직접 찌르지 않지만 사용자가 가장 먼저 부딪힐 만한 다섯 가지입니다. 각 항목의 확인은 해당 단계 검증 표에 넣었습니다.

  1. 에디터 씬 뷰 크기 변경과 미리보기 카메라 바꾸기. 히스토리가 남으면 한 프레임 동안 이전 화면이 겹쳐 보입니다. 바뀐 직후 프레임이 깨끗해야 합니다. → 3단계 검증 "리셋".

2단계-2 셰이더 MotionBlurPixelShader.hlsl 새

  1. 가운데 속도 vc(픽셀) = 속도 × 크기 × 셔터 배율이고, 길이를 최대 반경으로 자릅니다. 0.5 픽셀보다 짧으면 가운데 색을 그대로 냅니다.
  2. 샘플 오프셋은 ti = (i + 0.5 + 노이즈) / N − 0.5, i = 0..N−1 입니다. 노이즈는 픽셀 좌표의 Interleaved Gradient Noise 이고 프레임과 무관합니다(스크린샷이 결정적임). 샘플 위치는 uv + ti · vc 입니다.
  3. 샘플마다 선형 깊이(clusterParams 의 near/far 로 변환)와 샘플 자신의 속도 vs 를 읽습니다. McGuire 가중치는 w = 앞(zs, zc)·cone(d, |vs|) + 앞(zc, zs)·cone(d, |vc|) + cylinder(d, |vs|)·cylinder(d, |vc|)·2 입니다. 여기서 앞 은 부드러운 깊이 비교이고 d 는 픽셀 거리입니다.
  4. 가운데 샘플도 가중치 1 / |vc| 로 더하고 가중 평균을 냅니다.

입력은 temporalSet(t13 hdr, t23 깊이, t7 속도)이고 출력은 scratch.temp 입니다. 뒤이어 PS_Post 모드 0 으로 temp → hdr 복사합니다. EnsurePostScratch 의 needBlur 를 "temp 가 필요함"으로 바꿔 모션 블러만 켜져도 temp 를 만들게 합니다.

2단계-5 위험

  • 실루엣 밖 번짐 없음: 타일 최대 속도 없이는 빠르게 지나가는 작은 물체 뒤로 꼬리가 생기지 않습니다. 2-3 이 해결합니다.
  • 에디터 조작 중 블러: 씬 뷰에서 카메라를 움직이거나 기즈모로 오브젝트를 끌면 번집니다. 실제 움직임이라 맞는 동작이지만, 편집이 불편하면 "편집 모드에서는 끔" 옵션을 나중에 추가합니다.

3단계 — TAA RHI 확장 없음

목표투영 지터와 히스토리 누적으로 기하 계단, 셰이딩 깜빡임, SSAO 잡음을 줄입니다. 선행 조건1단계(속도, Layout_Temporal), 2단계(복사 모드) 공존 규칙꺼져 있으면 지터도 없습니다(b0 의 행렬이 2단계와 같음). 디버그 뷰가 켜지면 건너뜁니다. 정답 화면정지 화면에서 기울어진 가장자리 계단이 사라집니다. 지터 0 + 피드백 1 이면 끈 화면과 같습니다.

3단계-1 지터

  • 위상 k = view.temporal.frameIndex % 8 입니다. 오프셋(픽셀)은 (Halton(k+1, 2) − 0.5, Halton(k+1, 3) − 0.5) 이고, NDC 로는 jx = 2·ox / width, jy = −2·oy / height 입니다.
  • frameIndex 는 뷰마다 셉니다. 실행마다 같은 프레임에서 같은 위상이므로 편집 모드 스크린샷이 결정적입니다.
  • UploadPerFrameConstants 가 proj, viewProj, invViewProj 에 J 를 곱합니다(3.2). view 와 unjitteredViewProj 는 그대로입니다. 파티클 빌보드와 디버그 선은 b0 를 쓰므로 같이 흔들립니다. 그림자 뷰와 컬링은 흔들리지 않습니다.
  • RenderSettings::taaJitter(기본 true)와 --taa-jitter=0 은 검증용입니다.

3단계-2 리졸브 TaaPixelShader.hlsl 새

  1. 속도 팽창: 3×3 에서 깊이가 가장 가까운 픽셀의 속도를 씁니다(가장자리 안티에일리어싱이 배경 속도를 따라가지 않게).
  2. prevUV = uv − velocity. 화면 밖이거나 temporalParams.z == 0 이면 이번 색을 그대로 냅니다.
  3. 히스토리는 Catmull-Rom 5탭(s6 선형 샘플러)으로 읽습니다. 쌍선형보다 흐림이 적습니다.
  4. 이번 프레임 3×3 이웃을 YCoCg 로 바꿔 평균 μ, 표준편차 σ 를 구합니다. 히스토리를 [μ − γσ, μ + γσ] 상자(γ = 1.0) 쪽으로 클리핑합니다(AABB 중심 방향 클리핑).
  5. 섞기: out = lerp(history, current, α), α = taaFeedback(기본 0.1)입니다. α ≥ 1 이면 맨 앞에서 이번 색을 그대로 냅니다. YCoCg 왕복과 가중치 계산을 거치지 않으므로 배관 검증이 비트 단위로 같아야 합니다. HDR 반딧불이 깜빡임을 막으려고 두 색에 1 / (1 + luma) 가중치를 줘서 섞고 되돌립니다(Karis 2014).
  6. 출력은 history[current] 입니다. 이어서 historyPostSet[current] → hdr 로 복사(모드 0)하고 current 를 뒤집습니다.

3단계-3 설정

taaEnabled(false), taaFeedback(0.1, 0.02~1)을 PostProcessSettings 에 넣습니다. --taa=0|1 오버라이드를 둡니다. 텍스처 밉 LOD 음수 바이어스와 샤프닝은 넣지 않습니다. 결과가 흐리다는 의견이 나오면 그때 선택 항목으로 넣습니다.

3단계-4 작업 순서

  • 3-1 히스토리 타깃과 리셋: EnsureTaaTargets, history[2]·셋, 3.6 의 리셋 규칙 전부. 검증: 리사이즈·미리보기 전환·씬 전환 로그, 경고 없음.
  • 3-2 지터: Halton, J 행렬, taaJitter. 검증: taaFeedback = 1 씬에서 --taa-jitter=1 로 종료 프레임을 바꿔 가며(--exit-after=40, 41) 찍으면 두 장이 1픽셀 미만으로 어긋남. --taa-jitter=0 이면 두 장이 같음.
  • 3-3 리졸브 패스: 셰이더, 패스 표, ApplyHdrEffects 맨 앞, 썸네일 "TAA", 설정·직렬화·UI·--taa=. 검증: 아래 표.

  • 단계별 썸네일: 썸네일은 TAA 결과를 다시 톤매핑할 뿐이라 영향이 없지만, 썸네일 패스가 hdr 를 바꾸지 않는지 다시 확인합니다.
