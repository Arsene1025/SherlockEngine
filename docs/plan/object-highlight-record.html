오브젝트별 강조·디졸브 구현 기록

2026-11-26 · 피격 때 붉게 번쩍이는 효과처럼 재질은 공유한 채로 오브젝트 하나만 색을 바꾸는 기능을 넣은 작업의 기록입니다. 강조 효과는 세 가지(색 섞기, 발광 번쩍임, 가장자리 빛)입니다. 값은 새 Highlight 컴포넌트에 두고, 드로우마다 올리는 b1 PerObject 상수 버퍼에 실어 픽셀 셰이더가 읽습니다(1~5장). 이어서 넣은 디졸브는 진행도를 b1 에, 노이즈를 재질 셋(t20)에 두고, 그림자 패스에 알파 테스트 변형을 더해 그림자까지 같이 사라지게 했습니다. 이 변형은 컷아웃 재질의 그림자에도 쓰여서 잎 모양 그림자가 생겼습니다(7장).

기준: 작업 트리(아직 커밋하지 않음), 바로 앞 커밋 1fc0e12. 경로는 SherlockEngine/ 기준이고, 테스트 씬과 스크립트는 Projects/SherlockTestScenes/ 기준입니다. D3D11·D3D12, 디퍼드·포워드에서 확인했습니다. 1~5장은 강조만 들어갔을 때의 기록이라 b1 크기를 240 B 로 적었습니다. 디졸브까지 들어간 지금도 256 B 입니다. 디졸브는 float4 하나와 번쩍임의 남는 칸(highlightFlash.a)을 씁니다(7.1).

1. 왜 재질도 셰이더도 아니고 b1 인가

방법문제
재질 옵션Renderer::GetOrCreateGpuMaterial 은 GPU 재질을 Material 포인터 기준으로 캐시하고, 재질 상수(b3)는 프레임에 한 번 올립니다. 그래서 재질 색을 바꾸면 그 재질을 쓰는 오브젝트가 전부 바뀝니다. 오브젝트마다 재질 복사본을 만들면 재질 캐시와 ResourceSet 이 그만큼 늘어납니다.
셰이더 변형PSO 가 포워드·G-buffer·스킨·바다·블렌드 조합으로 나뉘어 있어서, "강조" 변형을 더하면 모든 조합이 두 배가 됩니다. 0.1초 번쩍일 때마다 PSO 도 바뀝니다.
b1 PerObject (고른 방법)b1 은 이미 드로우마다 UpdateBuffer 로 올리고 있습니다. 여기에 float4 세 개(48 B)를 더하면 재질과 PSO 는 그대로 공유됩니다. 유니티의 MaterialPropertyBlock, 언리얼의 Custom Primitive Data 와 같은 생각입니다.

세 효과 모두 값이 0 이면 결과가 그대로 나오도록 짰습니다(lerp(x, c, 0) 과 + 0). 그래서 셰이더 분기도 PSO 변형도 없이 모든 메시 드로우가 같은 코드를 탑니다. 강조가 없는 씬은 바뀌기 전과 픽셀이 완전히 같습니다(5장).

2. 쓰는 법

오브젝트에 Add Component → Highlight 를 붙입니다. 모델은 루트 아래에 자식 메시로 들어오므로 루트에 붙이면 모든 자식이 물려받습니다. 자손이 자기 Highlight 를 가지면 그 아래로는 가까운 쪽이 이깁니다. 꺼진(enabled = false) 컴포넌트는 없는 것으로 봅니다.

필드뜻기본
tintColor, tintAmount기본색(알베도)을 이 색 쪽으로 섞음 [0, 1]. 조명을 받은 색이 됩니다. 금속도 색이 바뀝니다(4장).빨강, 0
flashColor, flashIntensity발광에 색 × 세기를 더함. 조명과 상관없이 밝아집니다(HDR, 1 을 넘어도 됨).흰색, 0
rimColor, rimIntensity, rimPower가장자리 빛 (1 − N·V)rimPower × 색 × 세기를 발광에 더함. 지수가 클수록 테두리가 얇습니다.주황, 0, 3

색은 재질의 Base color 처럼 선형 값 그대로 씁니다(인스펙터의 ColorEdit4 값, 알파는 무시). 범위는 렌더러가 자릅니다: 섞는 양 [0, 1], 세기 ≥ 0, 지수 ≥ 0.1.

피격 연출 예: HitFlash 스크립트

컴포넌트는 값만 들고 있고 시간에 따라 바꾸지 않습니다. 연출은 스크립트가 만듭니다. 실험 프로젝트에 예제를 두었습니다(Projects/SherlockTestScenes/Scripts/Tests/HitFlash.h/.cpp).

Highlight* highlight = GetOwner().GetBehaviour<Highlight>();
//맞은 순간 1 → duration 뒤 0
const float k = std::clamp(1.0f - m_elapsed / duration, 0.0f, 1.0f);
highlight->tintAmount = peakTint * k;
highlight->flashIntensity = peakFlash * k;

예제는 interval 초마다 맞은 것으로 칩니다. 실제 게임에서는 "맞았을 때" 이벤트에서 m_elapsed = 0 으로 되돌리면 됩니다. 가장자리 빛은 건드리지 않으므로 "선택됨"이나 "무적" 같은 상태 표시를 씬에 따로 둘 수 있습니다.

4. 셰이더와 결정한 것

float3 HighlightAlbedo(float3 albedo)
{
    return lerp(albedo, highlightTint.rgb, saturate(highlightTint.a));
}

float3 HighlightEmission(float3 geometricNormal, float3 worldPosition)
{
    const float3 viewDirection = SafeNormalize(cameraPosition - worldPosition, float3(0.0f, 0.0f, -1.0f));
    const float rim = pow(saturate(1.0f - saturate(dot(geometricNormal, viewDirection))), max(highlightRim.a, 0.1f));
    return highlightFlash.rgb + highlightRim.rgb * rim;
}
결정이유
색 섞기는 F0 를 만들기 전에금속은 확산이 없고 F0 = 기본색입니다. 나중에 알베도만 바꾸면 금속 부품은 색이 안 바뀝니다. 테스트 씬의 D_Metal 상자가 갈색에서 검붉은색으로 바뀌는 것으로 확인했습니다.
가장자리 빛은 기하 노멀(노말맵 전)로실루엣을 따라야 하는 효과라서입니다. 노말맵 노멀을 쓰면 표면의 잔무늬가 테두리처럼 반짝입니다.
디퍼드는 G-buffer 패스에서 계산라이팅 패스는 화면 픽셀만 보고 어느 오브젝트인지 모릅니다. 그래서 가장자리 빛과 번쩍임을 GBufferPS 에서 발광 칸에 미리 넣습니다. 포워드와 같은 함수(EvaluateMaterialSurface)라 두 경로가 따로 놀지 않습니다.
지수 0.1 하한을 C++ 와 셰이더 양쪽에pow(0, 0) 은 NaN 이고 NaN × 0 도 NaN 이라, 강조가 없는 오브젝트에서 블룸·TAA 로 번질 수 있습니다. 셰이더에서도 max 로 자르는 것은 상수 버퍼가 어떤 이유로든 0 일 때를 대비한 것입니다.
그림자 패스에도 강조 셋을 채워 올림그림자 VS 에는 PS 가 없어 읽지 않지만, PerObjectConstants perObject; 는 초기화되지 않은 지역 변수라 칸을 비워 두면 쓰레기 값이 올라갑니다. 모든 경로에서 세 칸을 대입합니다.
디버그 뷰에서는 번쩍임·가장자리 빛이 안 보임G-buffer 경로는 디버그 뷰가 켜지면 발광을 0 으로 쓰고, Shading.hlsli 의 SurfaceDebugColor 는 발광을 쓰는 뷰가 없습니다. 그래서 번쩍임과 가장자리 빛은 조명 화면(뷰 0)에서만 보입니다. 색 섞기는 알베도를 바꾸므로 알베도 뷰(1)에도 나타납니다.

6. 남은 일

  • 디졸브 — 구현했습니다(7장). 남은 것: 메시 UV 를 노이즈 좌표로 쓰므로 UV 섬 경계에서 무늬가 끊기고, UV 가 없거나 겹친 모델은 무늬가 이상합니다. 그런 모델용으로 오브젝트 공간 좌표(트라이플래너) 방식을 고를 수 있게 하는 것은 하지 않았습니다. 움직이는 경계를 TAA 를 켠 상태에서 따로 보지는 않았고, 컷아웃 재질이 많은 씬에서 그림자 패스가 PS 를 돌리게 된 비용(Sponza 는 26 개 중 3 개)도 시간으로 재지 않았습니다. 파티클·UI 에는 디졸브가 없습니다.
  • 짧은 번쩍임과 TAA — 한두 프레임짜리 번쩍임은 TAA 히스토리와 섞여 흐려질 수 있습니다. TAA 를 켠 씬에서 HitFlash 를 확인하지는 않았습니다. duration 기본 0.15초는 60fps 기준 약 9 프레임이라 크게 문제 되지 않을 것으로 보지만, 더 짧게 할 때는 TAA 를 켜고 화면으로 확인해야 합니다.
  • 다른 문서의 낡은 숫자 — 디졸브 작업 때 현재형 문서를 고쳤습니다: overview/rendering-analysis.html(b1 크기·단계, 재질 셋 t20, 그림자 패스의 PS), study/binding-study.html 슬롯 표, study/velocity-buffer-study.html 의 b1 크기. 계획 문서(velocity-motionblur-taa-plan, ocean-gerstner-plan)는 그 시점의 기록이라 그대로 둡니다.

7. 디졸브

강조와 같은 날 이어서 넣었습니다. 노이즈 값이 문턱보다 작은 픽셀을 버려서 몸이 타 들어가듯 사라지게 하고, 문턱 바로 위의 띠에 발광을 더해 타는 테두리를 만듭니다. 강조와 달리 텍스처(노이즈)와 그림자 패스의 PS 가 필요해서 b1 만으로는 끝나지 않았습니다.

7.1 값을 어디에 두었나

값자리이유
진행도, 경계 폭, 경계 색 × 세기새 Dissolve 컴포넌트 → b1 dissolveEdge(rgb 경계 빛, a 진행도)와 highlightFlash.a(경계 폭). PerObjectConstants 240 → 256 B오브젝트마다 다르고 매 프레임 바뀝니다. 강조와 같은 이유로 b1 입니다. 경계 폭을 번쩍임의 남는 칸에 둔 이유는 아래 상자.
노이즈 텍스처Material::dissolveNoiseTexture → 재질 셋 t20텍스처는 상수 버퍼에 못 넣습니다. 재질 셋은 재질마다 하나씩 이미 만들어 두므로 칸 하나만 늘리면 됩니다. 상용 엔진도 "노이즈는 재질 파라미터(기본값 있음), 진행도는 인스턴스 값"으로 나눕니다.
노이즈 UV 배율Material::dissolveNoiseScale → b3 의 예전 padding1 자리 (오프셋 100)무늬 크기는 노이즈와 짝이라 재질에 둡니다. MaterialConstants 크기(112 B)는 그대로입니다.
b1 을 256 B 로 맞춘 이유. 처음에는 float4 두 칸(진행도·폭, 경계 색)을 더해 272 B 로 만들었습니다. 그런데 D3D12 는 상수 버퍼 크기를 256 단위로 올리고(D3D12Device.cpp 의 CreateBuffer, 루트 CBV 정렬), 업로드 링에서 UpdateBuffer 한 번마다 그 크기만큼 떼어 갑니다. 272 B 는 512 B 조각이 되어 드로우 하나가 링을 두 배로 씁니다. 8 MB 링으로 그릴 수 있는 일반 드로우가 프레임당 약 32,000 번에서 약 16,000 번으로 줄고(그림자 뷰마다의 드로우 포함), 넘치면 그 갱신은 버려집니다. 다섯 값을 float4 하나와 쓰지 않던 highlightFlash.a 에 넣어 256 B 를 지켰습니다. static_assert(sizeof(PerObjectConstants) == 256) 에 이유를 적어 두었습니다. 셰이더는 DissolveAmount()·DissolveWidth() 로만 읽으므로 칸 배치는 한 곳에 모여 있습니다. 다시 접은 뒤에도 디졸브 화면은 접기 전과 픽셀이 같았습니다(7.6).

재질 칸이 비면 엔진 기본 노이즈 builtin:noise 를 씁니다(다른 텍스처 칸처럼 흰색이 아님). 흰색(1)이면 진행도가 1 이 될 때까지 아무것도 안 사라지다가 한 번에 사라집니다. 기본 노이즈 덕분에 재질이 여러 개인 모델(마스터치프는 재질 4 개)도 칸을 하나도 채우지 않고 사라집니다.

t20 은 후처리 셋의 kSRVSlotBlurWeights(BlurCS 의 가중치 버퍼)와 번호가 같습니다. 두 셋은 같은 패스에서 같이 묶이지 않고, 엔진 시작 때 바인딩 대조 가 패스마다 레이아웃과 셰이더를 맞춰 보므로(BlurCompute t20, ShadowAlpha t20 모두 OK) 겹쳐도 됩니다.

7.2 쓰는 법

Add Component → Dissolve. 계층 규칙은 Highlight 와 같습니다(루트에 붙이면 자손이 물려받고, 가까운 쪽이 이기고, 꺼진 것은 없는 것). 미리 붙여 둘 필요는 없습니다: 재생 중에 스크립트가 AddBehaviour 로 붙여도 다음 순회에서 Start 가 불리고 그 프레임부터 그려집니다(Scene::Update 가 인덱스로 순회함). 미리 붙여 둔 amount = 0 도 비용이 거의 없습니다(아래 7.4).

필드뜻기본
amount진행도 [0, 1]. 0 은 끔, 1 은 완전히 사라짐. 기본 노이즈에서는 사라진 면적의 비율과 거의 같습니다.0
edgeWidth경계 띠의 폭(노이즈 값 단위). 0 이면 테두리 빛 없음0.05
edgeColor, edgeIntensity경계 빛 색 × 세기(선형, HDR)주황, 4

재질 쪽은 인스펙터의 재질 칸과 Materials 탭에 Dissolve noise(텍스처 이름, Enter 로 확정, 비우면 builtin:noise)와 Dissolve noise scale 이 생겼습니다. 이름 규칙은 다른 텍스처 칸과 같고(Assets/Textures 기준, asset:, builtin:) 선형으로 읽어 R 채널을 씁니다. 씬 파일에는 기본값이 아닐 때만 dissolveNoiseTexture·dissolveNoiseScale 키를 씁니다(예전 씬 파일과 모양이 같음).

연출 예제는 Projects/SherlockTestScenes/Scripts/Tests/DissolveOut.h/.cpp 입니다. Start 에서 Dissolve 가 없으면 붙이고, delay 뒤 duration 초 동안 amount 를 0 → 1 로 올린 뒤 hold 초 쉬고 되풀이합니다.

7.3 셰이더

// Shaders/Dissolve.hlsli
float DissolveNoise(float2 uv)            // uv 는 이미 uvScale 을 곱한 메시 UV
{
    return dissolveNoiseTexture.Sample(albedoSampler, uv * dissolveNoiseScale).r;
}
float DissolveAmount() { return dissolveEdge.a; }                // a: 진행도
float DissolveWidth()  { return max(highlightFlash.a, 0.0f); }   // w: 경계 폭 (번쩍임의 남는 칸)
float DissolveThreshold()                 // t = a(1 + w) − w : a = 0 이면 −w (아무것도 안 버림), a = 1 이면 1 (전부 버림)
{
    return DissolveAmount() * (1.0f + DissolveWidth()) - DissolveWidth();
}
void DissolveClip(float noise)
{
    if (DissolveAmount() > 0.0f) clip(noise - DissolveThreshold() - 0.0001f);
}
float3 DissolveEdgeEmission(float noise)  // 문턱 위 폭 w 의 띠: 문턱에 가까울수록 밝음
{
    if (DissolveAmount() <= 0.0f || DissolveWidth() <= 0.0f) return 0.0f;
    return dissolveEdge.rgb * (1.0f - saturate((noise - DissolveThreshold()) / DissolveWidth()));
}

실제 파일은 같은 식을 if 블록으로 썼습니다. 위는 줄여 옮긴 것입니다.

자리하는 일
BasicPixelShader.hlsl (포워드·블렌드·unlit·바다 포워드)알파 컷아웃 clip 바로 뒤에 DissolveClip. unlit 분기도 경계 빛을 더함
GBufferPixelShader.hlsl (디퍼드·바다 디퍼드)같은 자리에 DissolveClip
MaterialSurface.hlsli 의 EvaluateMaterialSurfaces.emission += HighlightEmission(...) + DissolveEdgeEmission(...) — 포워드는 조명 결과에, 디퍼드는 G-buffer 발광 칸에 들어감(강조와 같은 길)
ShadowAlphaPixelShader.hlsl (새 파일)그림자 패스용. 알파 컷아웃과 디졸브로 버릴 픽셀만 고르고 색은 내지 않음(7.4)
결정이유
노이즈 좌표는 메시 UV사용자가 고른 방식입니다. 계산이 싸고 재질의 UV 배율을 그대로 따릅니다. 대신 UV 섬 경계에서 무늬가 끊기고, UV 가 없는 메시나 UV 가 겹친 모델은 무늬가 이상할 수 있습니다(6장).
기본 노이즈는 엔진이 만듦 (TextureLoader::CreateTileableNoise)256², 격자 8 → 64 의 4 옥타브 값 노이즈(fBm). 가장자리가 이어지도록 격자를 감고, 같은 시드면 항상 같은 결과입니다. 값을 순위로 다시 매겨 [0, 1] 에 고르게 퍼뜨렸습니다. fBm 은 가운데 값이 몰려 있어서 그대로 쓰면 진행도 0.5 근처에서 한꺼번에 많이 사라집니다. 순위로 펴면 amount 가 사라진 면적 비율과 거의 같아집니다(밉으로 흐려지는 먼 곳은 예외).
문턱 식 a(1 + w) − w경계 띠 폭만큼 문턱을 아래로 밀어서, 시작할 때(a 가 0 에 가까울 때) 아직 아무것도 안 버린 표면에 띠만 먼저 나타나고, a = 1 에서 띠까지 모두 사라지게 했습니다. clip 의 0.0001 여유는 노이즈 값 1(255)인 픽셀이 a = 1 에서 남지 않게 합니다.
a = 0 이면 아무것도 안 함DissolveClip·DissolveEdgeEmission 이 모두 DissolveAmount() > 0 을 봅니다. 컴포넌트가 없는 오브젝트는 b1 칸이 0 이라 같은 길을 탑니다. 강조와 마찬가지로 셰이더 변형이 없습니다.
메인 패스의 early-Z메인 PS 와 G-buffer PS 에는 원래 알파 컷아웃 clip 이 있었습니다. 그래서 clip 이 하나 더 들어가도 셰이더의 성질(깊이를 PS 뒤에 쓰는지)은 바뀌지 않습니다. 그림자 패스는 아래처럼 필요한 드로우만 PS 있는 변형으로 보냅니다.

7.4 그림자: 알파 테스트 변형

그림자 패스(Pass_Shadow·Pass_ShadowSkin)는 VS 만 있고 셋도 프레임·오브젝트 둘뿐이라, 그대로 두면 몸이 사라져도 그림자는 남습니다. 그래서 PS 가 있는 변형을 하나 더 만들었습니다.

Pass_ShadowAlpha      ShadowAlphaVS     + ShadowAlphaPS   셋: 프레임, 오브젝트, 재질
Pass_ShadowAlphaSkin  ShadowAlphaSkinVS + ShadowAlphaPS   (깊이 바이어스·포맷은 Pass_Shadow 와 같음 — BuildPassDescs 의 같은 반복문)

BuildDrawList:  item.shadowAlpha = material->alphaCutoff > 0 || 디졸브 중(amount > 0)
                item.shadowPipeline = GetShadowPipelineFor(재질, 정점 형식, mirrored, item.shadowAlpha)   // 키 비트 10
RenderShadowPass: shadowAlpha 인 드로우만, 재질이 바뀔 때 cmd.SetResourceSet(kSetMaterial, gpuMaterial->set)
  • PS 는 메인 패스와 같은 식으로 알파(정점 색 × baseColor × 알베도 텍스처 a)를 구해 컷아웃을 하고, 같은 노이즈·문턱으로 DissolveClip 을 합니다. 그래서 그림자에도 몸과 같은 무늬로 구멍이 납니다.
  • 컷아웃 재질도 이 변형으로 갑니다. 예전에는 나뭇잎 같은 컷아웃 재질의 그림자가 구멍 없이 꽉 찬 다각형이었는데, 이제 잎 모양대로 납니다. 화면이 바뀌는 쪽의 변경이라 따로 측정했습니다(7.6).
  • 디졸브가 없는 불투명 재질은 예전과 같은 PS 없는 빠른 경로입니다. 디졸브도 amount = 0 이면 빠른 경로이고, 0 보다 커지는 프레임부터 변형으로 바뀝니다.
  • D3D12 는 루트 시그니처가 바뀌면 테이블이 다시 묶여야 하므로, 변형 PSO 를 고른 뒤 재질 셋을 꽂습니다. PS 없는 변형의 루트 레이아웃에는 재질 셋이 없어 꽂혀 있어도 ApplyBindings 가 무시합니다.

  • 다시 접은 뒤 — b1 을 272 → 256 B 로 바꾼 뒤 위 표의 씬을 모두 다시 찍었습니다. 디졸브 씬 4 개(Dissolve·DissolveChecker·DissolveHierarchy·DissolveGone) × 3 경로는 접기 전과 픽셀이 같았고(차이 0), Sponza·SponzaCascades 는 잡음 수준(±1 픽셀)만 달랐습니다.
  • 인스펙터 — --select 화면에서 Components 에 Dissolve 와 네 칸(amount·edgeWidth·edgeColor·edgeIntensity)이 나오는 것을 확인했습니다. 재질 쪽 Dissolve noise·Dissolve noise scale 칸은 화면으로 보지 않았습니다(같은 값을 씬 파일로 읽는 경로는 DissolveChecker·DissolveFile 로 확인).
  • 패키지 빌드 — DissolveFile.json 을 시작 씬으로 --build-game --build-minimal=1 로 빌드했습니다. 노이즈 파일이 TextureCache 에 선형 DDS 로 변환돼 실렸고(텍스처 변환본: NormalBumpTest.png (1024x1024, 밉 11, linear)), 패키지 실행 화면이 에디터와 같은 무늬로 사라졌습니다. 빈 칸(builtin:noise)은 실을 파일이 없습니다. 확인한 뒤 빌드 폴더는 지웠습니다.
