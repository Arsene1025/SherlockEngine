텍스처 파이프라인 구현 기록

2026-11-12 · 블록 압축(BC) 텍스처를 압축 그대로 GPU 에 올리고, PNG/JPG 를 읽을 때 BC7 + 밉 체인 DDS 를 자동으로 만들어 캐시하며, 텍스처마다 압축·밉·해상도를 Inspector 에서 고르게 한 작업의 기록입니다. 세 단계를 순서대로 구현했습니다.

기준: 작업 트리(아직 커밋하지 않음). 경로는 SherlockEngine/ 기준입니다. D3D11·D3D12, Debug·Release 와 게임 빌드에서 확인했습니다. 마스터치프는 원본이 이미 DDS 라 이 파이프라인을 거치지 않으므로 측정에서 뺐습니다.

1. BC 직접 업로드

이전에는 BC DDS 를 읽으면 Decompress 로 CPU 에서 R8G8B8A8 로 풀어 올렸습니다. 디스크만 줄고 VRAM 은 그대로였습니다.

  • RHI 포맷 — Format 끝에 BC1/BC3/BC7 (UNORM, UNORM_SRGB) 6개를 추가했습니다(PSO 캐시 키 번호가 바뀌지 않도록 끝에 붙임). IsBlockCompressed(Format) 헬퍼를 두어 번호 비교에 기대지 않습니다. D3D11·D3D12 의 ToDXGI 에 매핑을 추가했습니다.
  • 디바이스 — 고칠 곳이 없었습니다. D3D11 은 서브리소스의 rowPitch 를, D3D12 는 GetCopyableFootprints 의 행 수·행 크기를 쓰므로 블록 단위 레이아웃도 그대로 맞습니다.
  • 로더 (TextureLoader.cpp 의 FinishImage) — 2D 이고 BC1/BC3/BC7 이며 밉 0 의 가로·세로가 4 의 배수이고, 밉이 이미 2개 이상이거나 밉 생성을 요청하지 않았으면 압축 그대로 둡니다. sRGB 라벨은 기존 규칙대로 srgb 인자로 붙입니다. 그 밖의 경우(BC2/BC4/BC5/BC6H, 큐브, 4의 배수가 아닌 크기, 밉 1개 + 밉 생성 요청)는 이전처럼 풀어서 올립니다.

측정

로더가 GPU 에 넘기는 서브리소스 크기의 합입니다. 드라이버가 보고하는 실제 사용량은 정렬 때문에 조금 다를 수 있습니다.

2. 임포트 변환과 캐시

새 Graphics/TextureImporter.h/.cpp 입니다. TextureCache::Load2D 가 모델 내장 이미지와 파일 텍스처 모두 이 함수를 거칩니다.

원본 바이트 → ResolveCached(이름, 바이트, srgb)
   ├ DDS 이거나 변환 불필요 → 원본 그대로 읽음
   ├ 캐시 파일 있음        → 캐시 DDS 를 읽음 (밉 생성 없음)
   └ 없음 + 에디터         → 변환해 캐시에 쓰고 읽음
항목내용
캐시 위치<프로젝트>\Library\TextureCache\<해시>.dds (프로젝트가 없으면 <exe>\TextureCache\). .gitignore 에 Projects/*/Library/ 를 추가했습니다.
캐시 키원본 바이트의 FNV-1a 64비트 + sRGB 여부 + 설정 + 변환기 버전. 같은 원본을 색과 데이터로 쓰면 파일이 둘이 됩니다. 원본이나 설정이 바뀌면 다른 파일이 되어 자동으로 새로 만들어집니다(옛 파일은 남음).
변환WIC 로 읽기 → RGBA8 → 전체 밉 체인(sRGB 는 선형에서 평균) → 설정에 맞게 위쪽 단계 건너뛰기·자르기 → BC7. 임시 파일에 쓴 뒤 이름을 바꾸므로 쓰다 중단돼도 깨진 캐시가 남지 않습니다.
인코더DirectXTex GPU BC7(임시 D3D11 장치, D3D12 백엔드에서도 동일). 실패하면 CPU BC7_QUICK. 4096² 한 장 기준 CPU 약 7초, GPU 포함 전체 약 2.8초. 2048² 는 0.6~1초.
변환 제외이미 DDS 인 원본, 기본 설정이면서 긴 변이 256 미만인 텍스처. 밉 0 이 4의 배수가 아니면 압축하지 않고 RGBA8 DDS 로 저장합니다.
게임 빌드변환하지 않고 캐시가 있으면 쓰며 없으면 원본을 읽습니다(SetBuildEnabled 는 에디터가 켬).
패키징GameBuilder 가 TextureSettings.json(캐시 키에 들어가므로 게임도 같은 설정을 읽어야 함)과 캐시 폴더를 <패키지>\TextureCache\ 로 복사합니다. 쓰이지 않는 옛 캐시도 함께 가는 한계가 있습니다.
설정은 처음 제안한 .meta 사이드카가 아니라 프로젝트 Assets/TextureSettings.json 에 텍스처 이름(재질이 저장하는 이름) 기준으로 둡니다. 모델 내장 이미지는 개별 파일이 아니라서 같은 방식으로 한 곳에서 다루려는 선택입니다. 기본값과 다른 항목만 저장합니다.

3. 설정과 Inspector

설정값기본

mipLevels0 = 전체, 1 = 밉 없음, N = 상위 N단계0
maxSize0 = 원본, 아니면 긴 변이 이 값 이하가 되도록 위쪽 밉을 건너뜀0
  • UI — 재질 패널(DebugUI::DrawTextureImportSettings)과 Inspector 의 모델 재질 칸에 "Texture import" 가 생깁니다. 파일 텍스처 슬롯마다 압축 체크, 밉(All/None/Top N), 최대 해상도(Original~128)를 고르고 Apply 를 누르면 저장한 뒤 그 텍스처만 다시 읽습니다. Revert 로 되돌립니다. 원본이 DDS 면 설정이 적용되지 않는다고 표시합니다.
  • 부분 재로드 — TextureCache::Evict(name) 가 이름 하나의 sRGB·선형 항목을 파괴하고 세대 번호를 올려, 재질 셋이 다음 프레임에 새 텍스처로 다시 만들어집니다(ReleaseLoaded 처럼 전부 지우지 않음). Renderer::ReloadTexture 로 노출했습니다.
  • 검증용 인자 — --tex-setting=이름;압축;밉;최대크기 (12 프레임째 같은 코드 경로).

Inspector 의 Apply 를 마우스로 눌러 보는 검증은 하지 못했고, 같은 경로를 부르는 자동화 인자로 확인했습니다.

겪은 문제

  • 빌드 — windows.h 의 max 매크로 때문에 (std::max) 로 감쌌습니다. HLSL 새 파일에 UTF-8 BOM 이 있으면 fxc 가 Illegal character 로 실패해서 BOM 없이 저장합니다.
  • DirectXTex Resize — 필터를 바꿔도 모두 E_FAIL 이라 쓰지 않았습니다. 전체 밉 체인을 만든 뒤 maxSize 를 넘는 위쪽 단계를 건너뛰는 방식으로 대신했습니다. 한 단계 아래 밉이 그대로 새 원본이 되므로 결과는 같습니다.

4. 남은 일

  • BC5(노멀)·BC4·BC6H(HDR 큐브)는 아직 풀어서 올립니다. 큐브맵의 BC 직접 업로드도 하지 않았습니다.
  • 옛 캐시 파일을 자동으로 정리하지 않습니다. 패키징도 전체 캐시 폴더를 복사합니다.
  • 첫 로드에서 큰 텍스처를 변환하는 동안 에디터가 멈춥니다(캐시되면 한 번뿐). 비동기 변환과 진행 표시는 없습니다.
  • 모델 내장 이미지의 설정 키는 이름(모델/번호 파일명)이라 모델 파일이나 이미지 순서가 바뀌면 설정이 어긋날 수 있습니다.
