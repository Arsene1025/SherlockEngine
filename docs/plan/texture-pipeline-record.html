텍스처 파이프라인 구현 기록

2026-11-12 · 블록 압축(BC) 텍스처를 압축 그대로 GPU 에 올리고, PNG/JPG 를 읽을 때 BC7 + 밉 체인 DDS 를 자동으로 만들어 캐시하며, 텍스처마다 압축·밉·해상도를 Inspector 에서 고르게 한 작업의 기록입니다. 세 단계를 순서대로 구현했습니다.

기준: 작업 트리(아직 커밋하지 않음). 경로는 SherlockEngine/ 기준입니다. D3D11·D3D12, Debug·Release 와 게임 빌드에서 확인했습니다. 마스터치프는 원본이 이미 DDS 라 이 파이프라인을 거치지 않으므로 측정에서 뺐습니다.

1. BC 직접 업로드

이전에는 BC DDS 를 읽으면 Decompress 로 CPU 에서 R8G8B8A8 로 풀어 올렸습니다. 디스크만 줄고 VRAM 은 그대로였습니다.

  • RHI 포맷 — Format 끝에 BC1/BC3/BC7 (UNORM, UNORM_SRGB) 6개를 추가했습니다(PSO 캐시 키 번호가 바뀌지 않도록 끝에 붙임). IsBlockCompressed(Format) 헬퍼를 두어 번호 비교에 기대지 않습니다. D3D11·D3D12 의 ToDXGI 에 매핑을 추가했습니다.
  • 디바이스 — 고칠 곳이 없었습니다. D3D11 은 서브리소스의 rowPitch 를, D3D12 는 GetCopyableFootprints 의 행 수·행 크기를 쓰므로 블록 단위 레이아웃도 그대로 맞습니다.
  • 로더 (TextureLoader.cpp 의 FinishImage) — 2D 이고 BC1/BC3/BC7 이며 밉 0 의 가로·세로가 4 의 배수이고, 밉이 이미 2개 이상이거나 밉 생성을 요청하지 않았으면 압축 그대로 둡니다. sRGB 라벨은 기존 규칙대로 srgb 인자로 붙입니다. 그 밖의 경우(BC2/BC4/BC5/BC6H, 큐브, 4의 배수가 아닌 크기, 밉 1개 + 밉 생성 요청)는 이전처럼 풀어서 올립니다.

측정

로더가 GPU 에 넘기는 서브리소스 크기의 합입니다. 드라이버가 보고하는 실제 사용량은 정렬 때문에 조금 다를 수 있습니다.

2. 임포트 변환과 캐시

새 Graphics/TextureImporter.h/.cpp 입니다. TextureCache::Load2D 가 모델 내장 이미지와 파일 텍스처 모두 이 함수를 거칩니다.

원본 바이트 → ResolveCached(이름, 바이트, srgb)
   ├ DDS 이거나 변환 불필요 → 원본 그대로 읽음
   ├ 캐시 파일 있음        → 캐시 DDS 를 읽음 (밉 생성 없음)
   └ 없음 + 에디터         → 변환해 캐시에 쓰고 읽음
항목내용
캐시 위치<프로젝트>\Library\TextureCache\<해시>.dds (프로젝트가 없으면 <exe>\TextureCache\). (2026-11-26 기준: TextureImporter::GetCacheDir 는 프로젝트가 있고 엔진 루트가 소스 트리일 때만 <프로젝트>\Library\TextureCache\ 를 쓰고, 그 밖에는 프로젝트가 있는 배포본도 <exe>\TextureCache\ 를 씁니다.) .gitignore 에 Projects/*/Library/ 를 추가했습니다.
캐시 키원본 바이트의 FNV-1a 64비트 + sRGB 여부 + 설정 + 변환기 버전. 같은 원본을 색과 데이터로 쓰면 파일이 둘이 됩니다. 원본이나 설정이 바뀌면 다른 파일이 되어 자동으로 새로 만들어집니다(옛 파일은 남음).
변환WIC 로 읽기 → RGBA8 → 전체 밉 체인(sRGB 는 선형에서 평균) → 설정에 맞게 위쪽 단계 건너뛰기·자르기 → BC7. 임시 파일에 쓴 뒤 이름을 바꾸므로 쓰다 중단돼도 깨진 캐시가 남지 않습니다.
인코더DirectXTex GPU BC7(임시 D3D11 장치, D3D12 백엔드에서도 동일). 실패하면 CPU BC7_QUICK. 4096² 한 장 기준 CPU 약 7초, GPU 포함 전체 약 2.8초. 2048² 는 0.6~1초.
변환 제외이미 DDS 인 원본, 기본 설정이면서 긴 변이 256 미만인 텍스처. 밉 0 이 4의 배수가 아니면 압축하지 않고 RGBA8 DDS 로 저장합니다.
게임 빌드변환하지 않습니다(SetBuildEnabled 는 에디터가 켬). 패키지의 변환 목록에 있으면 그 DDS 를, 없으면 캐시 → 원본 순으로 읽습니다.
패키징2026-11-22 부터 변환본만 싣습니다. 아래 4장을 보세요. (처음에는 TextureSettings.json 과 캐시 폴더 전체를 복사해서 옛 캐시와 원본이 함께 갔습니다.)
설정은 처음 제안한 .meta 사이드카가 아니라 프로젝트 Assets/TextureSettings.json 에 텍스처 이름(재질이 저장하는 이름) 기준으로 둡니다. 모델 내장 이미지는 개별 파일이 아니라서 같은 방식으로 한 곳에서 다루려는 선택입니다. 기본값과 다른 항목만 저장합니다.

3. 설정과 Inspector

설정값기본
compressBC7 압축. 끄면 RGBA8 로 저장(밉·크기 설정만 적용)켬
mipLevels0 = 전체, 1 = 밉 없음, N = 상위 N단계0
maxSize0 = 원본, 아니면 긴 변이 이 값 이하가 되도록 위쪽 밉을 건너뜀0
  • UI — 재질 패널(DebugUI::DrawTextureImportSettings)과 Inspector 의 모델 재질 칸에 "Texture import" 가 생깁니다. 파일 텍스처 슬롯마다 압축 체크, 밉(All/None/Top N), 최대 해상도(Original~128)를 고르고 Apply 를 누르면 저장한 뒤 그 텍스처만 다시 읽습니다. Revert 로 되돌립니다. 원본이 DDS 면 설정이 적용되지 않는다고 표시합니다.
  • 부분 재로드 — TextureCache::Evict(name) 가 이름 하나의 sRGB·선형 항목을 파괴하고 세대 번호를 올려, 재질 셋이 다음 프레임에 새 텍스처로 다시 만들어집니다(ReleaseLoaded 처럼 전부 지우지 않음). Renderer::ReloadTexture 로 노출했습니다.
  • 검증용 인자 — --tex-setting=이름;압축;밉;최대크기 (12 프레임째 같은 코드 경로).

겪은 문제

  • 빌드 — windows.h 의 max 매크로 때문에 (std::max) 로 감쌌습니다. HLSL 새 파일에 UTF-8 BOM 이 있으면 fxc 가 Illegal character 로 실패해서 BOM 없이 저장합니다.
  • DirectXTex Resize — 필터를 바꿔도 모두 E_FAIL 이라 쓰지 않았습니다. 전체 밉 체인을 만든 뒤 maxSize 를 넘는 위쪽 단계를 건너뛰는 방식으로 대신했습니다. 한 단계 아래 밉이 그대로 새 원본이 되므로 결과는 같습니다.

4. 게임 패키지에 변환본만 싣기 (2026-11-22)

상용 엔진에서 흔히 쓰는 방식(에디터는 원본과 변환 캐시를 두고, 빌드는 변환본만 싣는 것)을 따라, 원본은 에디터에만 두고 패키지에는 변환된 DDS 와 "이름 → 변환본" 목록만 싣습니다. 원본 PNG/JPG 파일과 .gltf 는 고치지 않습니다. 이전에는 게임이 원본을 읽어 해시를 계산해야 캐시를 찾을 수 있어서 원본과 캐시를 둘 다 실었습니다.

GameBuilder (에디터)
  3a 씬·프리팹 JSON 의 재질 + 그 모델의 재질 → (텍스처 이름, sRGB) 목록
     → TextureImporter::CookForBuild (캐시가 없으면 여기서 변환)
     → 변환본이 생긴 원본 파일은 복사에서 뺌
  3b 쓰인 DDS 만 <패키지>\TextureCache\ 로 복사 + manifest.json

게임
  TextureCache::Load2D → FindCooked(이름, srgb) → DDS 를 바로 읽음 (원본·해시 없음)
  GltfImporter         → HasCooked(이름) 이면 이미지 바이트를 읽지 않음
항목내용
목록 형식{ "version": 1, "textures": { "<이름>": { "srgb": "<해시>.dds", "linear": "<해시>.dds" } } }. 쓰이는 색공간만 있습니다. 요청한 색공간이 없으면 다른 쪽 변환본을 경고와 함께 씁니다(흰색보다 나음).
색공간 규칙albedo 는 albedoSrgb, emissive·specularColor 는 sRGB, 나머지는 선형. Renderer::GetOrCreateGpuMaterial 의 Load2D 호출과 같아야 합니다(GameBuilder.cpp 의 kTextureSlots).
대상 씬에셋 전부 복사면 모든 씬, 아니면 시작 씬. 프리팹은 항상 전부.
작은 텍스처기본 설정에서 256 미만이라 에디터가 변환하지 않던 것도 빌드 때는 압축 없이 RGBA8 + 밉 DDS 로 만듭니다. 원본을 읽을 때 로더가 만드는 것과 같은 결과입니다.
원본을 싣는 경우원본이 이미 DDS(마스터치프), 디코딩 실패, 환경 맵 파일과 면 이미지 폴더 안의 파일(큐브는 변환 캐시를 거치지 않음), 어떤 씬·프리팹도 쓰지 않는 모델의 이미지.
줄지 않는 것GLB·data URI 안의 이미지는 파일을 다시 쓰지 않으므로 용량이 그대로입니다. 게임은 그 바이트를 메모리에 들지 않을 뿐입니다.
다시 빌드<패키지>\TextureCache\ 는 지우고 새로 만들고, 뺀 원본이 이전 빌드에 남아 있으면 지웁니다.

검증 (SherlockTestScenes)

에셋 전부 패키지를 Debug 와 Release(--build-release=1)로 만들고, 씬 26 개 전부를 D3D11·D3D12 에서 실행했습니다(4 조합 × 26). 게임은 --scene 을 받지 않으므로 패키지의 .sherlock 시작 씬을 바꿔 가며 띄웠고, 같은 씬을 소스 트리의 같은 구성 SherlockGame.exe(해시 캐시 경로)로 띄워 90 프레임 스크린샷(--particle-step 고정)을 비교했습니다.

  • 104 번 모두 정상 종료, "흰색으로 대체"·"읽지 못함"·"검은 큐브로 대체"·"변환본이 패키지에 없어" 경고 0 건. 씬마다 읽은 변환본 수는 네 조합이 같습니다(DemoScene 69, MasterChiefWalk 186, DamagedHelmet 5 …).
  • 정적인 씬(Cubemap·DamagedHelmet·MultiShadow·Tree 등)은 픽셀이 같습니다. Sponza 계열은 1~5 픽셀이 다른데, 소스 트리 게임끼리 두 번 돌려도 같은 자리가 달라지고 패키지끼리도 실행마다 값이 바뀌는 타이밍 의존 픽셀입니다. 의심했던 4×4 white.png(빌드 때 새로 RGBA8 로 변환된 유일한 Sponza 텍스처)를 원본으로 되돌려도, 소스 트리 게임이 같은 DDS 를 읽게 해도 결과가 같아 텍스처 내용과는 관계가 없습니다.
  • 차이가 큰 씬은 움직이는 것만 다릅니다: 걷는 마스터치프·드래곤(실시간 애니메이션), demo_components 의 회전 오브젝트, ParticleSpawn 의 파티클.

처음 실행에서 게임이 접근 위반으로 종료했습니다. root.value("textures", …) 가 돌려준 임시 json 에 바로 .items() 를 range-for 로 돌린 탓입니다. range-for 는 바깥 임시 객체(iteration_proxy)만 살려 두므로 json 이 먼저 사라집니다. 지역 변수에 받아 두도록 고쳤습니다.

한계: 스크립트가 재질과 다른 이름 표기(예: asset:Textures\a.png 대신 a.png)로 같은 파일을 런타임에 지정하면, 그 이름은 목록에 없고 원본도 빠져 있어 흰색이 됩니다. 재질이나 프리팹에 같은 이름으로 한 번 쓰이면 목록에 들어갑니다. 또 씬이 쓰는 모델과 스크립트만 놓는 모델이 같은 이미지 파일을 가리키면, 파일은 빠지는데 뒤쪽 모델의 이미지 이름은 목록에 없어서 흰색이 됩니다. 빌드할 때마다 모델을 다시 읽으므로 에디터가 몇 초(시작 씬만)에서 20초(에셋 전부)쯤 멈춥니다.

5. 남은 일

  • BC5(노멀)·BC4·BC6H(HDR 큐브)는 아직 풀어서 올립니다. 큐브맵의 BC 직접 업로드도 하지 않았습니다.
  • 에디터의 옛 캐시 파일을 자동으로 정리하지 않습니다(패키지에는 쓰이는 것만 갑니다).
  • 첫 로드에서 큰 텍스처를 변환하는 동안 에디터가 멈춥니다(캐시되면 한 번뿐). 비동기 변환과 진행 표시는 없습니다.
  • 모델 내장 이미지의 설정 키는 이름(모델/번호 파일명)이라 모델 파일이나 이미지 순서가 바뀌면 설정이 어긋날 수 있습니다.
