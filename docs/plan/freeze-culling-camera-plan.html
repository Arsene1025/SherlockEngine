컬링 카메라 고정 계획

지금은 Freeze cascade camera를 켜면 캐스케이드만 고정된 카메라로 계산되고, 에디터 카메라는 자유롭게 움직이며 그 결과를 밖에서 볼 수 있습니다. 이 계획은 같은 고정 카메라를 오브젝트 절두체 컬링과 조명 컬링에도 써서, 자유 시점으로 돌아다니며 "고정된 시점에서 무엇이 버려졌는지"를 눈으로 확인하게 만드는 것입니다.

디버그 기능이므로 고정하지 않았을 때의 화면과 성능은 지금과 같아야 합니다. RHI 확장도 셰이더 변경도 없습니다.

진행 방식. 1단계에서 Renderer 안에서 컬링에 쓰는 카메라를 그리는 카메라와 분리합니다. 2단계는 컬링된 조명이 자유 시점에서도 꺼져 보이게 하고, 3단계에서 에디터 UI·오버레이·자동화 인자를 붙입니다. 단계마다 스크린샷으로 확인하고 이상이 없으면 다음 단계로 넘어갑니다.

구현 완료 (2026-11-24). 1~3단계를 모두 구현했습니다. 계획과 달라진 점과 검증 숫자는 9장에 있습니다. 요약: 테스트 씬 FreezeCulling.json 을 새로 만듦(CascadeBigScene 기본 시점은 culled = 0), 항목을 고르는 --freeze-parts=col 추가, 오버레이 변을 카메라 앞에서 잘라 그림, 컬링된 오브젝트 윤곽(선택 항목)은 하지 않음.

2. 개념: 컬링 시점과 그리는 시점

보통은 한 카메라가 두 가지 일을 합니다. 무엇을 그릴지 고르는 일(컬링)과, 고른 것을 화면에 투영하는 일(그리기)입니다. 둘을 떼어 컬링은 고정해 둔 사본으로, 그리기는 지금 카메라로 하면, 컬링 결과를 바깥에서 볼 수 있습니다. 고정 시점 절두체 밖에 있어서 버려진 메시는 자유 시점에서 뻥 뚫린 자리로 보입니다.

이 방법으로 잡을 수 있는 문제:

  • 경계 구가 너무 작음. 정점 셰이더가 메시를 경계 밖으로 옮기는 경우(바다 변위, 스킨 메시)에 화면 가장자리에서 메시가 갑자기 사라집니다. 고정하면 절두체 근처에서 버려진 메시가 보입니다.
  • 컬링이 너무 느슨함. 평면별 구 검사(Frustum::Intersects)는 모서리 근처에서 밖에 있는 구를 남깁니다. 고정 절두체 밖인데도 그려지는 메시가 그 몫입니다.
  • 조명·그림자 선택. 그림자 아틀라스 16 타일이 어느 조명에 갔는지, 화면 밖 조명이 빠졌는지를 고정 시점 기준으로 볼 수 있습니다.

그리는 쪽에 남겨야 하는 것도 있습니다. 클러스터 상자는 그리는 화면의 픽셀을 나눈 것이라 고정 카메라로 만들면 자유 시점 픽셀과 맞지 않습니다. 반투명 정렬, 화면 공간 효과, 속도 버퍼도 그리는 시점이 기준입니다.

3. 설계 결정

3.1 모든 단계에 걸리는 규칙

  • 고정하지 않으면 지금과 같은 결과. 고정이 꺼진 동안 화면 픽셀과 통계가 바뀌면 안 됩니다. 1단계 검증의 첫 항목입니다.
  • 고정 직후 카메라를 움직이기 전에는 같은 화면. 고정 카메라가 그리는 카메라의 사본이라 절두체가 같기 때문입니다. 다르면 사본을 잘못 쓴 것입니다.
  • 오브젝트 컬링은 메인 뷰만. 카메라 미리보기 뷰(m_previewCamera, viewIndex 1)는 자기 카메라로 오브젝트를 컬링합니다. 캐스케이드·조명 컬링(그림자 타일 배정, 2단계 조명 게이트)은 Render 가 두 뷰를 그리기 전에 프레임당 한 번 하므로 미리보기에도 걸립니다. 지금 캐스케이드 고정도 이미 그렇습니다.
  • 바꾸는 것은 절두체와 눈 위치뿐. b0, 클러스터, 반투명 정렬, 파티클, TAA 는 그리는 카메라를 그대로 씁니다.

3.4 에디터 UI와 오버레이

  • 체크박스. Render Settings 의 그림자 패널 뒤, 조건 없이 Freeze culling camera. 켜져 있을 때만 아래에 Cascades·Objects·Lights 세 체크박스를 들여 써서 보여 줍니다. 그 아래 한 줄 안내(TextDisabled)와 고정 시점 통계 한 줄(culled, lightsVisible/lightsCulled).
  • 절두체 와이어. DrawCascadeFrustums 를 DrawFreezeOverlay 로 넓혀서, 고정 중이고 Objects 나 Lights 항목이 켜져 있으면 고정 카메라의 전체 절두체를 흰 선으로 그립니다. 캐스케이드만 고정한 경우(--freeze-cascades)는 지금과 같은 화면이 되도록 흰 선을 그리지 않습니다. 꼭짓점은 고정 카메라 View·Proj 의 역행렬로 NDC 여덟 점(x, y = ±1, z = 0·1)을 되돌려 얻습니다. 캐스케이드 항목이 켜져 있으면 지금처럼 캐스케이드 색 와이어를 덧그립니다.
  • 조명 아이콘. 조명 항목이 켜져 있으면 DrawLightIcons 에서 고정 시점에서 컬링된 지역광 아이콘을 회색으로 칠합니다. Renderer 에는 씬 조명 번호로 묻는 IsLightCulledByFreeze(sceneIndex) 를 둡니다. GPU 배열은 방향광을 앞으로 모아 정렬하므로 번호가 달라서, 이미 있는 대응표 m_lightSceneIndex(정렬 뒤 m_gpuLights[i] 의 씬 번호)로 거꾸로 찾습니다.
  • 컬링된 오브젝트 윤곽 선택: 고정 시점에서 버린 오브젝트의 경계 구를 씬 뷰에 회색 원으로 그림. 뚫린 자리가 무엇이었는지 알려 줍니다. 3단계 끝에서 화면을 보고 넣을지 정합니다.

1단계 — 컬링 카메라 분리 RHI 확장 없음

1단계 작업 순서

  • Graphics/Renderer.h: m_cascadeFrozen·m_cascadeFreezeCamera 를 m_cullFrozen·m_cullFreezeCamera·m_cullFreezeParts 로 바꾸고 3.3 의 함수 선언. DrawItems 시그니처에 cullCamera.
  • Graphics/RendererShadow.cpp: SetCascadeFreeze → SetCullFreeze·SetCullFreezeParts. BuildShadowViews 는 CullCamera(drawCamera, parts.cascades).
  • Graphics/Renderer.cpp Render: CullLights(CullCamera(camera, parts.lights)).
  • Graphics/Renderer.cpp DrawItems: 절두체는 cullCamera, 반투명 정렬 eye 는 camera. RenderScenePass 와 Graphics/RendererDeferred.cpp RenderDeferredScene 의 호출 세 곳에서 3.3 처럼 넘김.
  • Editor/Editor.cpp·Editor/EditorAutomation.cpp: 옛 호출 두 곳을 SetCullFreeze(…, {.cascades = true, .objects = false, .lights = false}) 로 바꿔 동작을 유지(UI 는 3단계).
  • 임시로 --freeze-culling=N 파싱만 먼저 넣어 검증에 씀(모든 항목 켬). 3단계에서 정리.
  • Editor/EditorAutomation.cpp 렌더 통계 로그 줄에 culled=%u 추가.

1단계 검증

  • 고정 없음 = 기준. CascadeBigScene·ManyLights64·Ocean 에서 바뀌기 전 바이너리와 스크린샷·통계가 같음(씬 뷰 영역, 4장 잡음 기준).
  • 고정만, 이동 없음 = 같은 화면. --freeze-culling=10 만 주고 --cam-look 없이: 고정 없는 실행과 같은 픽셀·같은 culled.
  • 고정 후 이동. --freeze-culling=10 "--cam-look=…" 으로 고정 시점 뒤·위로 뺌: 로그의 culled·lightsCulled 가 이동 전 값과 같고, 스크린샷에 고정 절두체 밖 메시가 빠져 있음. 같은 이동을 고정 없이 찍은 것과 비교해 차이가 그 메시들뿐인지 눈으로 확인.
  • 디퍼드·포워드 두 경로 모두(로그 path= 로 확인), D3D11·D3D12 같은 결과.
  • 미리보기의 메시는 그대로. --select= 로 카메라 오브젝트를 골라 미리보기를 켠 채 Objects 항목만 고정·이동(임시 인자에 항목 지정이 없으면 이 검사만 코드에서 항목을 바꿔 한 번): 미리보기 화면이 고정 없는 실행과 같음. 캐스케이드·조명까지 고정하면 미리보기 그림자가 바뀌는 것이 정상.
  • --freeze-cascades 회귀. csm-study.html 의 명령이 바뀌기 전과 같은 스크린샷.

1단계 위험

  • 디퍼드의 두 DrawItems 호출 중 하나만 바꾸면 G-buffer 와 포워드 나머지가 다른 절두체를 씀. 고정 후 이동 화면에서 반투명·unlit 만 남거나 빠지면 이것.
  • Camera 사본은 고정 시점의 화면비를 그대로 가짐. 고정 뒤 창 크기를 바꿔도 컬링 절두체는 옛 화면비 — 의도한 동작으로 둠.

2단계 — 컬링된 조명 끄기 RHI 확장 없음

1단계만으로는 고정 시점 밖 조명도 자유 시점 화면을 계속 비춥니다(0장 정정 참고). 고정 중에만 컬링 결과를 클러스터에 반영합니다.

2단계 작업 순서

  • Graphics/RendererClusters.cpp CullLights: 고정 중이고 조명 항목이 켜져 있으면, 컬링된 지역광(visible == false)의 m_lightBounds[i].w = 0. 고정이 아니면 손대지 않음(그리는 카메라 기준이라 어차피 클러스터에 안 걸림).
  • 같은 자리에 주석: w = 0 은 CPU BuildClusters 와 GPU 비닝이 이미 건너뜀. 경계 배열이 두 뷰 공용이라 미리보기에도 걸림. 클러스터드를 끈 ShadeAllLights 경로에는 효과 없음.

2단계 검증

  • ManyLights64 에서 고정 후 이동: 고정 절두체 밖 조명이 비추던 바닥이 어두워짐. 로그 clusterLightRefs 가 1단계 같은 이동보다 줄어듦.
  • CPU 비닝(--cluster-gpu=0)과 GPU 비닝이 같은 화면.
  • 고정 없음·고정만(이동 없음)은 1단계와 같은 픽셀 — 그리는 카메라 절두체 밖 조명은 원래 빛이 닿는 픽셀이 없으니 이동 없이는 화면 차이가 없어야 함. clusterRefs 는 상자 검사가 보수적이라 절두체 가장자리 조명 몫만큼 조금 줄 수 있음.

3단계 — UI · 오버레이 · 자동화

3단계 작업 순서

  • Editor/Editor.cpp: 3.4 의 체크박스 묶음. 체크박스가 늘 보이게 조건 제거. 항목을 바꾸면 SetCullFreezeParts. Lights 툴팁에 "미리보기 뷰 조명에도 걸림, Clustered 를 끄면 빛은 그대로".
  • Editor/Editor.cpp DrawCascadeFrustums → DrawFreezeOverlay: 흰 전체 절두체 + (캐스케이드 항목) 색 와이어. Editor.h 선언 갱신.
  • Graphics/Renderer.h·RendererClusters.cpp: IsLightCulledByFreeze(sceneIndex). Editor/Editor.cpp DrawLightIcons 에서 회색 아이콘.
  • 고정 해제: 씬 불러오기·재생 시작·정지에서 SetCullFreeze(false, …). Editor/EditorApp.cpp 에서 ResetTemporalHistory 를 부르는 자리(EditorApp::ResetHistory, 재생 시작)와 같은 곳. 재생 정지가 ResetHistory 를 거치는지는 그때 확인.
  • Editor/EditorAutomation.h/.cpp: --freeze-culling=N 정식 파싱과 머리 주석, --cam-look 순서 보장(freezeCascadesAt 와 같이 N+1 프레임째).
  • 선택 컬링된 오브젝트 경계 구 윤곽. 하지 않음 — 흰 절두체와 남은 그림자(9장)로 빠진 자리를 충분히 알아볼 수 있었음.

3단계 검증

  • 고정 후 이동 스크린샷에 흰 절두체 와이어와 회색 조명 아이콘. 와이어 안쪽 메시는 남고 바깥 메시는 빠짐.
  • 캐스케이드를 1 개로 둔 씬에서도 체크박스가 보이고 흰 와이어가 그려짐.
  • csm-study.html 의 --freeze-cascades 명령이 1단계 이전과 같은 스크린샷(흰 선 없음).
  • 고정한 채 다른 씬을 불러오면 고정이 풀림. 재생을 시작해도 풀림.
  • 항목 하나씩 끄기: Objects 만 끄면 메시가 다시 나타나고 조명은 꺼진 채. Cascades 만 끄면 캐스케이드가 그리는 카메라를 따라감.

FreezeCulling.json 은 그 전 판에서 만들어 120 개 그대로입니다.)), ManyLights64 -6,7,0;12,0,0(위층 회랑에서 고정 카메라 쪽을 봄).
