2. 개념: 유니티 uGUI 구조

uGUI 의 요소는 넷입니다. 화면 하나를 대표하는 Canvas, 부모 사각형 안에서 자기 사각형을 정하는 RectTransform, 사각형에 무언가를 그리는 Graphic(Image·Text), 입력을 받아 상태를 바꾸는 Selectable(Button·Slider·Toggle)입니다. 레이아웃 그룹은 자식들의 RectTransform 값을 대신 써 주는 컴포넌트일 뿐이고, ScrollRect 는 content 자식의 위치를 움직이는 컴포넌트입니다. 이 엔진도 같은 나눔을 따릅니다.

2.1 RectTransform 계산

좌표는 캔버스 단위(CanvasScaler 를 거친 논리 픽셀), 원점은 부모 사각형의 왼쪽 아래, y 는 위쪽이 +입니다(유니티와 같음). 화면 픽셀(y 아래가 +)로는 정점을 만들 때 한 번 뒤집습니다.

// 입력: 부모 사각형 P(min, size), anchorMin·anchorMax·pivot (0~1), anchoredPosition, sizeDelta
aMin   = P.min + anchorMin * P.size          // 앵커 사각형의 두 모서리
aMax   = P.min + anchorMax * P.size
size   = (aMax - aMin) + sizeDelta           // 앵커가 한 점이면 sizeDelta 가 곧 크기
pivotP = aMin + (aMax - aMin) * pivot + anchoredPosition
rect.min = pivotP - size * pivot
rect.max = rect.min + size
// 회전(z)·스케일(xy)은 pivotP 를 중심으로 행렬로 붙여 자식에게 넘김
local = T(-pivotP) · S(scale.xy) · Rz(rotation.z) · T(pivotP)

앵커가 한 점(min = max)이면 "그 점에서 얼마나 떨어진 곳에 몇 크기로", 벌어져 있으면 "부모 가장자리에서 얼마씩 안쪽으로"가 됩니다. 늘어나는 패널과 모서리에 붙는 버튼이 같은 식으로 나옵니다.

2.2 CanvasScaler

Scale With Screen Size 모드에서 기준 해상도(기본 1920×1080)에 대한 배율을 가로·세로 사이에서 섞습니다. 로그 공간에서 섞어야 가로로 긴 화면과 세로로 긴 화면이 대칭이 됩니다.

logW  = log2(screenW / refW)
logH  = log2(screenH / refH)
scale = 2 ^ lerp(logW, logH, match)          // match 0 = 가로 맞춤, 1 = 세로 맞춤
canvasSize = screenSize / scale              // 루트 RectTransform 의 크기

Constant Pixel Size 모드는 scale = scaleFactor(기본 1)입니다. 에디터에서 화면 크기는 씬 창 크기, 게임에서는 백버퍼 크기입니다.

2.3 그리는 순서와 배치

3. 설계 결정

3.1 모든 단계에 걸리는 규칙

  • UI 가 없는 씬은 지금과 같은 결과. 캔버스가 없거나 그릴 사각형이 0개면 UI 패스를 열지 않고, 톤 패스의 끝 상태도 지금 경로 그대로 둡니다. 모든 단계 검증의 첫 항목입니다.
  • Scene 은 CPU 데이터, GPU 자원은 Renderer. UI 컴포넌트와 레이아웃·그리기 목록(정점 배열, 드로우 목록)은 Scene 쪽(UI/)이 만들고, 버퍼·텍스처·파이프라인은 Graphics/RendererUI.cpp 가 가집니다. 글리프 비트맵도 CPU 쪽이 굽고 Renderer 가 올립니다.
  • 편집 모드에서도 레이아웃. Scene::Update 는 재생 중에만 돌기 때문에, 레이아웃과 그리기 목록 만들기는 UI 시스템이 매 프레임 직접 부릅니다. 재생 중에만 도는 것은 이벤트 처리와 스크립트 콜백뿐입니다.
  • D3D11·D3D12 같은 픽셀. 다른 렌더링 기능과 같은 기준입니다.
  • ABI. PropertyVisitor·Behaviour·Input 에 가상 함수를 더할 때는 끝에 붙입니다. 새 방문자 함수는 기본 구현을 둡니다(예: Float2 → Float 둘). UI 컴포넌트 클래스는 SHERLOCK_API 로 내보내 스크립트에서 GetBehaviour<UIText>() 를 쓸 수 있게 합니다.
  • 스크립트가 넘긴 함수는 씬보다 오래 살지 않음. 리스너(std::function)는 컴포넌트 안에만 두고 전역 저장소에 두지 않습니다. 스크립트 핫리로드는 씬을 문자열로 저장했다 다시 읽어 컴포넌트를 새로 만들므로, 내려간 DLL 의 함수를 가리키는 리스너가 남지 않습니다. 하나 예외인 전역 표 SHERLOCK_UI_ACTION 레지스트리(3.2)는 BehaviourRegistry 와 같은 방식으로, 스크립트 DLL 을 내릴 때 그 DLL 이 등록한 항목을 지웁니다(그 정리 방식은 3단계 시작 때 Core/ScriptModule.cpp 에서 확인).

2단계 검증

  • UpdateTexture 단독 검사. 체커 텍스처의 가운데 64×64 만 빨강으로 바꾼 뒤 그려서 두 백엔드 같은 픽셀(디버그 뷰나 Image 로).
  • 글자 기준. 첫 실행 스크린샷을 기준 이미지로 저장하고 이후 단계마다 같은 픽셀. 크기별로 ascent 위치가 정수 픽셀에 오는지(가로선 글자 "ㅡ" 가 두 줄로 번지지 않음) 확대 확인.
  • 아틀라스 키우기. 1920×1080 에서 한글 2,350자를 24 px 로 한 화면에(80열 × 30줄): 글리프 넓이 합이 약 1.5M px 라 1024²(1.05M)를 넘고 2048²(4.2M)에 들어감 → 한 번 커지고 모든 글자가 제대로 나옴.
  • 아틀라스 비우기. 같은 씬에서 테스트 스크립트가 30 프레임째 글자 크기를 24 → 36 px 로 바꿈: 두 크기를 합치면 2048² 를 넘으므로 비우고 36 px 만 다시 구움. 바뀐 뒤 프레임들에서 깨진 글자가 없는지 프레임별 스크린샷 비교. 비우기는 GPU 가 앞 프레임을 끝낸 뒤라 한 프레임 동안 옛 크기가 보여도 정상.
  • 보이는 글자만으로도 넘칠 때. 비운 뒤에도 이번 프레임 글자가 다 안 들어가면 못 넣은 글자는 □ 로 그리고 경고 로그를 한 번 남김(두 번째 아틀라스 페이지는 범위 밖). 64 px 로 2,350자를 그리는 씬에서 □ 와 경고 한 줄 확인.
  • 패키징. --build-game 결과를 글꼴 없는 폴더에서 실행해도 같은 글자.

2단계 위험

항목확인한 것계획에 미치는 영향
UNORM 렌더 타깃 뷰ColorAttachment::srgbView 가 뷰를 고름. 씬 색 텍스처는 R8G8B8A8_UNORM 으로 만들고 백엔드가 TYPELESS 리소스로 만듦. 두 백엔드 모두 (텍스처, sRGB 여부)마다 RTV 를 따로 만들어 캐시(D3D12Device rtv/rtvSrgb, D3D11 GetRTV). PSO 의 rtvFormats 는 D3D12 만 씀UI 파이프라인 RTV 형식 R8G8B8A8_UNORM, srgbView = false. RHI 확장 없음
srgbOutput 꺼짐톤 셰이더는 감마를 걸지 않음(TonemapPixelShader.hlsl 이 선형 값을 냄). 꺼지면 선형 값이 UNORM 뷰에 그대로 써짐 — 비교용 디버그 상태UI 는 이 설정과 상관없이 sRGB 값을 UNORM 뷰에 씀. 꺼진 상태에서는 장면만 어둡게 보이고 UI 는 그대로인 것이 정상
톤 패스 뒤 상태에디터·미리보기 색은 ShaderResource 로 끝나 ImGui 가 읽음. 게임 백버퍼는 RenderTarget 으로 끝나 BeginUIPass 가 Load. 후처리 단계 썸네일은 ApplyHdrEffects 안에서 따로 톤매핑하므로 영향 없음. Barrier() 는 텍스처가 기억한 상태에서 바꾸므로 앞 상태가 어긋날 일이 없음UI 패스가 직접 RenderTarget 으로 바꿔 그리고, 에디터·미리보기는 ShaderResource 로, 게임은 RenderTarget 으로 돌려놓음. 톤 패스는 고치지 않아도 됨 계획 변경(1단계 위험 하나가 없어짐)
깊이 (8단계)렌더 패스는 색·깊이 형식이 달라도 막지 않음. 톤 패스 뒤 깊이는 DepthRead(ApplyHdrEffects 가 항상 DepthRead 로 둠). 읽기 전용 깊이는 readOnly + Load + DepthRead. 깊이는 TAA 지터가 들어가 있고, b0 에 지터 없는 unjitteredViewProj 가 있음. 미리보기 패스가 b0 를 덮어씀World 캔버스 행렬은 Renderer 가 CPU 에서 지터 없는 ViewProj 로 곱해 UI 상수 버퍼에 넣음(b0 에 기대지 않음). 깊이 PSO 는 dsvFormat D24S8
Dynamic 버퍼버퍼마다 프레임 슬롯 링(8 MB)에서 조각을 받음 → 여러 버퍼를 각각 한 번씩 갱신 가능. 이미 기록한 드로우는 옛 조각을 씀. 그 프레임에 갱신 안 된 버퍼를 묶으면 오류 로그. OnUpdate 에서 갱신하면 아직 앞 프레임 슬롯이라 GPU 와 겹칠 수 있음Build 는 CPU 만, 업로드는 Renderer::Render 안(UploadDebugLines 와 같은 자리). 사각형 0개면 패스를 건너뜀. 키울 때는 Destroy + Create, VB·IB 는 셋에 넣지 않고 직접 묶음
