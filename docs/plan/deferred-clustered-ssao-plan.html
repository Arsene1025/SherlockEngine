2. 개념: 디퍼드 셰이딩

2.1 포워드와 디퍼드는 "조명 계산을 언제 하느냐"가 다름

포워드(지금 엔진)는 물체를 그리는 픽셀 셰이더 안에서 바로 조명을 계산합니다. 물체 A 를 그린 뒤 그 앞에 물체 B 가 그려지면, A 의 픽셀에서 계산한 조명은 덮어써져 버려집니다(오버드로). 그래서 비용은 대략 "래스터화된 조각 수 × 조명 수"입니다.

디퍼드는 두 번에 나눕니다. 먼저 지오메트리 패스가 물체를 그리면서 조명은 하지 않고, 조명에 필요한 표면 정보(색, 노멀, 거칠기 …)만 여러 장의 텍스처에 씁니다. 이 텍스처 묶음이 G-buffer 입니다. 그다음 라이팅 패스가 화면을 덮는 삼각형 하나를 그리면서, 픽셀마다 G-buffer 를 읽어 조명을 한 번만 계산합니다. 비용은 "화면 픽셀 수 × 조명 수"가 되고 오버드로와 무관해집니다.

2.2 MRT (Multiple Render Targets)

픽셀 셰이더가 SV_Target0, SV_Target1, … 처럼 여러 출력을 내면, 렌더 패스에 묶인 색 타깃 여러 장에 한 번에 씁니다. 조건은 셋입니다.

  1. PSO 의 rtvCount·rtvFormats[i] 가 패스의 색 타깃 개수·포맷과 정확히 같아야 함 (D3D12 는 다르면 거부, D3D11 은 결과가 정의되지 않음).
  2. 모든 타깃의 크기가 같아야 함.
  3. 한 텍스처가 같은 패스에서 RTV 이면서 SRV 일 수 없음. D3D11 은 RTV 로 붙일 때 같은 텍스처의 SRV 바인딩을 런타임이 풀고, D3D12 는 리소스 상태가 둘 중 하나여야 함. 그래서 G-buffer 는 "지오메트리 패스에서 RenderTarget → 배리어 → 라이팅 패스에서 ShaderResource"로 전이합니다.

2.3 G-buffer 에 무엇을, 어떤 정밀도로

원칙은 "라이팅 패스가 포워드 셰이더와 같은 식을 계산하는 데 필요한 값만, 화면에서 구별되지 않을 정밀도로"입니다.

  • 색 계열(알베도, F0): 8 비트면 충분하지만 선형으로 저장하면 어두운 값의 계단이 큽니다. _SRGB 포맷은 쓸 때 선형 → sRGB 로 인코딩하고 읽을 때 되돌리므로, 어두운 쪽에 비트가 몰려 정밀도가 좋아집니다. 예: 유전체 F0 0.04 근처에서 선형 8 비트의 한 단계는 1/255 ≈ 0.0039(값의 약 10%)이고, sRGB 8 비트는 0.04 를 약 0.221 → 56/255 로 담아 한 단계가 약 0.0014(약 3.4%)입니다. 복원값도 선형은 10/255 = 0.0392(오차 2%), sRGB 는 약 0.0396(오차 1%)입니다. 알파 채널은 sRGB 변환을 받지 않으므로 거칠기·AO 같은 선형 값을 넣어도 됩니다.
  • 노멀: 단위 벡터 3 성분을 그대로 담으면 낭비라 2 성분으로 줄입니다(2.5). 8 비트 2 성분이면 하이라이트에 띠가 보일 수 있어 16 비트 부동소수점을 씁니다.
  • 위치: 저장하지 않고 깊이 버퍼에서 복원합니다(2.4). 깊이는 어차피 있고, R32G32B32A32 위치 타깃은 16 B/픽셀이라 비쌉니다.
  • 발광: 조명과 무관하므로 G-buffer 에 따로 두지 않고, 지오메트리 패스가 HDR 타깃 자체에 바로 씁니다. 라이팅 패스는 그 위에 가산 블렌딩으로 조명을 더합니다.

2.4 깊이에서 월드 위치 복원

라이팅 패스의 픽셀 (x, y) 와 그 픽셀의 깊이 d 를 알면, 투영의 역변환으로 월드 위치가 나옵니다.

// GBuffer.hlsli (제안). screenParams.zw = 1 / 뷰 타깃 크기
float3 ReconstructWorldPosition(float2 svPosition, float depth)
{
    const float2 uv = svPosition * screenParams.zw;
    const float4 ndc = float4(uv.x * 2.0f - 1.0f, 1.0f - uv.y * 2.0f, depth, 1.0f);
    const float4 h = mul(ndc, invViewProj);     // 행벡터 관례 mul(v, M). C++ 가 전치해서 올림
    return h.xyz / h.w;
}

정밀도. 원근 투영의 깊이는 d = a + b / z 꼴이라(a = f/(f−n), b = −nf/(f−n)), 깊이 한 단계가 덮는 거리는 Δz ≈ z²·Δd / n 입니다. D24 의 Δd = 2−24 ≈ 6×10−8 이므로 near = 0.1 이면 z = 10 m 에서 약 0.06 mm, z = 100 m 에서 약 6 mm 입니다. 포워드는 보간된 worldPosition 을 쓰므로, 먼 곳의 그림자 경계와 날카로운 하이라이트에서 포워드와 디퍼드의 차이가 가장 먼저 보일 것으로 예상합니다. 차이가 허용 범위를 넘으면 깊이를 D32_FLOAT 로 바꾸는 선택지가 있습니다(스텐실을 쓰지 않으므로 잃는 것이 없음, 위험 참고). 뷰 공간 z 만 필요할 때는 파티클이 쓰는 LinearViewDepth(d, proj._m22, proj._m32, proj._m23)(Particle.hlsli)를 재사용합니다.

2.5 옥타헤드럴(팔면체) 노멀 인코딩

단위 벡터를 2 성분으로 담는 방법입니다. 단위 구를 팔면체 |x|+|y|+|z| = 1 로 투영하고, 아래 반구(z < 0)의 네 삼각형을 정사각형 바깥 모서리로 접어 펴면 구 전체가 [−1, 1]² 정사각형 하나에 들어갑니다. 구면 좌표(각도 둘)보다 분포가 고르고 삼각함수가 없습니다.

// Cigolle et al. 2014 의 정의. GBuffer.hlsli (제안)
float2 OctWrap(float2 v)
{
    return (1.0f - abs(v.yx)) * float2(v.x >= 0.0f ? 1.0f : -1.0f, v.y >= 0.0f ? 1.0f : -1.0f);
}
float2 EncodeOct(float3 n)                    // n 은 단위 벡터. 결과는 [−1, 1]²
{
    n /= (abs(n.x) + abs(n.y) + abs(n.z));
    return n.z >= 0.0f ? n.xy : OctWrap(n.xy);
}
float3 DecodeOct(float2 f)
{
    float3 n = float3(f.x, f.y, 1.0f - abs(f.x) - abs(f.y));
    const float t = saturate(-n.z);
    n.x += n.x >= 0.0f ? -t : t;
    n.y += n.y >= 0.0f ? -t : t;
    return normalize(n);
}

FP16 의 가수는 10 비트라 [0.5, 1] 구간의 간격이 약 0.0005 입니다. 디코드한 노멀의 각도 오차는 0.05° 안팎으로, 거칠기 0.03 의 가장 날카로운 하이라이트에서도 눈에 띄지 않을 것으로 봅니다(검증에서 확인).

3.2 타일드와 클러스터드

타일드는 화면을 2D 타일(예: 16×16 픽셀)로 나누고, 타일 안 깊이의 최소·최대로 만든 작은 절두체와 겹치는 조명을 모읍니다. 한 타일에 가까운 물체와 먼 배경이 섞이면 깊이 범위가 카메라 앞부터 끝까지 늘어나, 사이의 빈 공간에 있는 조명까지 목록에 들어갑니다. 또 깊이 버퍼가 있어야 범위를 알 수 있어 반투명(깊이를 쓰지 않음)에는 맞지 않습니다.

클러스터드는 타일을 깊이 방향으로도 잘라 3D 칸(클러스터)을 만듭니다. 칸의 깊이 범위가 고정이라 깊이 버퍼 없이 미리 만들 수 있고, 반투명 포워드 픽셀도 자기 위치로 칸을 찾아 같은 목록을 읽습니다. 로드맵은 타일드를 생략하고 클러스터드만 하기로 했습니다.

3.3 클러스터 격자와 깊이 슬라이스

격자는 화면 가로 16 × 세로 9 × 깊이 24 = 3,456 칸입니다(로드맵 제안). 가로·세로는 픽셀 크기가 아니라 개수로 고정해서, 씬 뷰(약 730×443)와 카메라 미리보기(더 작음)가 같은 격자 수를 씁니다. 타일 하나의 픽셀 크기는 뷰 크기 / 개수입니다.

깊이는 지수 분할합니다. 원근에서는 먼 곳일수록 화면에 작게 보이므로, 칸의 화면상 크기와 깊이 두께의 비율을 비슷하게 맞추려면 두께가 거리에 비례해 커져야 합니다. near = n, far = f, 슬라이스 수 S 일 때 k 번째 경계와 뷰 공간 z 의 슬라이스 번호는:

z_k   = n · (f / n)^(k / S)                       // k = 0 … S
slice = floor( log2(z) · scale + bias )           // 셰이더와 CPU 가 같은 식
scale =  S / log2(f / n)
bias  = −S · log2(n) / log2(f / n)

표처럼 n 이 작으면 슬라이스 8 개가 카메라 앞 1 m 안에 몰립니다. 그 구간에는 물체가 거의 없으므로 낭비입니다. 흔한 보정은 첫 슬라이스를 고정 거리(예: 1 m)까지 하나로 두고 그 뒤부터 지수 분할하는 것입니다. 처음에는 식 그대로 하고, 히트맵 디버그 뷰로 분포를 본 뒤 결정합니다 제안.

직교 카메라(Camera::IsUsePerspectiveProjection 이 거짓, 예: ParticleOrtho.json)는 화면 크기가 거리와 무관하므로 선형 분할 slice = floor((z − n) / (f − n) · S) 을 씁니다. 상수 하나(clusterDepth.z, 원근 1 / 직교 0)로 두 식을 고릅니다.

칸 (i, j, k) 의 AABB: 타일의 NDC 범위 x ∈ [−1 + 2i/16, −1 + 2(i+1)/16], y ∈ [1 − 2(j+1)/9, 1 − 2j/9] (타일 행 0 이 화면 위) 의 네 모서리를 깊이 z_k 와 z_(k+1) 두 평면 위로 옮긴 8 점의 최소·최대입니다. 원근이면 NDC (x, y) 와 깊이 z 의 뷰 공간 점은 (x·z / P₁₁, y·z / P₂₂, z) 입니다(P = 투영 행렬, 비대칭 투영이면 P₃₁·P₃₂ 항이 더해짐 — 일반식은 역투영 행렬로 계산). 직교면 (x / P₁₁, y / P₂₂, z). 이 AABB 들은 카메라 위치·방향과 무관하고 투영(시야각·종횡비·near·far)과 격자에만 달리므로, 뷰마다 한 번 만들어 두고 투영이 바뀔 때만 다시 계산합니다.

3.4 조명과 클러스터의 겹침 판정

판정은 보수적이어야 합니다. 겹치지 않는 조명을 목록에 넣으면 조금 느려질 뿐이지만, 겹치는 조명을 빼면 화면에 조명이 격자 모양으로 끊깁니다.

  • 포인트: 영향 범위는 구(중심 = 광원, 반지름 = range). 셰이더의 감쇠 CalculateDistanceAttenuation 은 saturate(1 − d / range)² 를 곱하므로 range 에서 정확히 0 이고, 이 구 밖에는 기여가 없습니다(코드 확인). range ≤ 0 이면 max(range, EPSILON) 때문에 모든 곳에서 0 이라 비닝에서 빼도 됩니다. 스팟의 원뿔 항 saturate((cos − outerConeCos) / (inner − outer)) 도 바깥 원뿔 밖에서 정확히 0 입니다. 구–AABB 판정은 "AABB 위에서 구 중심에 가장 가까운 점까지의 거리² ≤ r²" 입니다.
  • 스팟: 원뿔을 감싸는 구로 판정합니다(원뿔–AABB 정밀 판정은 나중의 개선). 원뿔 반각 θ(= acos(outerConeCos)), 길이 h(= range)일 때 가장 작은 경계 구는 아래 그림의 두 경우입니다.
  • 방향광: 범위가 없으므로 비닝하지 않고 모든 픽셀이 따로 순회합니다. 이를 위해 조명 배열을 "방향광 먼저, 지역광 뒤"로 정렬하고 방향광 개수를 b2 에 둡니다.

스팟 경계 구의 유도(θ ≤ 45°): 중심을 축 위 거리 t 에 두면 꼭짓점까지 거리 t 와 뚜껑 가장자리(A + h(cos θ·d + sin θ·u))까지 거리가 같아야 하므로 (h cos θ − t)² + h² sin² θ = t² → t = h / (2 cos θ). 뚜껑 꼭대기(A + h·d)까지 거리 h − t ≤ t 도 성립합니다. θ > 45° 이면 이 구가 h·d 방향으로 너무 커지므로 뚜껑 가장자리 원을 대원으로 하는 구(중심 h cos θ, 반지름 h sin θ)가 더 작고, 꼭짓점(거리 h cos θ ≤ h sin θ)도 안에 들어갑니다. 같은 경계 구를 3a 의 화면 밖 판정과 그림자 점수에도 씁니다.

3.6 섀도 타일 우선순위

지역광 타일은 16 개(스팟 1, 포인트 6)뿐이라 조명이 많으면 "누가 그림자를 받는가"를 정해야 합니다. 지금은 조명 배열 순서라 카메라 뒤 조명이 먼저 가져갈 수 있습니다. 바꾸는 규칙은 셋입니다 제안.

  1. 화면 밖 제외: 경계 구가 메인 카메라 절두체(Frustum::FromViewProj + Intersects)와 겹치지 않는 조명은 후보에서 뺍니다. 영향 구가 절두체와 겹치지 않으면 그 조명은 보이는 어떤 표면도 비추지 않으므로 그림자도 보이지 않습니다.
  2. 점수: 화면에서 차지하는 크기 × 밝기. 카메라에서 광원까지 거리 D, 경계 구 반지름 r 일 때 크기 ≈ (r / D)² (입체각에 비례), 밝기 = intensity × 휘도(color). 카메라가 구 안이면(D < r) 최고 점수.
  3. 이력(히스테리시스): 지난 프레임에 그림자를 받은 조명은 점수에 1.25 를 곱합니다. 점수가 비슷한 두 조명이 프레임마다 순위를 바꾸면 그림자가 깜빡이기 때문입니다.

배정은 점수 내림차순 탐욕법입니다. 포인트가 6 칸이 안 남아 못 받아도 계속 진행해서, 뒤의 스팟이 남은 1 칸을 받을 수 있게 합니다. 방향광 CSM 은 지금처럼 첫 castShadows 방향광이 받고 CSM 아틀라스를 따로 쓰므로 경쟁하지 않습니다.

4. 개념: SSAO (Screen-Space Ambient Occlusion)

4.1 무엇을 근사하나

환경광(하늘·IBL)은 모든 방향에서 오는 빛인데, 구석이나 물체가 맞닿은 곳은 주변 기하가 그 방향들 일부를 가려 덜 받습니다. 이 "가려진 비율"이 앰비언트 오클루전(AO)입니다. 재질의 AO 텍스처(t3)는 메시 자기 자신 안의 작은 홈만 담고, 물체끼리의 가림(책상 위 컵의 아래쪽, 벽과 바닥이 만나는 모서리)은 담지 못합니다. SSAO 는 그 가림을 깊이 버퍼만 보고 화면 공간에서 추정합니다.

라이팅 (PS_DeferredLighting)

float4 PS_DeferredLighting(float4 svPos : SV_POSITION) : SV_TARGET
{
    const int2 p = int2(svPos.xy);
    const float depth = gbDepth.Load(int3(p, 0));            // t23
    if (depth >= 1.0f) discard;                               // 그린 물체가 없음 → HDR 의 클리어 색(또는 뒤에 그릴 하늘)을 그대로 둠

    Surface s;
    s.position        = ReconstructWorldPosition(svPos.xy, depth);
    const float4 g0 = gb0.Load(int3(p, 0)), g1 = gb1.Load(int3(p, 0));
    const float4 g2 = gb2.Load(int3(p, 0)), g3 = gb3.Load(int3(p, 0));
    s.normal          = DecodeOct(g1.xy);
    s.geometricNormal = DecodeOct(g1.zw);
    s.view            = SafeNormalize(cameraPosition - s.position, float3(0, 0, -1));
    s.diffuseAlbedo   = g0.rgb;     s.ao = g0.a;
    s.F0              = g2.rgb;     s.rough = g2.a;
    s.metal = g3.r; s.F90 = g3.g;   s.clearcoat = g3.b; s.clearcoatRough = g3.a;
    s.clearcoatNormal = s.geometricNormal;                    // 코팅 노멀 맵이 있는 재질은 포워드로 감 (2단계-1)

    const int dv = (int)debugParams.x;
    if (dv != 0) return DebugViewColor(dv, s, svPos.xy);      // G-buffer 패스가 발광을 0 으로 써 둠
    return float4(ShadeEnvironment(s) + ShadeAllLights(s), 0.0f);   // 알파 0: 블렌드가 HDR 알파를 유지
}

  • PSO 변형: 재질 × 정점 포맷 × 미러 × 와이어 × {메인, G-buffer} 로 캐시 항목이 늘어남. Stats 의 PSO cache 숫자를 전후로 기록.
  • 바인딩: 라이팅 패스는 셋 2개 { 프레임, G-buffer }. 패스 표 기반 바인딩 대조가 새 레이아웃을 그대로 검사하는지 확인.

2단계-9 위험

  • 위치 복원 정밀도(2.4). 그림자 바이어스(shadowSettings.bias, 노말 오프셋)는 포워드의 보간 위치에 맞춰 조정된 값이라 먼 곳에서 여드름(acne)이 생길 수 있습니다. 먼저 디버그 뷰 4 로 비교하고, 안 되면 깊이를 D32_FLOAT 로 바꾸는 것을 실험합니다 — 그림자 맵이 이미 D32 를 SRV 로 읽으므로 RHI 경로는 있습니다. 바꾸면 파티클 PSO 와 디버그 선 PSO 의 dsvFormat 도 같이 바꿔야 합니다(Pass_Particle, GetDebugLinePipeline, GetPipelineFor 의 D24_UNORM_S8_UINT).
  • 바인딩 대조: G-buffer PS 가 GBuffer.hlsli 를 include 해 t25~t29 를 선언만 하는 경우, fxc 가 안 쓰는 리소스를 리플렉션에서 빼는 것을 전제로 합니다. 혹시 남으면 인코딩 함수를 별도 헤더(GBufferEncode.hlsli)로 뺍니다.
  • sRGB G-buffer 의 RTV/SRV: TYPELESS 로 만들지 않는 포맷이라 RTV·SRV 가 모두 _SRGB 로 만들어질 것으로 봅니다. ColorAttachment::srgbView 가 TYPELESS 가 아닌 텍스처에서 무엇을 하는지 구현 때 확인합니다 (8.2).
  • 디버그 뷰의 톤 패스: 디버그 뷰면 톤 패스가 saturate 만 하므로 G-buffer 패스가 발광을 0 으로 써야 디버그 색이 섞이지 않습니다(위 PS_GBuffer).
  • 에디터·게임 두 경로: 씬 뷰(에디터), 카메라 미리보기, 게임 모드(백버퍼 출력, EnsureGameTarget) 세 곳 모두에서 확인합니다. 에디터에서만 보고 끝내지 않습니다.

float ShadowScore(const LightBounds& b, const GpuLight& l, XMVECTOR cameraPos, bool hadShadowLastFrame)
{
    const float D = max(XMVectorGetX(XMVector3Length(XMLoadFloat3(&b.center) - cameraPos)), 1e-3f);
    const float coverage = D <= b.radius ? 1.0f : min((b.radius / D) * (b.radius / D), 1.0f);
    const float luminance = 0.2126f * l.color.x + 0.7152f * l.color.y + 0.0722f * l.color.z;
    float score = coverage * l.intensity * luminance;
    return hadShadowLastFrame ? score * 1.25f : score;
}

칸 범위를 줄이는 방법

3,456 칸 × 조명 수를 모두 구–AABB 로 검사하면 조명 256 개에서 88 만 번입니다. 대신 조명마다 겹칠 수 있는 칸의 범위를 먼저 좁힙니다.

  1. 깊이: 뷰 공간 구 중심 z 에서 [z − r, z + r] 를 near·far 로 자르고, 그 양 끝의 슬라이스 번호를 같은 식(log2)으로 구함. 구 전체가 near 앞이거나 far 뒤면 이 뷰에서 제외(= 뷰별 절두체 컬링).
  2. 화면: 구의 화면 투영을 감싸는 사각형. 정확한 식(구의 투영 경계, Mara & McGuire 2013)이 있지만 처음에는 단순하게 구를 감싸는 뷰 공간 AABB 의 8 꼭짓점을 투영해 min/max 를 냄(카메라가 구 안에 있거나 꼭짓점이 near 뒤면 화면 전체로 둠) 제안.

{
    const uint2 tile = min(uint2(svPosition * clusterParams.xy * screenParams.zw), uint2(clusterParams.xy) - 1);

// Ssao.hlsli (새). ShaderConstants.h 의 SsaoConstants 와 바이트 단위로 같아야 함
cbuffer SsaoParams : register(b12)
{
    float  ssaoRadius;        // 월드 거리 (m). 기본 0.5
    float  ssaoBias;          // 뷰 z 비교 여유. 기본 0.025
    float  ssaoIntensity;     // 결과 1 − occ·intensity. 기본 1
    float  ssaoPower;         // pow(ao, power). 기본 1.5
    uint   ssaoSampleCount;   // 8 / 16 / 32. 기본 16
    float3 ssaoPadding;
    float4 ssaoKernel[32];    // 탄젠트 공간 반구 (z ≥ 0). w 미사용
};   // 32 + 512 = 544 B
// C++: 고정 시드로 만듦. 샘플 수 n 이 바뀔 때만 같은 시드로 다시 만듦 (결정적)
void BuildSsaoKernel(uint32_t n, XMFLOAT4 (&kernel)[32])
{
std::mt19937 rng(1337u);
std::uniform_real_distribution<float> u01(0.0f, 1.0f);
for (uint32_t i = 0; i < n; ++i)
{
    XMVECTOR v = XMVector3Normalize(XMVectorSet(u01(rng) * 2 - 1, u01(rng) * 2 - 1, u01(rng), 0));
    float scale = float(i) / float(n);              // i / 32 로 두면 n = 16 일 때 최대 길이가 0.3 → 실효 반경이 1/3
    scale = 0.1f + 0.9f * scale * scale;               // lerp(0.1, 1, t²): 가까운 쪽에 몰림
    v = XMVectorScale(v, u01(rng) * scale);
    XMStoreFloat4(&kernel[i], v);
}
}

(2026-11-26 기준: 지금 코드의 길이는 0.2 + 0.8 × (i + u) / n 입니다. 균등 난수 × lerp(0.1, 1, (i/n)²) 는 두 번 몰려 실효 반경이 너무 작았습니다 — UploadSsaoConstants.) 길이 배율을 i / n 으로 두어야 샘플 수와 상관없이 마지막 샘플이 반경 끝까지 닿습니다. 설정 UI 는 8/16/32 중에서 고르고, 바뀌면 BuildSsaoKernel 을 다시 불러 b12 에 올립니다 제안.

PS_Ssao

float PS_Ssao(float4 svPos : SV_POSITION) : SV_TARGET
{
    const int2 p = int2(svPos.xy);
    const float depth = gbDepth.Load(int3(p, 0));
    if (depth >= 1.0f) return 1.0f;

    const float3 P = ReconstructWorldPosition(svPos.xy, depth);
    const float3 N = DecodeOct(gbNormal.Load(int3(p, 0)).xy);   // 셰이딩 노멀 (노멀 맵의 잔결까지 반영)
    const float  pz = mul(float4(P, 1.0f), view).z;

    // 4×4 회전: 픽셀 좌표의 Bayer 순서 → 16 각도. 블러가 4×4 라 패턴이 정확히 지워짐
    static const float kBayer[16] = { 0, 8, 2, 10, 12, 4, 14, 6, 3, 11, 1, 9, 15, 7, 13, 5 };
    const float angle = kBayer[(p.x & 3) + (p.y & 3) * 4] * (PI * 2.0f / 16.0f);
    float3 r = float3(cos(angle), sin(angle), 0.0f);

    // Gram–Schmidt: r 을 N 에 수직으로. N 이 r 과 거의 평행하면 다른 축
    float3 T = r - N * dot(r, N);
    T = dot(T, T) < 1e-4f ? normalize(cross(N, float3(0, 1, 0)) + 1e-3f) : normalize(T);
    const float3 B = cross(N, T);

    float occlusion = 0.0f;
    [loop] for (uint i = 0; i < ssaoSampleCount; ++i)
    {
        const float3 k = ssaoKernel[i].xyz;
        const float3 S = P + (T * k.x + B * k.y + N * k.z) * ssaoRadius;
        const float4 clip = mul(float4(S, 1.0f), viewProj);
        const float2 uv = float2(clip.x / clip.w * 0.5f + 0.5f, 0.5f - clip.y / clip.w * 0.5f);
        if (any(uv < 0.0f) || any(uv > 1.0f)) continue;           // 화면 밖: 가림 없음으로 셈
        const float sceneDepth = gbDepth.Load(int3(uv * screenParams.xy, 0));
        const float sceneZ = LinearViewDepth(sceneDepth, proj._m22, proj._m32, proj._m23);
        const float sampleZ = mul(float4(S, 1.0f), view).z;
        const float range = smoothstep(0.0f, 1.0f, ssaoRadius / max(abs(pz - sceneZ), 1e-4f));
        occlusion += (sceneZ <= sampleZ - ssaoBias ? 1.0f : 0.0f) * range;
    }
    const float ao = 1.0f - occlusion / ssaoSampleCount * ssaoIntensity;
    return pow(saturate(ao), ssaoPower);
}

이 엔진의 투영은 왼손 좌표입니다(Camera.cpp 가 XMMatrixPerspectiveFovLH·XMMatrixOrthographicLH 를 씀). +z 가 카메라 앞이라 "더 가까움 = z 가 더 작음"이고, LinearViewDepth 도 양수 z 를 돌려줍니다.

PS_SsaoBlur

float PS_SsaoBlur(float4 svPos : SV_POSITION) : SV_TARGET
{
    const int2 p = int2(svPos.xy);
    const float cz = LinearViewDepth(gbDepth.Load(int3(p, 0)), proj._m22, proj._m32, proj._m23);
    float sum = 0.0f, weight = 0.0f;
    [unroll] for (int y = -2; y < 2; ++y)                 // 4×4 (−2 … +1): Bayer 4×4 주기와 정확히 맞음
    [unroll] for (int x = -2; x < 2; ++x)
    {
        const int2 q = clamp(p + int2(x, y), int2(0, 0), int2(screenParams.xy) - 1);
        const float z = LinearViewDepth(gbDepth.Load(int3(q, 0)), proj._m22, proj._m32, proj._m23);
        const float w = 1.0f / (1e-3f + abs(z - cz) / max(cz, 1e-3f) * 50.0f);   // 상대 깊이 차가 크면 가중치 작게
        sum += ssaoInput.Load(int3(q, 0)) * w;
        weight += w;
    }
    return sum / weight;
}
