스키닝 · 본 디버그 구현 기록

2026-11-12 · glTF 스켈레톤 애니메이션(스키닝)과 본 디버그 표시, 그리고 MasterChief v5.5 walk 임포트와 텍스처 BC7 변환을 구현한 내용의 기록입니다. 개념 설명은 gltf-study.html 에 있습니다.

기준: 작업 트리(아직 커밋하지 않음). 경로는 SherlockEngine/ 기준입니다. D3D11·D3D12, Debug·Release 에서 확인했습니다.

1. 데이터와 임포터

  • 임포터 단일화 — cgltf 와 비교 도구를 지우고 ModelLoader::LoadGltf(Graphics/Import/GltfImporter.cpp) 하나만 둡니다. vcpkg.json 의 cgltf 도 뺐습니다.
  • 모델 데이터 — Model.h 에 ModelSkin(조인트 노드 번호, 역바인드 행렬), ModelNode::skin, ModelInstance::node/skin. 역바인드 행렬은 좌표계 변환(mirror·M·mirror)을 거쳐 저장합니다.
  • 정점 — VertexSkin(조인트 4개 R8G8B8A8_UINT + 가중치), VERTEX_SKINNED(84바이트). RHI 에 Format::R8G8B8A8_UINT, VertexSemantic::BlendIndices/BlendWeights 를 추가했고 D3D11·D3D12 변환 표도 고쳤습니다.

2. Animator 와 팔레트

스킨 메시를 그리는 오브젝트의 Animator 가 매 프레임 조인트 월드를 계산해 팔레트를 만듭니다.

palette[j] = inverseBind[j] · jointWorld[j] · inverse(meshNodeRestWorld)

마지막 항은 오브젝트의 월드 행렬이 메시 노드 변환(preTransform)을 다시 곱하기 때문에 상쇄하는 항입니다. 결과는 inverseBind · jointWorld 와 같아서 glTF 규격대로 메시 노드 변환을 무시한 것과 같습니다. 팔레트는 GameObject::SetSkinPalette 로 올립니다.

GameObject 멤버를 덧붙여 sizeof 가 352→384 로 바뀌었으므로 스크립트 DLL 을 모두 다시 빌드해야 합니다.

3. 셰이더와 렌더러

항목내용
셰이더BasicSkinVertexShader.hlsl(VS_MainSkin), ShadowSkinVertexShader.hlsl(VS_ShadowSkin). Common.hlsli 에 cbuffer Skin(b7, matrix joints[256] 16KB).
패스Pass_MainSkin / Pass_ShadowSkin. 정점 포맷이 스킨이면 자동 선택. PS·레이아웃은 기존과 같습니다.
상수 버퍼오브젝트 셋에 b7 을 추가. 팔레트가 비면 단위행렬 256개를 올립니다.
컬링스킨 메시는 반지름 1e9 로 컬링하지 않습니다.

겪은 문제

  • D3D12 "상수버퍼가 아직 UpdateBuffer 되지 않음" — Dynamic CB 는 프레임마다 한 번은 써야 주소가 생깁니다. 프레임당 단위행렬 1개를 올려 해결했습니다.
  • 편집 모드에서 모델이 떨림 — 팔레트가 비었을 때 0번 조인트만 올려 나머지가 미정의였습니다. 256개 전부 단위행렬로 올리도록 고쳤습니다(Release 에서 영상으로 확인된 문제).

4. 본 디버그 표시

  • 조작 — B 키로 끔 → 본+관절 → 본+관절+로컬 축 순환(에디터·게임). 에디터 Render Settings 의 "Bone debug (B)" 콤보, 실행 인자 --debug-bones=N. F1~F12 는 이미 쓰고 있어서 B 로 정했습니다.
  • 자료 — Animator 가 GameObject::SkeletonPose(jointToObject, 부모 조인트 번호)를 채웁니다.
  • 그리기 — 렌더러에 선 목록 파이프라인(Pass_DebugLine, LineList, 깊이 테스트 없음)과 동적 정점 버퍼(65536 정점)를 추가. BuildDebugLines 가 월드 공간 선을 만들고 DrawDebugLines 가 씬 패스 끝(하늘 뒤)에 그립니다. 본은 초록, 관절 십자는 노랑, 축은 RGB 입니다. 십자·축 길이는 부모까지의 거리에 비례합니다.
  • 한계 — 재생 중에만 그립니다. 마스터치프는 메시 4개에 Animator 가 각각 있어 같은 선이 4번 그려집니다. 선 굵기는 1픽셀입니다.

5. MasterChief v5.5 walk 와 텍스처 변환

항목값
모델노드 70, 조인트 65, 클립 1(1.07초, 채널 195), 메시 4(Arms·Chest·Helmet·Legs)
텍스처12장, 4096×4096. PNG 합계 약 185MB → BC7 DDS(밉 13단계) 합계 약 256MB
포맷baseColor = BC7_UNORM_SRGB, normal·metallicRoughness = BC7_UNORM. BC5 는 법선 Z 가 복원되지 않아 쓰지 않았습니다.
변환 도구DirectXTex 로 만든 임시 변환기(WIC 로 읽기 → 밉 → BC7_QUICK 압축). 저장소에는 넣지 않았습니다.
씬MasterChiefWalk.json(시작 씬). 이전 MasterChief_v4 모델과 Main.json 은 지웠습니다.
BC7 DDS 는 이 기록을 쓸 때까지 CPU 에서 R8G8B8A8 로 풀어 올렸지만, 이후 로더가 BC1/BC3/BC7 을 압축 그대로 GPU 에 올리도록 바꿨습니다(texture-pipeline-record.html). 지금은 BC7 이 VRAM 도 4분의 1 로 줄입니다. 4096² BC7 은 최상위 단계만 16.8MB 이고 밉 체인 전체가 22.4MB 입니다. 128 아래의 작은 단계는 합쳐도 수 KB 라서 밉 개수를 줄여도 용량은 거의 줄지 않고, 용량은 최상위 해상도가 정합니다(2048 이면 장당 약 5.6MB). 변환기는 밉 수준 인자(0=전체, 1=없음, N=상위 N단계)를 받으며 마스터치프는 4096·밉 6단계(128까지)로 변환했습니다. 여러 테스트를 위해 해상도는 그대로 둡니다.
