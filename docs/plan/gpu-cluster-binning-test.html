GPU 클러스터 비닝 측정 — CPU · GPU 1단계 · GPU 2단계

2026-11-21 · 클러스터 비닝을 세 경로로 돌려 조명이 적은 씬, 중간 씬, 많은 씬에서 비용을 잰 기록입니다. 구현과 화면 검증은 GPU 클러스터 비닝 구현 기록에 있습니다. 세 경로의 화면은 모두 같습니다 (전체 순회 기준 0 px, 구현 기록 9장).

  • CPU — --cluster-gpu=0. Renderer::BuildClusters 가 비닝하고 Dynamic 버퍼로 올림 (2026-11-18 부터의 경로)
  • GPU 1단계 — --cluster-tiles=0. 상자 3,456 개가 조명 전체를 직접 검사
  • GPU 2단계 — 기본. 화면 타일 144 개의 비트마스크로 먼저 거르고, 상자는 자기 타일 후보만 검사

기준: 커밋 1c763bf + 작업 트리 (아직 커밋하지 않음). 모든 숫자는 이 문서를 쓰면서 같은 바이너리로 직접 잰 값입니다.

1. 요약

  • CPU 비닝 시간은 거의 0이 됩니다. CPU 비닝은 조명 4개 씬 0.13~0.17 ms, 256개 1.2 ms, 촛불 1만 개 씬은 시점에 따라 2.9~17.5 ms였습니다. GPU 경로에서 CPU에 남는 일은 입력(경계 구, 상수) 업로드뿐이고, 0.002~0.02 ms입니다.
  • GPU에는 비닝 시간이 더해집니다. 2단계 기준으로 조명이 적은 씬 0.03 ms, 256개 0.1 ms, 촛불 씬 1.0~1.9 ms입니다.
  • 2단계는 조명이 많을수록 이득이 큽니다. 조명이 4개면 둘 다 0.03~0.05 ms이고, 차이는 실행마다 흔들리는 범위 안입니다 (DeferredMaterials 는 2단계가 0.005 ms 느리고, LightOrder 는 0.014 ms 빠름). 256개에서는 0.10 대 0.13 ms, 촛불 씬에서는 1.0~1.9 대 3.6~4.9 ms로 2~4배 빠릅니다.
  • 2단계는 목록이 짧아 라이팅도 조금 빨라집니다. 촛불 씬에서 2단계의 (상자, 조명) 쌍은 CPU보다 6~13% 적습니다. 그만큼 DeferredLight 가 8~14% 줄었습니다 (예: 2층 회랑 2.03 → 1.75 ms).
  • 프레임 전체가 빨라지는지는 병목에 달렸습니다. 촛불 씬은 GPU(그림자 패스 15~17 ms)가 병목입니다. CPU 비닝은 그동안 GPU 작업과 겹쳐 돌았기 때문에, GPU로 옮겨도 프레임은 흔들림 범위 안에서 비슷하거나(3개 시점) 약 3 ms 늘었습니다(입구). GPU 1단계는 2단계보다 3~10 ms 느립니다. 조명이 적은 씬에서는 CPU 시간(Engine::Render)이 줄고 GPU Frame 은 0.02~0.1 ms 늘었습니다.

  • D3D12에서는 세 경로의 DeferredLight 가 같습니다 (256개 1.11~1.13 ms, 64개 0.32 ms). 그리고 이 값은 D3D11 CPU 경로와 비슷합니다. 그러니 "D3D11 CPU 경로가 느리다"기보다 "D3D11 GPU 경로만 유난히 빠르게 측정된다"에 가깝습니다.

9. 한계

  • GPU 한 대(RTX 3070 Ti)에서만 쟀습니다. 상자마다 스레드 하나가 긴 루프를 도는 구조라, GPU에 따라 Count·Fill 비용이 크게 다를 수 있습니다.
  • 에디터 씬 뷰(767×222)에서 쟀습니다. 비닝 비용은 화면 크기와 거의 무관합니다. 하지만 라이팅·그림자 비용은 전체 화면에서 훨씬 커지므로, 프레임 전체에서 비닝이 차지하는 비중은 더 작아집니다.
  • 촛불 씬의 프레임 시간은 실행마다 수 ms씩 흔들립니다. 3회 중앙값이라도 1~2 ms 차이는 의미 있게 보기 어렵습니다.
  • 미리보기 카메라를 켠 경우(PreviewClusterBin, 비닝 두 번)와 게임 exe 는 재지 않았습니다.
  • Debug 빌드는 재지 않았습니다. CPU 비닝은 Debug 에서 몇 배 느려지므로(2026-11-18 기록: 256개 약 5 ms), Debug 에서는 GPU 경로의 이득이 더 큽니다.
