Gerstner 바다 구현 기록 — 정점 변위, 수평선까지 넓은 평면, 픽셀 단위 노멀

2026-11-23 · Gerstner 바다 구현 계획의 1~3단계를 구현한 기록입니다. 플레이어가 멈춰 있는 배 위에서 전투를 하고 배경으로 잔잔한 바다가 보이는 장면이 목표입니다. 파도는 GPU 에서만 계산하고 CPU 는 파도 높이를 읽지 않습니다(부력 없음).

계획 문서는 계획 당시 그대로 두고 맨 위 "구현하면서 바뀐 점" 상자만 덧붙였습니다. 이 문서는 지금 코드가 어떻게 되어 있는지, 무엇을 어떻게 확인했는지를 다룹니다.

기준: 커밋 3d19842. 코드 위치는 "파일 + 함수/타입 이름"으로 적었고, 경로는 SherlockEngine/ 프로젝트 폴더 기준입니다. 숫자는 구현하면서 에디터 자동화(--screenshot, --avg-frames)로 실행해 얻은 값이고, 화면 좌표는 에디터 씬 뷰(732×445) 기준입니다.

4. 파도 만들기 (CPU)

Ocean::BuildWaves 가 컴포넌트 값으로 파도를 만듭니다. 같은 값이면 같은 파도입니다. 난수는 시드로 만든 작은 LCG(state = seed · 747796405 + 2891336453, 다음 값 state · 1664525 + 1013904223, 출력 (state >> 8) / 2²⁴)이고 std::rand 는 쓰지 않습니다.

n      = clamp(waveCount, 1, 8)
Lᵢ     = Lmax · (Lmin / Lmax)^(i / (n − 1))      // 가장 긴 것에서 짧은 것까지 등비
kᵢ     = 2π / Lᵢ
Aᵢ     = amplitude · Lᵢ / Lmax                   // 모든 파도의 가파름 kA 가 같음 (기본 ≈ 0.05)
sᵢ     = clamp(steepness, 0, 1) / n              // Σ s ≤ 1 → 마루가 뒤집히지 않음
angleᵢ = windDirection + directionSpread · (2r − 1)   // 도, +X 에서 +Z 쪽
ωᵢ     = sqrt(9.81 · kᵢ) · speed                 // 깊은 물의 분산 관계. 긴 파도가 빠름
φ0ᵢ    = 2π · r

기본값: 파도 6, 바람 30°, 퍼짐 ±40°, 파장 4~32 m, 진폭 0.25 m, 경사 0.4, 속도 1, 시드 1, 감쇠 80~300 m. 수식은 Projects/SherlockTestScenes/Scripts/Tests/check_gerstner_normals.py 가 BuildWaves 를 그대로 옮겨 해석 노멀과 유한 차분 노멀을 비교합니다 — 각도 차 0.00001° 미만, 노멀 y 최솟값 0.975(steepness 1 이면 0.962).

5.2 정점 셰이더 VS_Ocean

  1. 평면 정점을 먼저 world·prevWorld 로 옮김(baseNow, basePrev). 파도는 월드 xz 에서 더하므로 바다를 옮기거나 요로 돌려도 파도 방향은 월드 기준입니다. 피치·롤은 지원하지 않습니다.
  2. GerstnerSample(baseNow, NOW) → 위치·노멀·편미분. GerstnerPosition(basePrev, PREV) → 지난 위치.
  3. position 은 viewProj(지터 포함), currClip·prevClip 은 지터 없는 두 행렬(unjitteredViewProj·prevUnjitteredViewProj).
  4. 탄젠트는 OceanSurfaceTangent(now, meshTangent.xz), 손잡이는 TangentHandedness(tangent.w, world).
  5. oceanBase = (baseNow.xz, meshTangent.xz) 를 픽셀 셰이더로 넘김.

정점 노멀은 격자 간격보다 촘촘한 굴곡을 담지 못하고, 성긴 격자에서는 삼각형 단위로 꺾입니다. 픽셀 셰이더가 변위 전 xz 로 파도를 다시 계산하면 격자 밀도와 상관없는 매끈한 노멀이 나옵니다. 속도·UV·위치는 VS 값을 그대로 씁니다. PS 가 b9 를 읽으므로 Layout_Object 의 b9 단계가 VS|PS 입니다.

5.4 대역 제한

// Ocean.hlsli 의 OceanBandLimit. dx0·dy0 = ddx·ddy(변위 전 xz)
cyclesPerPixel = kᵢ · length(float2(dot(dx0, Dᵢ), dot(dy0, Dᵢ))) / 2π
band           = 1 − smoothstep(0.1, 0.25, cyclesPerPixel)     // 파장당 10 픽셀 → 4 픽셀
// 노멀·편미분의 kᵢAᵢ 와 sᵢ 에 band 를 곱함. 위치에는 곱하지 않음
  • 파도 방향으로 잰 주기 수라 비스듬한 각도에서 깊이 방향으로만 성긴 픽셀이 그 방향 파도만 지웁니다.
  • 구간은 OceanHorizon.json 실험으로 정했습니다(9.3). 0.25~0.5(나이퀴스트 근처)는 깜빡임은 줄지만 외딴 점이 남았습니다.
  • 뺀 기울기를 거칠기로 옮기지는 않습니다(LEAN·Toksvig 류). 그래서 먼 바다의 해 반사 줄이 조금 약해집니다.

6. 시간과 속도 버퍼

  • 위상. 이번·지난 위상 φ = fmod(ω · t + φ0, 2π) 를 CPU 가 double 로 구해 b9 에 넣습니다. 셰이더는 ω · t 를 곱하지 않습니다.
  • 지난 시간. time − dt 가 아니라 지난 프레임에 실제로 쓴 시간(m_oceanPrevTime)입니다. 처음 프레임, ResetTemporalHistory 뒤, 바다 오브젝트가 바뀐 프레임(m_oceanPrevObject), --ocean-time 고정이면 지난 = 이번(속도 0). 일시정지에서는 totalTime 이 멈추므로 저절로 0 입니다.
  • 감쇠. 바다 원점 기준이라 이번·지난 위치에 같은 배율이 곱해집니다.
  • 시간 고정. --ocean-time=T 면 바다의 속도는 카메라 속도만 남으므로 뷰 17 이 검정이어야 합니다. 스크린샷 비교도 실행마다 같아집니다.
  • 정밀도. 엔진의 totalTime 이 float 라 실행 시간이 길면 입력 해상도가 떨어집니다(하루에 약 8 ms 단위). 위상 감기는 double 이지만 입력 해상도는 그대로입니다.

7. 넓은 평면·감쇠·수평선

Mesh::CreatePlane 에 spacingGrowth(g)를 추가했습니다. 축마다 정점 번호로 정한 t ∈ [−1, 1] 을 아래처럼 바꿉니다. 기울기가 가운데 (1 − g), 끝 (1 + 6g) 라 간격 비는 (1 + 6g)/(1 − g) 입니다. g = 0 이면 예전 균일 식을 그대로 써서 비트 단위로 같은 정점이 나옵니다. UV 는 g 와 상관없이 정점 번호에 대해 균일합니다.

  • 감쇠. fadeStart~fadeEnd(기본 80~300 m)에서 진폭과 경사를 함께 0 으로. 성긴 격자가 짧은 파도를 담지 못해 생기는 계단을 막고, 먼 바다는 평평하게 하늘을 비춥니다.
  • 수평선. OceanHorizon.json 은 바다 한 변 10 km, 씬 카메라·게임 카메라 far 5000 m 입니다. 바다는 far 에서 잘리고, 갑판 8 m 에서 그 자리는 수평선보다 약 0.09° 아래(씬 뷰에서 1 픽셀 미만)입니다. 수평선 바로 아래 행의 밝기는 164, 하늘 194, 조금 앞 바다 174~180 으로 틈은 없습니다.
  • 에디터. 메시 출처 편집 UI 가 없어 g 는 씬 JSON 의 params[2] 로만 넣습니다.

8. 바인딩·PSO·컬링

  • b9. kCBSlotOcean = 9, Layout_Object 에 VS|PS 로 b13 다음. 오브젝트 셋 바인딩 순서는 b1, b7, b13, b9. 같은 번호의 kCBSlotParticleCollision 은 컴퓨트 충돌 셋 전용이라 한 패스에 같이 묶이지 않습니다(b13 을 PrevSkin·ClusterBin 이 같이 쓰는 것과 같은 규칙). SM 5.0 은 b0~b13 이라 빈 번호가 없습니다.
  • 늘 올림. D3D12 의 Dynamic 상수 버퍼는 프레임마다 한 번은 써야 바인딩되므로 바다가 없어도 파도 0 개로 올립니다(b7·b13 과 같음).
  • 루트 시그니처. 메인 패스 26 → 28/64 DWORD.
  • 대조. kConstantBuffers 의 { "Ocean", 288 } 로 OceanVS·OceanPS·OceanGBufferPS 의 cbuffer 크기, ValidateBindings 로 b9 슬롯을 시작 로그에서 확인합니다.
  • PSO 키. 비트 0~7 정점 포맷, 8 미러, 9 와이어프레임, 10 뒷면 컬링, 11 블렌딩(메인만), 12 바다 VS. 와이어프레임·미러·컬링은 기존 코드를 그대로 탑니다.
  • 그림자. 바다는 shadowPipeline 이 비어 그림자 패스에 들어가지 않습니다. 받는 쪽은 변위된 월드 위치(포워드)·깊이 복원 위치(디퍼드)로 그대로 됩니다.
  • 컬링. 경계 구 반지름에 Ocean::MaxDisplacement(감쇠 전 Σ A + Σ s/k)를 더합니다.
  • 바다 개수. 씬에 하나. 둘째부터 "Ocean: 바다가 둘 이상임…" 경고 한 번.
