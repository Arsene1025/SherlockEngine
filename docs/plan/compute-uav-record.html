컴퓨트 RHI 구현 기록 — D3D12 컴퓨트, 버퍼 UAV, 블러 가중치 버퍼

2026-11-17 · RHI 확장 계획 3장(컴퓨트 파이프라인과 UAV)의 나머지, 곧 D3D12 컴퓨트 경로와 버퍼 UAV(RWStructuredBuffer)를 넣고, 그 첫 소비자로 블러 가중치 버퍼를 만든 기록입니다. 컴퓨트 가우시안 블러의 PS↔CS 1단계 차이를 조사한 결과와, 컴퓨트 블러를 기본값으로 바꾼 결정도 함께 적습니다.

기준: 커밋 9435e6b(D3D11 컴퓨트 + 컴퓨트 가우시안 블러) + 작업 트리(2026-11-17, 아직 커밋하지 않음). 위치는 "파일 + 함수 이름"이 기준입니다. 같은 날 rhi-roadmap-plan.html 의 진행 상황 표시와 낡은 상수도 고쳤습니다.

1. 요약

컴퓨트 파이프라인·텍스처 UAV·버퍼 UAV가 D3D11 과 D3D12 두 백엔드 모두에서 동작합니다. 컴퓨트 가우시안 블러는 PS 블러와 결과가 같고 (D3D12 0 픽셀, D3D11 1 픽셀 최하위 비트), 이제 기본 경로입니다 (RenderSettings::computeBlur = true). 컴퓨트 PSO 를 만들 수 없으면 PS 로 내려갑니다.
기능D3D11D3D12시점
컴퓨트 PSO · Dispatch · SetComputeResourceSet있음있음D3D11: 9435e6b / D3D12: 이번
텍스처 UAV (RWTexture2D, ResourceBinding::mip)있음있음D3D11: 9435e6b / D3D12: 이번

2. RHI 표면

항목추가·변경
ResourceDesc.hBufferBind_UnorderedAccess = 1 << 4. Default 사용법과 stride(구조체 크기)가 필수
BindingTypes.hBindingType::BufferUnorderedAccess (u#, RWStructuredBuffer, 컴퓨트 전용), IsBufferBinding()
CommandList.hBarrier(BufferHandle, ResourceState), UavBarrier(BufferHandle). 버퍼가 가질 수 있는 상태는 Common · ShaderResource · UnorderedAccess. 복사 상태는 CopyBuffer 가 정함
DXBC/ShaderCompiler.cpp리플렉션의 D3D_SIT_UAV_RWSTRUCTURED → BufferUnorderedAccess (바인딩 대조에 쓰임)

상한 상수 (BindingTypes.h, PipelineTypes.h): kMaxBindingSlots = 24, kMaxCbvRegister = 14, kMaxSrvRegister = 32, kMaxSamplerRegister = 16, kMaxUavRegister = 8, kMaxBindingSets = 4.

버퍼 상태 규칙: 상태는 프레임 끝에 Common 으로 돌아갑니다. D3D12 에서 버퍼는 ExecuteCommandLists 뒤에 COMMON 으로 감쇠(decay)하므로 그 규칙을 RHI 규칙으로 올렸고, D3D11 도 같은 시점에 기록을 되돌립니다. 따라서 프레임마다 처음 쓰기 전에 Barrier 를 다시 불러야 합니다. UAV 를 쓸 수 있는 버퍼를 SRV 로 읽으려면 ShaderResource 상태여야 합니다 (엄격 검사).

3. D3D11 (D3D11CommandList · D3D11Device)

  • 버퍼 추적 배열: 텍스처용 배열 옆에 m_vsSrvBuf · m_psSrvBuf · m_csSrvBuf · m_csUavBuf 를 둡니다. 같은 레지스터에 텍스처를 꽂으면 버퍼 항목을 지우고, 반대도 마찬가지입니다.
  • 위험(hazard) 처리: UAV 상태로 들어가거나 나올 때 그 버퍼가 꽂힌 SRV·UAV 슬롯을 풉니다 (UnbindShaderResourcesOf / UnbindUavsOf). 같은 자원이 SRV 와 UAV 에 동시에 꽂히면 D3D11 런타임이 한쪽을 NULL 로 만들기 때문입니다.
  • D3D11Buffer::GetUAV: D3D11_UAV_DIMENSION_BUFFER, 포맷 UNKNOWN, NumElements = size / stride. 생성 시 D3D11_BIND_UNORDERED_ACCESS + 구조체 버퍼 플래그.
  • UpdateBuffer(Default): UAV 버퍼가 Common 이 아니면 오류. EndFrame 이 리드백 뒤 ResetBufferStates().

4. D3D12

컴퓨트 PSO · 루트 시그니처 (D3D12PipelineState, D3D12Device::GetOrCreateRootLayout)

  • D3D12ComputePipelineState::Create 가 CS 스테이지와 "모든 슬롯이 컴퓨트 전용"인지 확인한 뒤 CreateComputePipelineState. 캐시는 그래픽스 PSO 와 세대(generation)를 같이 써서 핫리로드 때 함께 비워집니다.
  • 컴퓨트용 루트 레이아웃은 따로 만듭니다: IA 플래그 없음, 가시성 D3D12_SHADER_VISIBILITY_ALL. 캐시 키에 compute 플래그가 들어가고, 키가 같아도 저장된 레이아웃 핸들 배열을 다시 비교합니다 (충돌이면 경고 후 덮어씀).
  • UAV 는 SRV 와 같은 디스크립터 테이블(CBV/SRV/UAV 힙)에 들어갑니다. 그래서 D3D12ResourceSet::srvTableStart · srvCount 가 SRV + UAV 를 셉니다.

커맨드 리스트 (D3D12CommandList)

  • 파이프라인 슬롯이 그래픽스·컴퓨트 공용이라, SetComputePipeline 은 현재 그래픽스 PSO 기록을, SetPipelineState 는 컴퓨트 기록을 지웁니다 (다음 드로우·디스패치에서 다시 설정).
  • ApplyBindings(compute, caller) 가 SetComputeRoot* / SetGraphicsRoot* 로 갈립니다. 셋은 m_computeSets 에 따로 둡니다.
  • Dispatch 는 렌더 패스 안에서 부르면 거부합니다. UavBarrier 는 실제 D3D12_RESOURCE_BARRIER_TYPE_UAV.
  • 버퍼 상태 검사: BufferUnorderedAccess 슬롯은 UnorderedAccess, UAV 가능 버퍼를 BufferResource 로 읽으면 ShaderResource 여야 합니다.

버퍼 UAV (D3D12Device::CreateBuffer · CreateResourceSet)

  • 리소스에 D3D12_RESOURCE_FLAG_ALLOW_UNORDERED_ACCESS. 업로드 힙 스테이징 버퍼는 이 플래그 없는 desc 를 따로 씁니다.
  • 디스크립터: D3D12_UAV_DIMENSION_BUFFER, UNKNOWN, NumElements, StructureByteStride. 루트 UAV 가 아니라 테이블 디스크립터를 씁니다 — 디스크립터를 거치면 범위 밖 쓰기가 버려지지만 루트 UAV 는 범위 검사가 없습니다.
  • EndFrame 이 ExecuteCommandLists 바로 뒤 ResetBufferStates() (상태 감쇠와 기록을 맞춤).
  • CopyBuffer: Common(암묵적 승격) 또는 맞는 복사 상태여야 하고, 끝나면 CopyDest / CopySource 로 기록. D3D11 도 같은 규칙.

5. 블러 가중치 버퍼 (Renderer · RendererPost · 셰이더)

항목값
버퍼m_blurWeights "SB_BlurWeights": Default, ShaderResource | UnorderedAccess, stride 4, kMaxBlurRadius + 1 = 65 개 float
쓰는 쪽BlurWeightsComputeShader.hlsl CS_BlurWeights, [numthreads(64,1,1)], b4 PostParams + u0. 레이아웃 Layout_BlurWeights, 셋 Set_BlurWeights
읽는 쪽Common.hlsli 의 StructuredBuffer<float> blurWeights : register(t20). Layout_Post(PS) 와 Layout_BlurCompute(CS) 에 t20 추가 (kSRVSlotBlurWeights)
호출Renderer::DispatchBlurWeights — ApplyHdrEffects 의 블러 구간에서 PostParams 를 올린 직후. 뷰마다 높이가 달라 시그마가 다르므로 미리보기 뷰가 다시 씀
실패 시가중치 PSO 가 없으면 블러를 건너뛰고 한 번만 오류 로그 (두 경로 모두 이 버퍼를 읽음)

컴퓨트 PSO 캐시는 패스별 배열 GetComputePipeline(ComputePassId) 로 일반화했습니다 (kComputePasses 표: BlurCompute, BlurWeights). kMaxBlurRadius 는 ShaderConstants.h 와 Common.hlsli 두 곳에만 둡니다.

6. PS↔CS 1단계 차이 조사

9435e6b 에서 D3D11 의 컴퓨트 블러가 PS 블러와 2366 픽셀(최하위 1단계) 달랐습니다. D3D12 는 처음부터 0 이었습니다.

시험결과 (D3D11 게임 모드, PS vs CS)
UAV 저장을 내림(truncate)으로 흉내원래 CS 와 비트 단위로 같음 → UAV 저장도 내림
RNE 반올림으로 흉내두 백엔드 모두 약 77k 픽셀 차이 → RTV 쓰기도 RNE 가 아님
박스 가중치(모두 1)0 → 차이는 가중치 계산·누적 쪽
가중치를 버퍼로 공유 (이번 구현)1 픽셀
+ 두 셰이더 누적 변수에 precise0 (D3D11 CS = D3D12 CS 도 0). 대신 PS 출력이 변경 전과 39 픽셀 1단계 달라짐
원인은 특정하지 못했습니다. 조사 중에 "D3D11 드라이버가 CS 와 PS 의 exp 를 다르게 계산한다"고 결론냈지만, 가중치를 CS 에서 계산하도록 바꿔도 PS 출력이 변경 전과 같았으므로 그 결론은 측정과 맞지 않습니다. 확인된 것은 위 표의 숫자뿐이며, precise 로 차이가 없어지는 것으로 보아 곱셈+덧셈을 mad 로 합치는지가 스테이지마다 다른 것으로 보입니다. 모든 결과는 Debug 셰이더, 이 GPU 한 대에서 확인한 것입니다.

결정 (2026-11-17): precise 는 넣지 않습니다 — 기본 경로였던 PS 출력을 바꾸지 않는 쪽을 택하고, D3D11 의 PS↔CS 1 픽셀 차이는 받아들입니다. 그리고 컴퓨트 블러를 기본값으로 바꿨습니다.

7. 설계 결정·함정

  • 버퍼 상태는 프레임마다 Common: D3D12 의 감쇠를 숨기지 않고 규칙으로 올렸습니다. 그래서 Render 가 첫 후처리 패스 전에 Barrier(m_blurWeights, ShaderResource) 를 부릅니다 — 블러가 꺼진 프레임에도 톤 패스가 같은 레이아웃(t20 포함)을 바인딩하기 때문입니다.
  • 컴퓨트 셋은 따로: D3D12 는 컴퓨트 루트 인자가 그래픽스와 별개라 SetResourceSet 으로 꽂은 셋이 Dispatch 에 보이지 않습니다. RHI 도 SetComputeResourceSet 을 따로 둡니다.
  • PostParams 는 셋보다 먼저: D3D12 루트 CBV 는 셋을 꽂을 때가 아니라 드로우·디스패치마다 다시 바인딩하지만, 업로드 링 주소가 바뀌므로 UploadPostParams 다음에 셋을 꽂는 순서를 지킵니다.
  • D3D11 의 SRV/UAV 동시 바인딩: 가중치를 쓰려고 UnorderedAccess 로 바꾸는 순간, PS t20 · CS t20 에 남아 있던 같은 버퍼의 SRV 를 풀어야 UAV 가 NULL 이 되지 않습니다. Barrier(Buffer) 가 이 일을 합니다.
  • 비교는 연속 실행끼리만: 조사 중 ComputeBlur.json 이 카메라가 바뀐 채 다시 저장돼, 이전 기준 스크린샷과 큰 차이가 난 적이 있습니다. 같은 씬 상태의 연속 실행끼리만 비교합니다.
  • stdout 은 블록 버퍼링: setvbuf(_IOLBF) 가 Windows 에서는 완전 버퍼링이라, 실행 중 로그를 보려면 줄마다 flush 되는 x64/Debug/Logs/SherlockEngine.log 를 읽어야 합니다 (핫리로드 자동 검증에서 확인).

확인하지 못한 것

  • 실행 중에 Compute blur 체크박스를 켜고 끄기 (기본값이 바뀌었으므로 다음에 먼저 확인할 것)
  • 한 번도 실행되지 않은 경로: 버퍼 UavBarrier, CopyBuffer 상태 규칙, UpdateBuffer 의 UAV 검사, 배리어 오류 경로, 루트 레이아웃 키 충돌 경로
  • --select 의 PS = CS 는 두 경로가 같은 버퍼를 읽기 때문이므로, 뷰마다 가중치가 다시 쓰이는지를 증명하지는 않음
  • Release 셰이더, 다른 GPU
