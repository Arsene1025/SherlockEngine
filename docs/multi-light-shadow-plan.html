2.1 한 프레임의 흐름

Renderer::Render()
 ├ m_shadowSettings = scene.environment.shadow
 ├ LightConstants lights = (지금처럼 복사 + 방향 정규화)

#결정이유고르지 않은 대안
D1섀도 아틀라스 (큰 2D 깊이 텍스처 1장을 타일로 나눔)D3D11·D3D12 API는 깊이 텍스처 배열(장 단위 DSV, Texture2DArray SRV, TextureCubeArray)을 모두 지원하지만 우리 RHI에는 아직 2D 배열·큐브 DSV가 없음. 또 여러 종류의 조명을 섞는 상용 엔진(Unity URP, Godot, UE4)도 그림자마다 해상도를 다르게 줄 수 있는 아틀라스를 많이 씀(배열은 CSM만 따로 구현할 때 흔함). 아틀라스는 뷰포트만 바꾸면 되고, PS도 텍스처 하나(t8)·샘플러 하나(s4)를 그대로 씀. MS의 CSM 문서도 D3D10 시절 PCF 제약 때문에 같은 방식("one large buffer + viewport per cascade")을 씀Texture2DArray + 슬라이스별 DSV, 큐브 섀도 맵: ResourceDesc·뷰 생성·디스크립터를 양쪽 백엔드에서 손봐야 해서 이번 범위를 넘음
D2CommandList::SetViewport 추가 (사용자 선택)그림자 패스를 1개로 유지. D3D12의 RSSetViewports/RSSetScissorRects와 1:1로 대응해 RHI 목표에 맞음타일마다 렌더 패스: RHI는 그대로지만 패스·통계가 늘고 Load/Clear 관리가 번거로움
D3b5·b6을 기존 프레임 레이아웃에 추가. 그림자 PSO는 지금처럼 {frame, object}D3D12 커맨드 리스트가 기억하는 셋이 이미 4개로 가득 차 있음(1장 표). 새 레이아웃은 D3D12에서만 조용히 빠짐새 Layout_ShadowPass: 위 이유로 탈락. 커맨드 리스트의 셋 용량을 PSO 상한과 분리하는 RHI 개선은 따로 할 일로 남김
D4그림자 좌표를 PS에서 계산. VSOutput.shadowPosition과 b0 lightViewProj 삭제조명마다 쓰는 뷰가 다르고(포인트는 면, CSM은 캐스케이드까지 PS에서 고름) VS 출력 하나로는 표현할 수 없음VS에서 뷰 N개 좌표를 전부 출력: 보간기 슬롯이 모자라고 대부분 버려짐
D5LightData의 padding 자리에 castShadows, shadowIndex. 80B 유지상수버퍼 레이아웃과 static_assert가 그대로임. GPU 사본에 Renderer가 값을 써 넣는 것은 지금 방향 정규화(Render 약 1027~1039행)와 같은 방식별도 배열 int shadowIndex[8]: cbuffer 배열은 원소마다 16B라 128B를 씀
D6타일 크기 고정: 지역광 1024, 방향광 영역 2048할당이 "다음 빈 타일 번호"로 끝남. 디버그·검증이 쉬움크기가 다른 타일과 거리별 해상도: 나중 개선 거리
D7바이어스: 직교 뷰(방향광·캐스케이드)는 지금의 NDC 깊이 바이어스. 원근 뷰(스팟·포인트)는 NDC 바이어스 0 + 노멀 방향 월드 오프셋(텍셀 크기 × 배율)원근 투영의 깊이는 비선형이라 고정 NDC 바이어스가 거리마다 다른 월드 거리가 됨. 노멀 오프셋은 텍셀의 월드 크기에 비례해 거리와 무관하게 일정함원근 뷰 전용 PSO(래스터 바이어스 별도): 단계 5에서 여드름이 남으면 추가 (함정 5)

float SampleShadowView(uint viewIndex, float3 worldPosition, float3 geometricNormal, float3 normalDelta, float distanceToLight)
{
    float result = 1.0f;   // 단일 반환 구조 유지 (fxc -Od 의 X4000 오경고 회피 — 지금 함수의 주석 그대로)

    const bool perspective = view.params.z > 0.5f;

    // (1) 원근 뷰만: 받는 쪽 위치를 기하 노멀 방향으로 "텍셀 몇 개"만큼 밀어 자기 그림자를 피함 (단계 5부터 의미가 있음)
    const float texelWorld = perspective ? view.params.y * distanceToLight : view.params.y;
    const float3 p = worldPosition + geometricNormal * (perspective ? shadowAtlasParams.z * texelWorld : 0.0f);

    // (2) 월드 → 이 뷰의 클립 → NDC → 타일 안 UV (0..1). y 는 뒤집음 (지금 코드와 같음)
    const float4 clip = mul(float4(p, 1.0f), view.viewProj);
    const float3 ndc = clip.xyz / clip.w;
    float2 local = float2(ndc.x * 0.5f + 0.5f, -ndc.y * 0.5f + 0.5f);

    // (3) 노말맵 오프셋 (지금의 shadowExtra.x). 방향(w = 0)을 같은 행렬로 옮기고 clip.w 로 나눔 — 직교면 w = 1 이라 지금과 같음
    const float4 deltaClip = mul(float4(normalDelta, 0.0f), view.viewProj);
    local += deltaClip.xy / clip.w * float2(0.5f, -0.5f) * shadowExtra.x;

    // (4) 이 뷰 밖이면 빛을 받는 것으로 봄. 원근 뷰는 광원 뒤(w ≤ 0)와 near 앞(z < 0)도 밖
    const bool inside = clip.w > 0.0f && all(local >= 0.0f) && all(local <= 1.0f) && ndc.z <= 1.0f && (!perspective || ndc.z >= 0.0f);
    if (shadowParams.w >= 0.5f && inside)
    {
        // (5) 타일 UV → 아틀라스 UV. PCF 커널이 옆 타일을 읽지 않도록 여백(텍셀)만큼 안쪽으로 clamp
        float2 uv = view.atlasRect.xy + local * view.atlasRect.zw;
        const float2 border = shadowAtlasParams.y * shadowAtlasParams.x;
        uv = clamp(uv, view.atlasRect.xy + border, view.atlasRect.xy + view.atlasRect.zw - border);
        const float depth = ndc.z - view.params.x;

        // (6) 지금의 5×5 PCF 루프 그대로 (SampleCmpLevelZero, int2 오프셋)
        ...
        result = lerp(1.0f, lit / 25.0f, shadowParams.z);
    }
    return result;
}

    }

}

6-B. 지역광 컬링

점광 하나가 뷰 6개라 그림자 드로우가 "뷰 수 × 물체 수"로 늘어납니다. D3D12 업로드 링(프레임당 8 MB ÷ 256 B ≈ 32,768회)에는 Sponza 규모에서도 여유가 있지만, 범위 밖 물체를 그리는 것은 낭비이므로 구(sphere) 대 구 검사로 건너뜁니다.

7CSM (방향광 캐스케이드)

목표방향광 영역을 캐스케이드 2~4개로 나눠 카메라 가까운 곳에 해상도를 몰아준다. 캐스케이드는 회전·이동에 흔들리지 않게 만든다. 파일수정: Scene/ShadowSettings.h, Scene/SceneSerializer.cpp, App/DebugUI.cpp, App/Editor.cpp (디버그 뷰 콤보), Graphics/Renderer.h/.cpp, Shaders/BasicPixelShader.hlsl 만드는 것ShadowSettings::cascadeCount/cascadeDistance/cascadeLambda, void Renderer::AddCascadeViews(const Camera& camera, const LightData& light, uint32_t lightIndex), 멤버 m_cascadeCount·m_cascadeSplits·m_cascadeOrigin·m_cascadeForward, HLSL int SelectCascade(float3 worldPosition), 디버그 뷰 8 "Shadow cascade"

7-A. 설정

필드기본값뜻UI
int cascadeCount11 = 지금처럼 직교 뷰 하나(orthoSize/distance). 2~4 = CSMSliderInt("Cascades", 1, 4)
float cascadeDistance60그림자를 그리는 최대 카메라 거리(카메라 far와 작은 쪽)5 ~ 300 (CSM일 때만 표시)

저장 키는 필드 이름 그대로입니다(SceneSerializer.cpp 그림자 묶음). 기본값 1이라 옛 씬은 지금과 똑같이 보입니다. CSM일 때 distance("Light distance")는 "카메라 밖 뒤쪽 캐스터까지 잡는 거리"로 계속 쓰이고, orthoSize는 바이어스 환산 기준으로만 쓰입니다. UI에서 Ortho size 옆에 그렇게 적어 둡니다.

7-B. AddCascadeViews 알고리즘

BuildShadowViews의 방향광 분기에서 cascadeCount >= 2 && camera.IsUsePerspectiveProjection()이면 이 함수를, 아니면 지금의 단일 뷰를 씁니다(직교 카메라에서는 절두체 조각 계산이 맞지 않으므로 단일 뷰로 대체).

N = cascadeCount,  n = camera.GetNearZ(),  f = min(camera.GetFarZ(), cascadeDistance)
분할 (practical split):  s[i] = λ · n · (f/n)^(i/N) + (1 − λ) · (n + (f − n) · i/N),   i = 0..N   (s[0] = n, s[N] = f)

캐스케이드 c = 0..N−1:
  1) 조각의 꼭짓점 8개: d ∈ {s[c], s[c+1]} 마다
       h = d · tan(fovY/2),  w = h · aspect,  center = camPos + forward · d
       꼭짓점 = center ± right · w ± up · h
  2) 경계 구: 중심 C = 8개의 평균, 반지름 r = max |꼭짓점 − C|,  r = ceil(r · 16) / 16   ← 크기를 계단화해 회전에도 투영 크기가 그대로
  3) 광원 뷰:  eye = C − dir · (r + back),  back = shadow.distance
              view = XMMatrixLookToLH(eye, dir, up)        (up 은 ComputeLightViewProj 와 같은 규칙)
              proj = XMMatrixOrthographicLH(2r, 2r, 0, 2r + back)
  4) 텍셀 스냅:  월드 원점을 이 투영으로 옮긴 좌표를 텍셀 격자에 맞춤
              o = XMVector4Transform((0,0,0,1), view · proj) · (tile / 2)
              offset = (round(o) − o) · (2 / tile)
              proj.r[3] += (offset.x, offset.y, 0, 0)
  5) 사각형 = DirectionalRect(c, N),  tile = kShadowTileSize
     params = ( shadow.bias · (2·distance + orthoSize) / (2r + back),   ← 단일 뷰와 같은 "월드 거리" 바이어스로 환산
                2r / tile, 0, 0 )
  6) 첫 캐스케이드의 뷰 번호가 그 조명의 shadowIndex

m_cascadeSplits = (s[1], s[2], s[3], s[4])  (없는 칸은 0),  m_cascadeOrigin = camPos,  m_cascadeForward = forward,  m_cascadeCount = N

UploadShadowConstants가 cascadeSplits, cascadeOrigin = (camPos, N), cascadeForward = (forward, 0)을 올립니다. CSM이 아니면 cascadeOrigin.w = 0입니다. 카메라 벡터는 Camera::GetForward/GetRight/GetUp, 렌즈 값은 GetFovY/GetAspect/GetNearZ/GetFarZ를 씁니다.

int SelectCascade(float3 worldPosition)
{
    int result = -1;
    const uint count = (uint)cascadeOrigin.w;
    const float depth = dot(worldPosition - cascadeOrigin.xyz, cascadeForward.xyz);   // 캐스케이드를 계산한 카메라의 전방 거리

        if (result < 0 && i < count && depth < cascadeSplits[i]) result = (int)i;
    }
    return result;
}

function Shot {
    param([string]$Name, [string]$Scene, [string]$Backend = "d3d11", [int]$View = 0,
          [string]$Exe = "SherlockEditor.exe", [string[]]$Extra = @())
    $argList = @(
        "--project=Projects\SherlockTestScenes\SherlockTestScenes.sherlock",
        "--scene=$Scene", "--backend=$Backend", "--exit-after=40",
        "--screenshot=$out\$Name.png", "--debug-view=$View") + $Extra
    # Start-Process 는 인자를 따옴표 없이 이어 붙이므로, 공백이 든 값(--select=Main Camera)도 한 인자로 가게 감쌈
    $argList = $argList | ForEach-Object { '"' + $_ + '"' }
    $start = Get-Date
    # 에디터는 GUI 실행 파일이라 그냥 실행하면 기다리지 않음. -Wait 로 종료까지 기다림
    Start-Process -FilePath "$root\x64\Debug\$Exe" -ArgumentList $argList -WorkingDirectory $root -Wait
    # 로그는 실행마다 새로 쓰이므로 결과 옆에 복사해 둠. 이번 실행이 쓴 로그가 아니면 경고
    $log = "$root\x64\Debug\Logs\SherlockEngine.log"
    if ((Get-Item $log).LastWriteTime -lt $start) { "[주의] 이번 실행이 로그를 쓰지 않음: $log" }
    Copy-Item $log "$out\$Name.log"
    $ok = (Select-String -Path "$out\$Name.log" -Pattern "바인딩 대조.*OK").Count
    "바인딩 대조 OK: $ok 줄"
    Select-String -Path "$out\$Name.log" -Pattern "\[실패\]|\[경고\]" | ForEach-Object { $_.Line }
}

function GameShot {
    param([string]$Name, [string]$Scene, [string]$Backend = "d3d11")
    $proj = "$root\Projects\SherlockTestScenes\SherlockTestScenes.sherlock"
    $orig = [IO.File]::ReadAllText($proj)

    try     { Shot $Name $Scene $Backend 0 -Exe SherlockGame.exe }
    finally { [IO.File]::WriteAllText($proj, $orig) }
}

                    if (d != null) { int v = Math.Min(255, m * 8); d.SetPixel(x - x0, y - y0, Color.FromArgb(v, v, v)); }

function Compare-Shot {
    param([string]$A, [string]$B, [switch]$Diff, [switch]$Full)
    $diffPath = if ($Diff) { "$out\diff-$A-$B.png" } else { "" }

}

쪽 번호를 적지 않은 이유. 쪽 번호는 판·인쇄본·전자책마다 다르고, 합법적으로 볼 수 있는 자료(출판사 목차 등)에서는 쪽까지 확인하지 못했습니다. 틀린 쪽을 적느니 장·절 번호만 적었습니다. 장·절 번호는 같은 판이면 바뀌지 않으므로 책의 목차에서 찾은 뒤 마지막 쪽 칸을 직접 채워 쓰세요. 상태 열: 확인됨 = 공개 목차 자료로 장·절 번호를 확인함, 목차로 확인 = 기억에 기댄 번호라 한두 절 어긋날 수 있음. 제목은 원서(영문판) 기준입니다.
