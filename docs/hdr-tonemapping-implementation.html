2026-10-23 · hdr-tonemapping-plan.html 계획의 단계 2~7을 실제로 구현한 내용과 프레임 흐름을 정리한 기록입니다. 이 문서는 계획서를 고치지 않고 따로 만든 것입니다.

1. 요약

씬은 이제 선형 FP16 텍스처(R16G16B16A16_FLOAT)에 그려지고, 톤 패스가 그 텍스처를 읽어 노출 → ACES → sRGB 인코딩을 한 번만 적용한 뒤 최종 출력(에디터는 씬 뷰 텍스처, 게임은 백버퍼)에 씁니다. 머티리얼·스카이박스 PS는 더 이상 톤매핑을 하지 않습니다.
단계내용상태

2. 프레임 흐름 (이전 → 이후)

이전:  ShadowPass → MainPass(8비트 sRGB RTV, PS 끝에서 노출·ACES) → [PreviewPass] → UIPass

이후:  ShadowPass
       → MainPass          (HDR 텍스처 m_hdrColor, 선형, 톤매핑 없음)
       → TonemapPass       (m_hdrColor 를 t13 으로 읽음 → 노출·ACES → sRGB RTV)
             출력: 에디터 = m_sceneColor, 게임 = 백버퍼
       → [PreviewPass      (m_previewHdr)
          → PreviewTonemapPass  (→ m_previewColor)]
       → UIPass            (백버퍼 UNORM 뷰, 이전과 같음)

리소스 상태 전이

리소스메인 패스톤 패스
m_hdrColorCommon/ShaderResource → RenderTarget → ShaderResource읽기만 (t13)
에디터 m_sceneColor쓰지 않음이전 상태 → RenderTarget → ShaderResource (ImGui가 샘플링)
게임 백버퍼쓰지 않음Present → RenderTarget (UI 패스가 이어서 그림)
m_previewHdr→ RenderTarget → ShaderResource읽기만
m_previewColor쓰지 않음이전 상태 → RenderTarget → ShaderResource

백버퍼의 Present → RenderTarget 전이는 예전에는 RenderMainPass에 있었고, 이제 톤 패스로 옮겼습니다. BeginUIPass는 에디터가 아닐 때 전이하지 않고 백버퍼가 이미 RenderTarget이라고 가정하기 때문입니다.

3. 23 셰이더와 연결 규칙

ScreenVertexShader.hlsl — VS_Screen

정점 버퍼 없이 SV_VertexID 0, 1, 2로 화면 전체를 덮는 삼각형 하나를 만듭니다 (NDC (−1,1), (3,1), (−1,−3)). 색은 계산하지 않고, 삼각형이 덮는 모든 픽셀에서 PS가 한 번씩 돌게 하는 역할입니다. 후처리 패스(블룸, FXAA 등)가 늘어나도 이 VS를 공유합니다.

TonemapPixelShader.hlsl — PS_Tonemap

Texture2D sceneHdr : register(t13);

float4 PS_Tonemap(float4 position : SV_POSITION) : SV_TARGET
{
    const float3 hdr = sceneHdr.Load(int3((int2)position.xy, 0)).rgb;
    if (debugParams.x > 0.5f)                 // 디버그 뷰는 노출·톤매핑을 거치지 않음
        return float4(saturate(hdr), 1.0f);
    return float4(ApplyExposureToneMap(hdr), 1.0f);
}
  • 샘플러 없이 Load: 입력과 출력이 같은 크기라 1:1 대응이고, 재질 샘플러(s0)와 슬롯이 겹치지 않습니다.
  • 쓰는 리소스는 b0(PerFrame)와 t13뿐입니다. b0에서 outputParams(노출·톤매핑 on/off)와 debugParams.x를 읽습니다.

4. 4 HDR 타깃 생성

새 멤버 (Renderer.h)

uint32_t m_outputWidth, m_outputHeight;     // 게임 모드(백버퍼) 출력 크기 — SetOutputSize
TextureHandle m_hdrColor;                   // R16G16B16A16_FLOAT
uint32_t m_hdrWidth, m_hdrHeight;
ResourceState m_hdrColorState;
ResourceSetHandle m_hdrPostSet;             // Layout_Post: b0 (PerFrame) + t13 (m_hdrColor)
TextureHandle m_previewHdr;                 // 카메라 미리보기용

ResourceSetHandle m_previewHdrPostSet;

함수

함수하는 일
SetOutputSize(w, h)값만 저장. 텍스처는 만들지 않음 (에디터는 곧 SetSceneTarget으로 크기를 바꾸므로 지금 만들면 버리게 됨). Engine::Initialize(Renderer 초기화 직후)와 Engine::OnResize가 호출
EnsureHdrTargets()Render() 맨 앞에서 호출. 목표 크기 = IsOffscreen() ? (m_sceneWidth, m_sceneHeight) : (m_outputWidth, m_outputHeight). 같으면 아무것도 안 함. 다르면 DestroyHdrTargets() → 텍스처 생성 → 리소스 셋 생성 (슬롯 순서 b0, t13). 실패하면 로그 후 정리. 성공하면 "HDR 텍스처 WxH" 로그
DestroyHdrTargets()셋과 텍스처 해제, 크기·상태 초기화. Shutdown에서도 사용
SetPreviewTarget (수정)정리 단계에 m_previewHdr, m_previewHdrPostSet 포함. 생성 단계에서 FP16 텍스처 "CameraPreview_HDR"와 셋을 만들고, 실패 검사에 포함
HDR 텍스처 크기 = 깊이 버퍼 크기 = 출력 크기여야 합니다. 에디터는 m_sceneDepth, 게임은 장치 깊이 버퍼(Device::Resize가 백버퍼와 함께 다시 만듦)를 씁니다.
HDR 텍스처를 만들지 못한 프레임은 Render()가 일찍 return합니다 (if (!m_hdrColor.IsValid() || !m_hdrPostSet.IsValid()) return;). 정상 경로에서는 일어나지 않고, 이 경우 D3D12에서는 백버퍼 상태 전이가 빠지므로 에러 로그가 뜰 수 있습니다.

5. 567 패스 전환과 톤매핑 이동

PSO의 RTV 포맷

GetPipelineFor와 GetSkyPipeline은 이제 항상 R16G16B16A16_FLOAT입니다 (srgbOutput 분기 삭제). sRGB 여부는 톤 PSO(GetTonemapPipeline)만 따집니다. D3D12 PSO는 렌더 타깃 뷰 포맷이 다르면 그릴 수 없으므로, 메인·스카이·톤 세 PSO를 각각 맞췄습니다.

RenderMainPass

  • 색 타깃을 m_hdrColor로, srgbView = false. 깊이는 IsOffscreen() ? m_sceneDepth : 장치 깊이 버퍼.
  • m_hdrColorState → RenderTarget → 그리기 → → ShaderResource.
  • 예전의 씬 뷰 텍스처·백버퍼 전이는 제거 (톤 패스가 담당).

RenderTonemapPass(cmd, hdrSet, output, outputBefore, outputAfter, debugName) (신규)

cmd.Barrier(output, outputBefore, RenderTarget);
BeginRenderPass({ output, LoadOp::DontCare, srgbView = srgbOutput });   // 깊이 없음
cmd.SetPipelineState(GetTonemapPipeline());
cmd.SetResourceSet(hdrSet);       // b0 + t13
cmd.Draw(3, 0);
cmd.EndRenderPass();
cmd.Barrier(output, RenderTarget, outputAfter);

Render() 호출 순서

EnsureHdrTargets();  if (HDR 없음) return;
... 그림자 패스, 메인 패스(HDR) ...
톤 패스: 에디터 → (m_hdrPostSet, m_sceneColor, 이전 상태 → ShaderResource)
        게임   → (m_hdrPostSet, 백버퍼, Present → RenderTarget)
프리뷰: UploadPerFrameConstants(미리보기 카메라) → RenderPreviewPass → 프리뷰 톤 패스

메인 톤 패스를 프리뷰 패스보다 먼저 둔 이유: 프리뷰 패스가 b0를 다른 카메라로 덮어쓰기 전에 톤 패스를 끝내 두면, 톤 패스가 b0의 카메라 값과 무관하게 동작합니다.

RHI에서 확인한 것

  • D3D11: BeginRenderPass가 attachment 텍스처를 쓰는 모든 SRV 슬롯(m_psSrv[0..15])을 해제합니다. t13도 포함되어, 다음 프레임 메인 패스가 m_hdrColor를 RTV로 잡을 때 SRV 충돌 경고가 나지 않습니다.
  • D3D12: SetResourceSet은 바인딩을 기록만 하고 실제 바인딩은 드로우 직전(ApplyBindings)에 합니다. 따라서 SetPipelineState 뒤에 SetResourceSet을 불러도 안전하고, 루트 시그니처가 바뀌면 테이블을 다시 바인딩합니다.
  • 바인딩 셋 수: 한 프레임에 프레임·오브젝트·재질·포스트 4개가 쌓이며, 상한 kMaxBindingSets = 4에 정확히 맞습니다. 이후 레이아웃을 하나 더 늘리면 이 상한을 올려야 합니다.
  • 동적 상수버퍼: D3D12는 Dynamic 상수버퍼가 이번 프레임에 갱신되지 않았으면 경고합니다. b0는 매 프레임 UploadPerFrameConstants로 갱신되므로 문제없습니다.

7. 검증

한 것: Debug x64 MSBuild 통과 (경고 0, 오류 0). 셰이더 두 개를 포함해 프로젝트의 FxCompile이 모두 컴파일됨. ApplyExposureToneMap 호출처는 톤 PS 한 곳, 씬 패스에서 srgbView = m_settings.srgbOutput를 쓰는 곳은 없음 (grep).
D3D11 실행 한 번: SherlockEditor.exe --project=CubemapTest --exit-after=40 --screenshot=.... 로그에 바인딩 대조: ToneMapPS t13/b0 OK, HDR 텍스처 1280x670(첫 씬 뷰 크기)과 패널 크기가 바뀐 뒤 HDR 텍스처 614x294가 크기가 바뀔 때 한 번씩만 떴고, 오류 로그와 디버그 레이어 경고는 없었습니다. 스크린샷은 검지도 희지도 않게 구체·헬멧·하늘이 정상으로 보였습니다 (톤매핑 켜짐, 노출 1, IBL 0.5).
하지 않은 것: 이전 화면과의 픽셀 비교(기준 스크린샷이 없음), D3D12 백엔드 실행, Release 빌드, 게임 모드(SherlockGame.exe)와 카메라 미리보기 실행. 종료 시 로그에 D3D11: Live ID3D11Device ... Refcount: 3 경고가 한 줄 있었는데, 장치 자체에 대한 종료 시점 보고이고 개별 텍스처가 남았다는 줄은 없었습니다. 이 변경 이전에도 있었는지는 비교하지 못했습니다.

체크리스트

  1. 에디터를 실행해 씬이 이전과 같게 보이는지 확인. 톤매핑을 끈 씬은 거의 같고, 켠 씬은 배경색만 달라질 수 있음.
  2. 로그에 HDR 텍스처 WxH (R16G16B16A16_FLOAT)가 뜨고, 씬 뷰 패널 크기를 바꿀 때만 새로 뜨는지 확인 (같은 크기에서 매 프레임 뜨면 EnsureHdrTargets 비교 오류).
  3. Exposure 슬라이더와 "ACES tone mapping" 체크박스가 효과를 내는지 확인.
  4. F5(sRGB output) 토글이 이전과 같은 의미로 동작하는지 (끄면 감마 보정 없이 어두워짐).
  5. 디버그 뷰 1~7이 톤매핑 없이 그대로 나오는지 (알베도 뷰가 노출에 영향을 받지 않아야 함).
  6. CubemapTest(톤매핑 켜짐, IBL 0.5)에서 하늘과 하이라이트가 하얗게 날아가지 않는지. HDR 큐브의 태양이 이전보다 자연스럽게 눌리는지.
  7. 카메라 오브젝트를 선택해 프리뷰가 나오는지, 선택 해제 시 반납되는지.
  8. Play 모드(게임 시점)와 게임 창 리사이즈. 디버그 레이어 경고가 없어야 함.
  9. engine.backend = d3d12로 위 항목 반복. 특히 PSO RTV 포맷·배리어 경고.
  10. 씬 저장·재로드 후 노출·톤매핑 값 유지.
스크린샷은 백버퍼를 읽으므로 HDR 값 자체(1을 넘는 값)는 확인할 수 없습니다. HDR 값 확인용 디버그 뷰는 이번 범위 밖입니다.
