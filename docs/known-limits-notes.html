알려진 한계 정리 (22.4 후속)

2026-10-15 · rendering-analysis.html 22.4 "코드에 남아 있는 알려진 경고와 한계"에서 지금 코드로 고칠 수 있는 것을 고치고, 나머지는 무엇이 더 필요한지를 정리했습니다. 기존 분석 문서는 고치지 않았습니다.

상태: 작업 트리에 반영, 커밋하지 않음. 2026-10-23 갱신: "톤매핑이 셰이더 끝에 있음"을 해결했으므로 2장에서 1장으로 옮김(구현 기록).

1. 고친 것

통계의 배리어 수 Renderer.cpp

  • 문제. 패널의 barriers·passes 가 Renderer::Render 끝에서 찍혀 UI 패스와 마지막 Present 전이가 빠졌습니다.
  • 수정. Render 시작에서 Stats 를 비울 때 두 값은 지난 프레임 값을 남기고, 값 채우기는 EndUIPass 의 마지막 배리어 뒤로 옮겼습니다(cmd.GetStats() 가 그 프레임 전체를 셈). 패널이 UI 패스 안에서 그려지므로 한 프레임 늦은 값이 보입니다. 카운터라 문제는 없습니다.
  • 결과. 데모 씬 에디터: passes 3, barriers 6(그림자·메인·UI 패스, Present 전이 포함). 이전에는 UI 패스 몫이 빠진 값이었습니다. 이 수치를 문서에 적은 곳(분석 문서의 통계 표들)은 UI 패스만큼 늘어난 값으로 읽어야 합니다.
  • 확인하지 못한 것. D3D12 에서 숫자를 따로 대조하지 않았고, EndUIPass 를 부르지 않는 앱 구성이 있다면 그 구성에서는 값이 갱신되지 않습니다(엔진 루프는 항상 부름).

스카이박스는 원근 투영 전제 SkyboxVertexShader.hlsl

  • 문제. 시선 방향을 ndc / proj._11, ndc / proj._22 로 복원하는 식이 원근 전제라, 직교 카메라에서 방향이 원근처럼 퍼져 보였습니다.
  • 수정. 직교 투영이면(proj._44 > 0.5, 원근은 0) 모든 픽셀의 방향을 카메라 앞 방향 하나로 고정합니다. 직교에서 하늘은 원래 단색에 가깝습니다.
  • 검증. 카메라 기본값을 잠시 직교로 바꿔(검증 뒤 원복) 데모 씬을 D3D11·D3D12 로 실행: 하늘이 단색으로 나오고 오류 없음. 원복 후 헬멧 씬을 두 백엔드로 실행해 오류·경고 없음(종료 시 Live Device 한 줄만).
  • 확인하지 못한 것. 직교 카메라 UI(현재 에디터에 직교로 바꾸는 UI 가 없음)로의 확인, 두 백엔드 직교 화면의 픽셀 대조(스크린샷에 UI 가 들어가 직접 비교가 되지 않음), Release 빌드.

톤매핑이 셰이더 끝에 있음 Renderer.cpp · TonemapPixelShader.hlsl (2026-10-23)

  • 문제. HDR 렌더 타깃이 없어 노출·ACES 근사를 메인 PS 와 스카이박스 PS 의 끝에서 8비트 타깃에 쓰기 직전에 했습니다. 1 을 넘는 값이 그 자리에서 잘렸고, 블룸처럼 화면 전체를 보는 후처리를 넣을 수 없었습니다.
  • 수정. 메인·미리보기 패스가 R16G16B16A16_FLOAT 선형 텍스처에 그리고, 풀스크린 톤매핑 패스(ScreenVertexShader + TonemapPixelShader)가 노출·ACES·sRGB 인코딩을 한 번만 적용해 최종 출력에 씁니다. 메인·스카이박스 PS 의 ApplyExposureToneMap 호출은 지웠습니다.
  • 결과. Debug x64 빌드 통과(경고 0). D3D11 에디터를 자동 검증 모드로 한 번 실행: 톤 PS 의 t13·b0 바인딩 대조 OK, HDR 텍스처가 크기가 바뀔 때만 만들어짐, 스크린샷 정상.
  • 화면이 달라지는 점. 클리어 색(배경)이 노출·ACES 를 거치므로 톤매핑을 켰거나 노출이 1 이 아닌 씬은 배경색이 달라집니다. unlit 재질(감마 검증용)도 톤매핑을 거치므로 감마 검증은 톤매핑을 끄고 노출 1 에서 해야 합니다.
  • 확인하지 못한 것. D3D12 백엔드 실행, 게임 모드와 카메라 미리보기 실행, 이전 화면과의 픽셀 대조(기준 스크린샷 없음), Release 빌드.

2. 지금 못 고친 것 — 무엇이 필요한가

항목왜 지금 못 고치나필요한 것
환경이 없는 씬의 금속이 어두움버그가 아니라 설계 한계입니다. 환경이 없으면 금속은 균일한 ambientColor 만 반사합니다(물리적으로는 맞는 결과). 헬멧·데모 등 내장 씬은 10-08 부터 기본 환경이 있어 이미 해결되어 있습니다.결정: ① 환경이 없는 씬에 엔진 기본 환경(Cubemap 샘플 세트)을 자동 적용 — 옛 씬의 모습이 바뀜 ② 셰이더에 하늘/땅 그라데이션 같은 절차적 환경 — 반사 계산이 모든 씬에 영향 ③ 지금처럼 두고 씬 쪽에서 환경을 지정. 어느 쪽이든 기존 씬 화면 비교가 필요합니다.
모델 루트 경로 미실행노드가 둘 이상인 모델을 빈 루트 아래 묶는 경로를 실행해 볼 모델이 저장소에 없습니다(동봉 모델이 모두 단일 노드).다중 노드 glTF 한 개(라이선스가 자유로운 샘플, 예: 계층이 있는 간단한 장면). 불러온 뒤 --dump-objects=1 로 계층·위치를 보고, 단일 노드 모델과 같은 방식으로 놓였는지 스크린샷으로 확인.
셰이더 모델을 정하는 곳이 두 군데런타임 컴파일(GetTargetProfile)과 빌드(vcxproj 의 ShaderModel)가 다른 도구의 설정이라 코드만으로 한 곳으로 합칠 수 없습니다.결정: ① 현재 상태 유지(올릴 때 두 군데를 같이 바꾼다는 주석) ② 시작할 때 .cso 의 프로파일(리플렉션)과 런타임 프로파일을 대조해 어긋나면 경고하는 검사 추가. 셰이더 모델을 실제로 올리는 일(컴퓨트·SM 5.1 이상)이 생길 때 같이 하는 것이 효율적입니다(가이드 3장 참고).
비균등 스케일 부모의 분해 근사로컬 변환을 위치·회전·스케일로만 저장해 전단(shear)을 표현할 수 없습니다. 오차를 경고하는 정도는 가능하지만 원인(표현력)은 그대로입니다.설계 결정: 로컬을 행렬로 저장하거나(Transform 구조 변경, 씬 파일 버전 상승, 기즈모·인스펙터 전반에 영향), 비균등 스케일 부모 아래 회전된 자식을 금지/경고. 영향 범위가 커서 필요가 생길 때 다룹니다.
IBL 맵은 미리 구운 것만스카이박스에서 조도·프리필터·BRDF LUT 를 만들려면 컴퓨트 파이프라인이 필요합니다.22.6 의 4번(컴퓨트·UAV) 뒤 엔진 안 IBL 생성. 같은 가이드 3·4장.
샘플 IBL 세트가 약 2배 밝게 구워짐(씬 IBL 세기 0.5)자산 문제입니다. 세트를 다시 굽거나 세기를 다시 정해야 합니다.외부 도구(예: cmgen 계열, 또는 4번 이후 엔진 생성)로 맵을 다시 만든 뒤 모든 씬의 iblIntensity 를 1.0 기준으로 재조정하고 화면을 비교. 4번이 끝나면 엔진 생성물을 기준으로 삼는 편이 낫습니다.
스카이박스 UI 화면 확인 / 자동 검증의 사각자동 검증이 입력(클릭·드래그·단축키)을 주입하지 못합니다.입력 주입 수단: Win32 SendInput 기반 스크립트, 또는 ImGui 입력 큐에 이벤트를 넣는 자동화 모드(io.AddMousePosEvent 등)를 실행 인자 재생에 추가. 그러면 슬라이더 드래그·Ctrl+Z·드롭을 자동으로 검증할 수 있습니다(Undo 의 "확인하지 못한 것"도 함께 풀림).
