Undo · 프리팹 구현 기록

1. Undo 와 에디터 명령 큐

  • 방식. 명령 객체가 아니라 편집 상태 전체의 JSON 스냅샷 체인입니다(App/EditorHistory.h/.cpp, SceneSerializer::SaveEditState / RestoreEditState). 담는 것: 오브젝트(자식·컴포넌트·모르는 컴포넌트·ID), 재질 내용, 조명, 환경·앰비언트·클리어 색. 100단계·96MB 가 넘으면 오래된 것부터 버립니다.
  • 변경 감지. 편집 위젯마다 명령을 만들지 않고, ImGui "바쁨"(IsAnyItemActive · 마우스 누름 · 기즈모 사용)이던 프레임이 끝날 때 상태가 달라졌으면 한 단계로 기록합니다(EditorApp::TrackHistory). 슬라이더를 끌어도 한 단계입니다.
  • 명령 큐. 구조를 바꾸는 콜백(불러오기, 새 씬, 놓기, 추가, 복제, 프리팹, Undo/Redo)은 큐에 넣고 Editor::Draw 뒤 OnGUI 안(같은 프레임의 렌더 앞)에서 비웁니다. 추가·삭제·복제·드롭 같은 구조 명령은 RunCommand 가 실행 앞뒤를 기록합니다.
  • 안정 ID. GameObject::GetId()(uint64_t, Scene 의 단조 증가 카운터, 0 은 무효). 에디터 선택도 ID 로 기억해 Undo 로 목록이 다시 만들어져도 유지됩니다.
  • 복원. 오브젝트는 전부 다시 만들고 재질은 같은 인덱스에 덮어씁니다. 메시는 건드리지 않습니다(추가만 되고 줄지 않는 불변식). 씬을 통째로 바꾸는 경로(불러오기·새 씬·씬 전환·프로젝트 변경)는 기록을 비우고, 재생 정지와 스크립트 다시 올리기는 기준을 다시 잡으며(Rebase), 재생 중에는 기록을 멈춥니다.

2. Instantiate · 지연 Destroy · 프리팹

스크립트 API (Scene/Script.h)

함수동작
Instantiate(prefabPath, position)Assets 기준 경로의 .prefab 을 위치에 만들고 루트 GameObject* 반환(실패 시 nullptr)
Instantiate(const GameObject&)부분 트리 복제
Destroy(GameObject&) · DestroySelf()표시만 하고 그 프레임의 Update/FixedUpdate 끝에 지움. 표시된 오브젝트는 남은 순회에서 건너뜀. 자식도 같이 지워짐
FindById(id)안정 ID 로 찾기, 없으면 nullptr

규칙. 다른 오브젝트의 포인터를 오래 들고 있으면 대상이 지워질 때 dangling 입니다. ID 를 기억하고 쓸 때 FindById 로 다시 찾으세요. 엔진의 FollowTarget 도 그렇게 바꿨습니다. Instantiate 는 목록 끝에 추가하므로 새 컴포넌트는 순회가 거기 닿을 때 Start/Update 를 받습니다.

프리팹

  • 만들기: Hierarchy 의 Save Prefab 버튼. 쓰기: 콘텐츠 브라우저의 .prefab(아이콘·더블클릭=원점 배치·우클릭 메뉴·씬 뷰에 드롭=커서 아래 배치).
  • 같은 프리팹(경로 + 수정 시각)의 인스턴스는 메시·재질을 공유합니다(Scene::PrefabResources). 60개를 만들어도 메시 1·재질 1 이었습니다. 인스턴스 루트는 "prefab" 경로를 저장하고 Inspector 에 표시됩니다.
  • 패키징: GameBuilder 의 선택 복사 모드가 Prefabs 폴더를 항상 복사하고, 프리팹이 쓰는 모델·텍스처도 씬과 같은 함수(CollectReferences)로 모읍니다. 스크립트가 문자열 경로로 부르므로 씬이 참조하지 않기 때문입니다.
  • ABI. 이미 빌드된 스크립트 DLL 이 깨지지 않도록 GameObject 와 Scene 의 새 멤버는 모두 클래스 끝에 추가했습니다.

3. 파일 형식

  • 씬 파일 버전 5. 오브젝트에 "id"(씬 안에서 유일한 정수)와, 프리팹 인스턴스 루트에는 "prefab"(상대 경로). 둘 다 없는 옛 파일은 불러올 때 ID 를 새로 매기고 프리팹 출처는 없는 것으로 읽습니다.
  • .prefab: 씬 파일의 부분집합, 참조는 파일 안 지역 인덱스.
{ "version": 1, "type": "prefab",
  "meshes": [ … ], "materials": [ … ], "objects": [ … ] }

5. 검증

실험 프로젝트 Projects/UndoPrefabTest(Scripts/Tests/Lifetime·Spawner, 프리팹 Bullet·Sphere 1, 씬 Spawn·Tree)로 확인했습니다.

  • 추가·위치 변경 뒤 --undo/--redo 로 저장한 JSON 의 오브젝트 배열이 기대한 상태와 같음. 자식과 모르는 컴포넌트가 달린 부분 트리 삭제 뒤 Undo 도 원래와 같고, 복제의 Undo/Redo 도 같음.
  • --gesture 로 변경 감지 경로가 한 단계를 만듦. ID 는 저장·불러오기를 거쳐 유지.
  • Spawner 가 60개를 만드는 동안 메시 1·재질 1 공유, Lifetime 으로 살아 있는 수가 상한에 머문 뒤 0, 지워진 ID 의 FindById 는 nullptr.
  • 패키징: --build-game=PkgTest --build-scene=Spawn.json 으로 만든 패키지의 Assets\Prefabs 에 두 프리팹이 복사되고, 그 exe 에서 스크립트 DLL 이 로드되어 Spawner 가 프리팹을 만듦.
  • Debug 엔진 솔루션 빌드 성공. Sample·CubemapTest·QuaternionLookTest·UndoPrefabTest 의 스크립트 DLL 이 새 헤더로 빌드됨.

확인하지 못한 것. 실제 슬라이더 드래그와 Ctrl+Z 입력의 화면, Release 빌드(패키지 포함), D3D12 실행, 에디터에서 프리팹을 끌어 놓는 화면, 프리팹이 모델·텍스처를 참조하는 경우의 패키징. 프로젝트 솔루션으로 직접 빌드하면 SherlockEditor\EditorMain.cpp 에서 C1083(App/EntryPoints.h)이 나는데, 이 파일은 건드리지 않았고 엔진 솔루션 빌드는 통과합니다(원인 미조사).

6. 알려진 한계

  • 모델을 놓은 뒤 Undo 하면 오브젝트는 사라지지만 메시는 남습니다(고아 메시). 복원 뒤 자식의 표시 순서가 보존되지 않을 수 있습니다.
  • 프리팹 인스턴스끼리 재질을 공유하므로 한 인스턴스의 재질 편집이 전부에 보입니다. override·apply·revert, 중첩 프리팹, 프리팹 파일 수정의 기존 인스턴스 반영은 없습니다.
  • Hierarchy 재부모화와 텍스처 드롭은 아직 그리는 도중에 씬을 바꿉니다(큐를 거치지 않음). 변경 감지가 한 단계로 잡아 Undo 는 되지만 구조 변경의 안전은 "짝 맞추기"에 기댑니다.
  • 스냅샷이 전체라 큰 씬에서는 단계당 비용이 커서 바이트 상한을 두었습니다.
