계측 · Hierarchy 클리퍼 비포/애프터

2026-11-15 · OL_TestScene(오브젝트 7,067)에서 1번(계측 추가)과 2번(Hierarchy ListClipper) 를 적용하기 전과 후를 같은 Release 조건에서 잰 비교입니다. 렌더링 전체 분석은 OL_TestScene 렌더링 리포트 에 있습니다.

조건: 작업 트리를 Release 로 빌드(D3D11), 같은 씬·같은 카메라·같은 창(1280x720, 씬 뷰 649x251), Stats 패널 값. Before = 커밋된 HEAD 소스를 그대로 빌드(메인 패스 절두체 컬링은 이미 들어 있음), After = HEAD + 이번 변경 4파일. 두 바이너리를 번갈아 빌드해 잰 값이라 이전 리포트의 11/7 바이너리와 다릅니다. 아직 커밋하지 않았습니다.

1. 한눈에 보기

그림자 켬 78 → 112 FPS (+43%), 끔 102 → 165 FPS (+62%). 이득의 대부분은 GUI(Hierarchy) 구간에서 나왔습니다 (약 5.2~5.9ms → 2.6~3.1ms).

열 읽는 법: 두 가지 설정을 곱해서 4열입니다. 같은 씬·같은 카메라에서 아래 두 옵션만 다릅니다.

구분무엇이 다른가
Before이번 변경(1번 계측 + 2번 Hierarchy 클리퍼)을 적용하기 전 소스(커밋된 HEAD)로 빌드한 Release.
After이번 변경을 적용한 소스로 빌드한 Release.
켬그림자 켠 상태 — 방향광 castShadows = true (캐스케이드 4개, 원래 씬 그대로).
끔그림자 끈 상태 — 조명의 castShadows 만 false 로 바꾼 임시 씬 사본.

그래서 Before 켬 ↔ After 켬 과 Before 끔 ↔ After 끔 처럼 그림자 설정이 같은 열끼리 비교해야 합니다. (켬과 끔을 서로 비교하면 그림자 비용이 섞입니다.)

2. 무엇을 바꿨나

1번 — 계측 (성능 변화 없음, 보이는 정보만 늘림)

  • Renderer::Stats::drawItems 추가 (컬링 전 드로우 목록 크기).
  • Stats 탭과 Render Settings 에 draw items, culled main, culled shadow 를 따로 표시. 이전에는 그림자 컬링 수만 culled 라는 이름으로 나와, 메인 패스 컬링이 안 되는 것처럼 보였습니다.
  • Profiler 에 CPU 구간 Prepare · BuildDrawList · ShadowPass · MainPass 추가 (Renderer::Render 안).
  • 변경 파일: Renderer.h, Renderer.cpp, Editor.cpp, DebugUI.cpp.

2번 — Hierarchy ListClipper

// Editor::DrawHierarchyNode — 자식 순회부
const bool allLeaves = children.size() > 64
    && std::all_of(children.begin(), children.end(),
        [](const GameObject* c) { return c->GetChildren().empty(); });
if (allLeaves)
{
    ImGuiListClipper clipper;
    clipper.Begin(static_cast<int>(children.size()));
    while (clipper.Step())
        for (int row = clipper.DisplayStart; row < clipper.DisplayEnd; ++row)
            DrawHierarchyNode(scene, *children[row], indexOf);
}
else { /* 예전처럼 전부 그림 */ }
  • 왜 조건이 있나: 클리퍼는 모든 행의 높이가 같다고 가정합니다. 자식 중에 펼친 노드(자식이 있는 노드)가 섞이면 높이가 달라져 스크롤이 어긋나므로, 전부 잎일 때만 켭니다. 64개 이하일 때는 이득이 없어 건너뜁니다.
  • 효과 범위: OL_TestScene 처럼 한 루트(OL_Map) 아래에 7,065개가 평평하게 들어 있는 경우입니다. 중첩이 깊은 씬은 지금과 같습니다.
  • 안 바꾼 것: 포인터→인덱스 맵(indexOf)은 아직 매 프레임 7,067개를 새로 만듭니다. GUI 에 남은 2.6~3.1ms 의 일부일 가능성이 있습니다(추정, 구간을 나눠 재지 않았습니다).

5. 해석과 주의

  • 이득의 출처: GUI 구간이 평균 약 2.6ms(켬) ~ 2.8ms(끔) 줄었습니다. CPU frame 은 그보다 조금 더 줄어(켬 3.4ms, 끔 3.0ms) 표본 흔들림이 섞여 있습니다. 클리퍼 외의 원인으로 나눌 근거는 없습니다.
  • Renderer::Render 의 차이(켬 7.45 → 6.60ms)는 이번 변경이 줄이려던 대상이 아니고 표본 편차 범위로 봅니다. 계측용 CPU 구간 4개가 더해졌지만 그 비용은 측정되지 않을 만큼 작았습니다.
  • 표본이 적습니다. 조건당 2~3개, 구간 시간은 그 프레임 한 번의 값이라 ±10% 이상 흔들립니다. 방향(GUI 가 줄고 FPS 가 오름)은 모든 표본에서 일관되지만 정확한 수치는 근삿값입니다.
  • GPU frame 은 비교에 쓰지 않았습니다. 이번 변경은 GPU 작업을 바꾸지 않았고, 표본마다 2.6~5.7ms 로 편차가 큽니다 (GPU 클럭 변화일 수 있으나 확인하지 못했습니다).
  • Debug 빌드는 재지 않았습니다. Debug 에서 GUI 27ms 였던 구간이 어떻게 변하는지는 별도 측정이 필요합니다.
  • 씬 뷰가 작아(649x251) 픽셀 비용은 실사용 크기보다 낮게 나옵니다.

6. 재현 방법

  1. Release 로 솔루션 빌드 후, x64\Release 에서 SherlockEditor.exe --project=Projects\SherlockTestScenes --load=...\Scenes\OL_TestScene.json --exit-after=400 --screenshot=out.png 실행.
  2. 스크린샷의 Stats 탭(Profiler 포함) 값을 읽음. Stats 탭이 기본으로 안 보이면 imgui.ini 에서 Stats 창을 떠 있는 창으로 바꿔야 합니다.
  3. Before 는 변경 4파일(Renderer.h, Renderer.cpp, Editor.cpp, DebugUI.cpp)을 HEAD 로 되돌려 같은 방법으로 빌드·측정했습니다.
