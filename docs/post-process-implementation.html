후처리(PostProcess) 구현 기록

2026-10-23 · HDR 타깃·톤매핑 위에 가우시안 블러, 블룸, GreyScale를 올리고, 단계마다 결과를 보여 주는 Post Stages 썸네일 창까지 구현한 내용을 코드와 함께 정리한 기록입니다. 이 문서는 새로 만든 것이며 다른 문서를 고치지 않았습니다.

1. 요약

씬은 선형 FP16 HDR 텍스처에 그려지고, 그 위에서 블러 → 블룸이 HDR 값 그대로 처리됩니다. 그 결과를 톤 패스가 읽어 노출 → ACES → GreyScale(색 효과) → sRGB를 한 번에 적용합니다. 모든 효과를 끄면 이전 화면과 픽셀 단위로 같습니다.
효과어디서패스 수추가 텍스처
가우시안 블러HDR 구간 (PS_Post 모드 1)2 (가로, 세로)hdr 와 같은 크기 1장
블룸HDR 구간 (PS_Post 모드 2·3·4)밝기추출 1 + 축소 4 + 확대 4 + 합성 11/2 ~ 1/32 크기 5장
GreyScale톤 패스 안 (PS_Tonemap)0 (새 패스 없음)없음
단계별 썸네일창이 열려 있을 때만단계마다 톤 패스 1회384 폭 RGBA8 4장

프레임 흐름

ShadowPass
→ MainPass                  (m_hdrColor, 선형 FP16)
→ [HDR 구간: ApplyHdrEffects]
     BlurH  (hdr → temp)  → BlurV (temp → hdr)               ← 블러가 켜졌을 때
     BloomPrefilter (hdr → L0) → BloomDown ×4 (L0→L1→…→L4)
       → BloomUp ×4 (가산, L4→L3→…→L0) → BloomComposite (가산, L0 → hdr)   ← 블룸이 켜졌을 때
→ TonemapPass               (hdr 읽기 → 노출·ACES·GreyScale → 씬 뷰 텍스처 / 백버퍼)
→ [PreviewPass → ApplyHdrEffects → PreviewTonemapPass]   (카메라 미리보기도 같은 체인)
→ UIPass                    (Post Stages 창의 썸네일은 이 패스의 ImGui 가 읽음)

2. 설계

결정이유
순서를 엔진이 고정 (사용자는 값만 조절)블러·블룸은 선형 HDR 값에서 해야 1을 넘는 밝기가 살아 있습니다. 톤매핑 전/후를 사용자가 바꾸게 하면 결과가 깨집니다. 상용 엔진도 순서는 엔진이 정합니다.
효과의 결과는 항상 hdr 텍스처에 "제자리"로 남김마지막 패스가 hdr 에 되돌려 쓰므로 톤 패스와 그 입력 셋(m_hdrPostSet)은 효과가 몇 개 켜졌는지 모릅니다. 효과를 추가해도 톤 패스는 안 바뀝니다.
색 효과(GreyScale)는 톤 셰이더 안에 (uber)패스도 텍스처도 늘지 않습니다. 비네트·그레인·대비 같은 효과도 같은 자리에 이어 붙입니다.
설정은 씬 단위, SceneEnvironment 안에노출·톤매핑이 이미 거기 있고, 환경 직렬화를 타면 씬 JSON 저장·로드와 되돌리기 이력(EditorHistory)이 따로 작업 없이 같이 됩니다. 구조체는 독립이라 나중에 카메라 컴포넌트로 옮길 수 있습니다.
후처리 패스는 레이아웃 하나(Layout_Post)를 공유셰이더가 안 쓰는 슬롯에도 항상 유효한 뷰가 꽂혀 있어 D3D12 디스크립터 테이블이 안전합니다. 효과마다 레이아웃을 따로 만들 필요가 없습니다.
카메라 미리보기에도 같은 체인 적용스크래치를 타깃별(m_postMain, m_postPreview)로 둡니다. 블러 반경은 720p 기준 픽셀이라 작은 미리보기에서도 모양이 같습니다.

{
    // 가우시안 블러 (가로·세로 분리). 반경은 "720p 기준 픽셀"이라 출력 높이에 비례해 늘고 줆 — 씬 뷰 크기를 바꾸거나 카메라 미리보기(작은 타깃)에서도 모양이 같음.

    float blurRadius = 4.0f;

    // 블룸: 밝기가 threshold 를 넘는 부분을 뽑아(knee 로 부드럽게) 축소 체인으로 흐린 뒤 intensity 만큼 더함.

    float bloomThreshold = 1.0f;

    float greyscale = 0.0f;

    bool AnyHdrEffect() const { return blurEnabled || bloomEnabled; }
};

4. 상수버퍼와 바인딩

슬롯 (ShaderConstants.h)

constexpr uint32_t kSRVSlotSceneHdr = 13;    // t13 (후처리 셋, 후처리 패스의 입력 텍스처. 톤 패스는 HDR 씬, 블러·블룸은 앞 단계의 결과)
constexpr uint32_t kCBSlotPostParams = 4;    // b4 (후처리 셋, 패스마다 올림)
constexpr uint32_t kSamplerSlotPost = 6;     // s6 (후처리 셋, 선형 Clamp. 블룸 축소·확대와 썸네일이 씀. 후처리 패스는 프레임 셋을 바인딩하지 않으므로 s4~s7 과 겹치지 않음)

RHI 한도: 상수버퍼 레지스터 < 8, 샘플러 레지스터 < 8 (kMaxCbvRegister, kMaxSamplerRegister). 그래서 샘플러는 s8 이 아니라 s6 입니다. 후처리 패스는 프레임 셋(s4~s7 구간)을 바인딩하지 않으므로 겹치지 않습니다.

PostParams — C++ 구조체

// 2026/10/23: 후처리 패스 파라미터 (b4). 패스마다 올림 — 업로드 링을 쓰므로 프레임 안에서 여러 번 올려도 됨 (b0 가 미리보기에서 그렇게 함).
// 톤 패스도 매 프레임 올리므로 효과가 전부 꺼져 있어도 D3D12 의 "이번 프레임에 갱신되지 않은 Dynamic CB" 경고가 나지 않음.
struct alignas(16) PostParamsConstants
{
    // x = 모드 (PS_Post: 1 블러, 2 블룸 밝기 추출+축소, 3 축소, 4 확대), y,z = 블러 방향 (텍셀 단위, 가로 (1,0) / 세로 (0,1)), w = 미사용
    DirectX::XMFLOAT4 pass;

    DirectX::XMFLOAT4 blur;

    DirectX::XMFLOAT4 bloom;

    DirectX::XMFLOAT4 view;
    // x = GreyScale 양 (0..1), y = 1 이면 색 효과를 건너뜀 (단계별 썸네일의 "효과 전" 그림), zw = 미사용
    DirectX::XMFLOAT4 grade;

5. 공통 후처리 패스 함수 (Renderer.cpp)

톤매핑·블러·블룸이 모두 이 함수 하나를 거칩니다. 출력의 상태 전이(before → RenderTarget → after), 패스 시작·끝, Draw(3) (정점 버퍼 없는 풀스크린 삼각형), 통계 카운터까지 합니다. 호출하는 쪽이 UploadPostParams 로 b4 를 먼저 올립니다.

ResourceSetHandle Renderer::CreatePostSet(TextureHandle input, const char* debugName)
{
    // 슬롯 순서는 Initialize 의 postLayout.Add(...) 순서: b0 PerFrame, b4 PostParams, t13 입력, s6 선형 Clamp.
    const ResourceSetDesc desc{
        .layout = m_postLayout,
        .bindings = { { .buffer = m_perFrameCB }, { .buffer = m_postParamsCB }, { .texture = input }, { .sampler = GetSampler(SamplerPreset::LinearClamp) } },
        .debugName = debugName,
    };
    return m_device->CreateResourceSet(desc);
}

void Renderer::UploadPostParams(const PostParamsConstants& params)
{
    m_device->UpdateBuffer(m_postParamsCB, &params, sizeof(params));
}

void Renderer::RenderPostPass(RHI::CommandList& cmd, const PostPassDesc& desc)
{
    if (!desc.pipeline.IsValid() || !desc.input.IsValid() || !desc.output.IsValid()) return;

    // 출력: (에디터) 씬 뷰 텍스처 Common/ShaderResource → RenderTarget, (게임) 백버퍼 Present → RenderTarget.
    // D3D12 스왑체인 관례. D3D11 에서는 상태 추적만 함.
    cmd.Barrier(desc.output, desc.outputBefore, ResourceState::RenderTarget);

    // 전체 화면을 다 덮어쓰면 Load 도 Clear 도 필요 없음 (DontCare). 덧그리는 패스(블룸 합성)는 Load.
    // sRGB 뷰는 선형 → sRGB 인코딩을 함 (톤 패스만 씀. F5 로 끄면 UNORM 뷰).
    const RenderPassDesc pass{
        .colors = { { .texture = desc.output, .load = desc.load, .srgbView = desc.srgbView } },
        .colorCount = 1,
        .debugName = desc.debugName,
    };
    cmd.BeginRenderPass(pass);
    cmd.SetPipelineState(desc.pipeline);
    cmd.SetResourceSet(desc.input);   // b0 (PerFrame) + b4 (PostParams) + t13 (입력) + s6
    cmd.Draw(3, 0);                   // 정점 버퍼 없음 — ScreenVS 가 SV_VertexID 로 삼각형 하나를 만듦
    ++m_stats.pipelineSwitches;
    ++m_stats.draws;
    m_stats.triangles += 1;
    cmd.EndRenderPass();

    if (m_device == nullptr || width == 0 || height == 0) return false;
    if (scratch.width != width || scratch.height != height) DestroyPostScratch(scratch);   // hdr 크기가 바뀌었으면 전부 다시

    // 후처리 텍스처는 전부 FP16 — 1 을 넘는 밝기를 잘라내지 않도록 hdr 와 같은 포맷.
    auto create = [this](uint32_t w, uint32_t h, const char* name, TextureHandle& texture, ResourceSetHandle& set)
    {
        const TextureDesc desc{
            .width = w,
            .height = h,
            .format = Format::R16G16B16A16_FLOAT,
            .mipLevels = 1,
            .bindFlags = TextureBind_RenderTarget | TextureBind_ShaderResource,
            .debugName = name,
        };
        texture = m_device->CreateTexture(desc);
        if (texture.IsValid()) set = CreatePostSet(texture, name);
        return texture.IsValid() && set.IsValid();
    };

    if (needBlur && !scratch.temp.IsValid())
    {
        if (!create(width, height, "PostTemp", scratch.temp, scratch.tempSet))
        {
            Log::Error("후처리 스크래치 텍스처 생성 실패 (%ux%u).", width, height);
            DestroyPostScratch(scratch);
            return false;
        }
        scratch.tempState = ResourceState::Common;
        Log::Info("후처리 스크래치(블러) %ux%u (R16G16B16A16_FLOAT)", width, height);
    }
    if (needBloom && scratch.bloomCount == 0)
    {
        // 레벨 i = hdr 의 1/2^(i+1). 변이 4 미만이 되면 거기서 멈춤 (너무 작은 레벨은 의미가 없음).
        uint32_t w = width, h = height;
        for (uint32_t i = 0; i < PostScratch::kBloomLevels; ++i)
        {
            w = (std::max)(1u, (w + 1) / 2);
            h = (std::max)(1u, (h + 1) / 2);
            PostScratch::BloomLevel& level = scratch.bloom[i];
            if (!create(w, h, "PostBloom", level.texture, level.set))
            {
                Log::Error("후처리 스크래치 텍스처 생성 실패 (블룸 레벨 %u, %ux%u).", i, w, h);
                DestroyPostScratch(scratch);
                return false;
            }
            level.state = ResourceState::Common;
            level.width = w;
            level.height = h;
            scratch.bloomCount = i + 1;
            if (w < 4 || h < 4) break;
        }
        Log::Info("후처리 스크래치(블룸) 레벨 %u개, 가장 큰 쪽 %ux%u", scratch.bloomCount, scratch.bloom[0].width, scratch.bloom[0].height);
    }
    scratch.width = width;
    scratch.height = height;
    return true;
}
void Renderer::DestroyPostScratch(PostScratch& scratch)
{
    if (m_device != nullptr)
    {
        // D3D12 는 지연 해제라 이미 기록된 명령이 읽어도 안전함.
        if (scratch.tempSet.IsValid()) m_device->DestroyResourceSet(scratch.tempSet);
        if (scratch.temp.IsValid()) m_device->DestroyTexture(scratch.temp);
        for (PostScratch::BloomLevel& level : scratch.bloom)
        {
            if (level.set.IsValid()) m_device->DestroyResourceSet(level.set);
            if (level.texture.IsValid()) m_device->DestroyTexture(level.texture);
        }
    }
    scratch = PostScratch{};
}

void Renderer::ApplyHdrEffects(RHI::CommandList& cmd, PostScratch& scratch, TextureHandle hdr, ResourceState& hdrState, ResourceSetHandle hdrSet,

{
    const PostProcessSettings& post = m_postSettings;

    {

    }
    if (capture) CapturePostStage(cmd, 0, "Scene", hdrSet, width, height, true);

11. 단계별 썸네일 (Post Stages 창)

환경 패널의 "Stage thumbnails" 체크로 켜는 창입니다. Scene → Blur → Bloom → Final 의 HDR 결과를 톤매핑해 본 모습으로 나란히 보여 줍니다. Scene/Blur/Bloom 은 색 효과를 건너뛴 그림이고(그 효과가 한 일만 보이게), Final 만 색 효과까지 포함합니다. 꺼진 효과 칸은 "off" 로 표시합니다.

void Renderer::EnsureStageThumbs(uint32_t hdrWidth, uint32_t hdrHeight)
{
    if (m_device == nullptr || hdrWidth == 0 || hdrHeight == 0) return;
    // 폭 384 (HDR 가 더 좁으면 그 폭), 높이는 같은 종횡비. 종횡비가 바뀌면(씬 뷰 리사이즈) 다시 만듦.
    const uint32_t width = (std::min)(384u, hdrWidth);
    const uint32_t height = (std::max)(1u, static_cast<uint32_t>(static_cast<uint64_t>(width) * hdrHeight / hdrWidth));
    if (width == m_thumbWidth && height == m_thumbHeight && m_stageThumbs[0].texture.IsValid()) return;

    DestroyStageThumbs();
    static const char* const kNames[kPostStageCount] = { "Scene", "Blur", "Bloom", "Final" };
    for (uint32_t i = 0; i < kPostStageCount; ++i)
    {
        const TextureDesc desc{
            .width = width,
            .height = height,
            .format = Format::R8G8B8A8_UNORM,   // 씬 뷰와 같은 TYPELESS 규칙 (sRGB RTV + UNORM SRV 로 ImGui 가 읽음)
            .mipLevels = 1,
            .bindFlags = TextureBind_RenderTarget | TextureBind_ShaderResource,
            .debugName = "PostStageThumb",
        };
        m_stageThumbs[i].texture = m_device->CreateTexture(desc);
        m_stageThumbs[i].name = kNames[i];
        m_stageThumbStates[i] = ResourceState::Common;
        if (!m_stageThumbs[i].texture.IsValid())
        {
            Log::Error("후처리 단계 썸네일 생성 실패 (%ux%u).", width, height);
            DestroyStageThumbs();
            return;
        }
    }
    m_thumbWidth = width;
    m_thumbHeight = height;
    Log::Info("후처리 단계 썸네일 %ux%u x %u", width, height, kPostStageCount);
}

void Renderer::DestroyStageThumbs()
{
    for (uint32_t i = 0; i < kPostStageCount; ++i)
    {
        if (m_device != nullptr && m_stageThumbs[i].texture.IsValid()) m_device->DestroyTexture(m_stageThumbs[i].texture);   // D3D12 는 지연 해제 (ImGui 가 읽을 수 있음)
        m_stageThumbs[i] = PostStageThumb{};
        m_stageThumbStates[i] = ResourceState::Common;
    }
    m_thumbWidth = m_thumbHeight = 0;
}

void Renderer::CapturePostStage(RHI::CommandList& cmd, uint32_t stage, const char* name, ResourceSetHandle hdrSet,
    uint32_t hdrWidth, uint32_t hdrHeight, bool skipGrade)
{
    PostStageThumb& thumb = m_stageThumbs[stage];
    if (!thumb.texture.IsValid() || m_thumbWidth == 0) return;
    // 지금까지의 HDR 결과를 노출·ACES 로 톤매핑해 작은 텍스처에 그림 (톤 패스의 셰이더가 입력/출력 크기 비로 읽음 = 최근접 축소).
    // 단계 0~2 는 색 효과를 건너뜀 — "이 효과가 한 일"만 보이게. 마지막 Final 만 색 효과까지 포함.
    RenderTonemapPass(cmd, hdrSet, thumb.texture, m_stageThumbStates[stage], ResourceState::ShaderResource, name,
        hdrWidth, hdrHeight, m_thumbWidth, m_thumbHeight, skipGrade);
    m_stageThumbStates[stage] = ResourceState::ShaderResource;
    thumb.active = true;
}

항목내용
UpdateBuffer 를 한 프레임에 여러 번D3D12 는 UpdateBuffer 가 호출마다 업로드 링에서 새 조각을 할당하고, 바인딩은 draw 시점(ApplyBindings)에 최신 조각을 가리킵니다. 그래서 패스마다 b4 를 올려도 앞 패스가 덮이지 않습니다 (b0 가 미리보기에서 이미 이렇게 쓰임). 패스마다 CB 를 따로 둘 필요가 없었습니다.
같은 텍스처를 읽고 쓰지 않음블러는 hdr → temp → hdr 로 핑퐁하고, 블룸 합성은 L0 을 읽어 hdr 에 가산합니다. D3D11 은 BeginRenderPass 가 렌더 타깃과 같은 텍스처의 SRV 슬롯을 자동으로 푸는데, 이에 기대지 않고 입력과 출력이 항상 다르게 했습니다.
std::min/max 와 Windows 매크로pch.h 가 windows.h 를 끌어와서 std::min(a, b) 가 컴파일 오류(C2589)가 납니다. 이 프로젝트 관례대로 (std::min)(a, b) 로 감쌌습니다.
에디터·게임 exe 와 DLLSherlockEditor/SherlockGame 프로젝트를 단독으로 msbuild x.vcxproj 하면 App/EntryPoints.h 를 못 찾아 실패합니다. 솔루션(SherlockEngine.sln)으로 빌드해야 합니다.
블러 반경 단위720p 기준 픽셀. 씬 뷰가 커지거나 작아져도, 작은 카메라 미리보기에서도 같은 비율의 흐림이 됩니다. 기준 높이는 RendererPost.cpp 의 kReferenceHeight.
블룸의 밝기 판정채널 최댓값 기준입니다. 노출·ACES 전의 선형 HDR 값에 대한 임계값이라, 장면이 어두우면(노출이 낮으면) 같은 임계값에서도 번지는 양이 달라집니다.

14. 효과를 추가하는 법

종류할 일
색만 바꾸는 효과 (비네트, 그레인, 대비, 채도 …)① PostProcessSettings 에 필드 ② 직렬화 두 곳 ③ UI 한 줄 ④ PostParamsConstants 의 빈 칸(grade.zw, pass.w 등)이나 새 float4 에 값을 실음 (크기를 바꾸면 HLSL cbuffer 와 static_assert 도 같이) ⑤ TonemapPixelShader.hlsl 의 색 효과 구간에 이어 붙임. 패스·텍스처는 늘지 않습니다.
HDR 구간 효과 (DoF, SSAO, 안개 …)① 설정·직렬화·UI ② PostPixelShader.hlsl 에 모드 추가 ③ ApplyHdrEffects 에 블록 하나 추가: EnsurePostScratch 에 필요한 텍스처를 더하고, 마지막 패스가 hdr 에 되돌려 쓰게 하면 톤 패스는 안 바뀝니다. 썸네일 단계가 필요하면 kPostStageCount 와 이름 배열을 늘립니다.
톤매핑 뒤 효과 (FXAA 등)톤 패스 출력이 지금은 최종 출력(씬 뷰 텍스처·백버퍼의 sRGB 뷰)에 바로 쓰입니다. LDR 입력이 필요하므로 톤 패스 출력을 LDR 중간 텍스처로 돌리는 구조 변경이 먼저 필요합니다. 아직 만들지 않았습니다.
