1. 현재 코드 상태

  • SherlockEngine/Graphics/Model.cpp에 cgltf 기반 glTF 로더가 이미 있습니다(vcpkg.json에도 cgltf 등록).
  • 스킨, 본, 스켈레톤, 애니메이션 클립 코드는 없습니다. 그래서 시작점은 "glTF의 skin과 animation 데이터를 읽는 것"입니다.
  • 스킨 메시는 정점 속성이 늘어납니다(joint 인덱스, weight). 그러면 input layout과 PSO 변형이 따로 필요합니다. 최종 목표인 RHI/PSO 공부와 바로 이어지는 부분입니다.

앞 단계가 뒤 단계의 전제입니다. 0~3단계가 기반이고, 4~5단계가 "캐릭터가 움직이는 시스템"의 뼈대, 6~8단계가 품질과 상호작용을 올리는 부분입니다.

3. 단계별 설명

0. 수학

스키닝 버그의 대부분은 변환 순서와 좌표계에서 나옵니다. 쿼터니언 곱의 순서, slerp가 최단 경로를 고르는 이유(q와 -q), 행렬 곱 순서(D3D의 행 벡터 관례 포함)를 먼저 손에 익힙니다. 스켈레톤은 local 변환을 부모 순서로 누적해 model 공간 행렬을 얻고, 거기에 inverse bind matrix를 곱해 "바인드 포즈 대비 변화량"을 만듭니다.

1. 에셋 파이프라인

glTF의 skin은 joint 노드 목록과 inverse bind matrices 접근자를 가집니다. 런타임에서는 노드 그래프 대신 joint 배열 + 부모 인덱스(부모가 항상 자식보다 앞)로 평탄화하면 포즈 계산이 단순한 한 번의 루프가 됩니다. 나중에 오프라인 변환 단계를 두면 로딩이 빨라집니다.

2. 클립 샘플링

glTF 애니메이션은 채널(노드 + 경로: translation/rotation/scale) 단위이고 보간은 STEP, LINEAR, CUBICSPLINE입니다. 회전은 쿼터니언 slerp, CUBICSPLINE은 접선 데이터가 따로 붙는 점에 주의합니다. 루프 경계의 보간과 시간 정규화가 첫 번째 함정입니다.

3. 스키닝

정점마다 최대 4개의 joint와 weight를 가지고 Σ wᵢ · (palette[jᵢ] · v)로 계산합니다. CPU로 먼저 구현해 결과를 확인하고, 버텍스 셰이더로 옮기고, 마지막에 컴퓨트로 옮기는 순서가 디버깅에 유리합니다. LBS는 관절이 비틀릴 때 부피가 줄어드는 "캔디 래퍼" 문제가 있고, Dual Quaternion Skinning이 이를 줄이는 대신 부피가 늘어나는 팽창 같은 다른 아티팩트가 생깁니다.

4. 블렌딩

두 포즈를 joint별로 섞습니다(위치·스케일은 lerp, 회전은 nlerp/slerp). additive는 기준 포즈 대비 차이만 더합니다. 레이어와 마스크는 상체/하체를 따로 재생할 때 씁니다.

5. 애니메이션 그래프

상태 머신 + 전이 조건 + 블렌드 노드로 구성합니다. 루트 모션(애니메이션이 캐릭터의 이동을 구동)과 코드 주도 이동 중 무엇이 위치를 결정하는지가 설계의 핵심 결정입니다(7장의 Holden 글 참고).

6. IK

2본 해석적 IK(다리, 팔)는 코사인 법칙으로 풀립니다. 체인이 길면 CCD나 FABRIK 같은 반복 방식을 씁니다. 발 접지는 지면 레이캐스트 + 2본 IK + 골반 높이 보정의 조합입니다.

7. 물리

캐릭터 컨트롤러는 보통 킨매틱 캡슐이고, 래그돌은 본마다 강체와 관절을 붙인 것입니다. 파워드 래그돌은 애니메이션 포즈를 목표로 관절 모터를 구동합니다. 직접 구현보다는 Jolt 같은 라이브러리를 참고 구현으로 쓰는 편이 효율적입니다.

8. 심화

모션 매칭은 모션 데이터베이스에서 현재 상태와 가장 가까운 프레임을 찾아 이어 붙이는 방식입니다. 압축(ACL), 리타게팅, 프로시저럴 애니메이션은 필요가 생길 때 하나씩 봅니다.

4. 우리 엔진 로드맵과 연결할 지점

  • CPU 스키닝은 언제든 시작할 수 있습니다.
  • GPU 컴퓨트 스키닝은 컴퓨트(RHI 확장) 단계 이후에 맞습니다. 순서는 CSM → CPU 라이트 컬링 → 디퍼드 → SSAO → 컴퓨트 → 클러스터드 입니다.
  • 스킨 메시를 넣을 때 통합해야 할 곳:
    • 애니메이션에 따라 갱신되는 바운딩 볼륨(CPU 라이트 컬링이 쓰는 값)
    • CSM 그림자 패스의 스킨 경로(그림자도 같은 포즈로 그려야 함)
    • 모션 벡터용 이전 프레임 본 행렬
    • 업데이트 순서 고정: 애니메이션 → 물리 → 렌더
    • 스킨용 input layout / PSO 변형

9. 추천 진행

  1. 0~3단계를 먼저 진행합니다. glTF 스킨 로딩, CPU 스키닝, 버텍스 셰이더 스키닝 순입니다. 이 구간에서 PSO 변형 구조를 결정하게 됩니다.
  2. 4~5단계로 블렌딩과 상태 머신을 붙입니다.
  3. 6단계에서 발 IK 하나를 만들어 봅니다.
  4. 컴퓨트 단계에 들어가면 GPU 스키닝으로 옮깁니다.
  5. 7~8단계는 필요가 생길 때 고릅니다.
첫 목표 제안. glTF 스킨 모델 하나(예: Khronos 샘플의 SimpleSkin이나 CesiumMan)를 불러와 CPU 스키닝으로 클립 하나를 재생하는 것.
