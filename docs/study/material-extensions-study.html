1. 왜 확장이 필요한가, 그리고 한눈에 보는 지도

1-1. metallic-roughness만으로는 모자란 재질

glTF의 기본 재질은 기본색·금속성·거칠기·노멀·AO·발광입니다. 비금속은 반사율 F0가 항상 0.04(굴절률 1.5)로 고정되고, 반사층은 하나뿐이며, 빛이 물체를 뚫고 지나가는 경우를 표현하지 못합니다. 그래서 다음 재질이 기본 PBR로는 틀리게 나옵니다.

  • 천이나 고무처럼 반사가 거의 없는 비금속, 보석처럼 반사가 센 비금속 — F0가 0.04가 아님
  • 자동차 도장, 니스 칠한 나무 — 거친 바탕 위에 매끈한 코팅이 한 겹 더 있음
  • 유리, 투명 플라스틱 — 뒤가 비침
  • 네온 간판, 화면처럼 밝게 빛나는 면 — 발광 계수가 0~1에 묶이면 HDR 밝기를 못 냄

glTF는 이런 것을 KHR_materials_* 확장으로 덧붙입니다. 우리 테스트 모델 14개 중 확장을 쓰는 것은 3개입니다. AlfaRomeo_1933은 clearcoat·transmission, USN-Hornet은 specular·ior, DarkDragon(BlackDragon_Ani_v2.gltf)은 specular를 씁니다. 세 파일의 extensionsUsed에서 확인했고, 나머지 모델에는 확장이 없습니다. KHR_materials_emissive_strength를 쓰는 모델은 없습니다.

1-2. 확장 → 엔진 필드 지도

2. 반사 세기와 색 — ior·specular, F0와 F90

2-1. 무엇을 바꾸는가

Schlick 프레넬은 수직으로 볼 때의 반사율 F0에서 스치는 각도의 반사율 F90까지 (1 − cosθ)⁵로 올라가는 곡선입니다. 기본 PBR은 F90을 항상 1로 둡니다. 두 확장은 비금속의 이 곡선을 이렇게 바꿉니다.

  • ior: F0의 바탕값 ((ior − 1) / (ior + 1))². 물 1.33 → 0.020, 기본 1.5 → 0.040, 2.4(다이아몬드) → 0.170 계산값
  • specularColor: F0에 색을 곱함 (비금속 반사에 색이 끼는 표현)
  • specularFactor: F0와 F90 둘 다에 곱하는 세기. 0이면 비금속 반사가 모든 각도에서 사라짐

금속은 이 값들을 쓰지 않습니다(F0 = 기본색, F90 = 1). 확장의 기본값(ior 1.5, factor 1, 흰색)이면 F0 = 0.04, F90 = 1이라 확장 전과 같은 식이 됩니다.

// Shaders/MaterialSurface.hlsli — EvaluateMaterialSurface
specularWeight = saturate(specularFactor * specularTexture.a)
specularTint   = specularColor * specularColorTexture.rgb
dielectricF0   = min(((ior-1)/(ior+1))² * specularTint, 1) * specularWeight
F0  = lerp(dielectricF0,  albedo, metallic)
F90 = lerp(specularWeight, 1,     metallic)

코드 주석은 three.js와 같은 식이라고 적고 있습니다. F90은 SurfaceData::F90에 담겨 세 곳에서 쓰입니다. 직접광의 FresnelSchlick(F0, F90, VdotH), 환경광의 FresnelSchlickRoughness(최대값을 (1 − roughness) · F90으로 누름), split-sum 반사항 F0 · A + F90 · B(Shading.hlsli의 EnvironmentLighting)입니다. 확산 쪽은 kd = (1 − F)(1 − metallic)이라 반사가 줄어든 만큼 확산이 늘어납니다.

2-2. Blender의 ior 1000

USN-Hornet의 재질 84개 중 83개가 ior: 1000이고 82개가 specularColorFactor: 0.05입니다(glTF 파일에서 확인). 기록 문서에 따르면 Blender가 Principled BSDF의 Specular를 이렇게 내보냅니다. ior만 읽으면 F0 = (999/1001)² ≈ 0.996으로 비금속이 거울이 되고, 색까지 곱하면 0.996 × 0.05 ≈ 0.050으로 기본 0.04에 가까운 값이 됩니다 계산값. 그래서 임포터는 두 확장을 같은 extensions 객체에서 함께 읽습니다. 이 사정은 GltfImporter.cpp와 Material.h 주석, 구현 기록 1장에 적혀 있습니다.

3. 클리어코트 — 두 번째 반사 로브

3-1. 층 구조와 에너지 나눔

클리어코트는 기본 층 위에 얇은 투명 유전체 막이 한 겹 있다고 보는 모델입니다. 막은 굴절률 1.5로 고정이라 F0 = 0.04이고, 자기 거칠기와 자기 노멀을 가집니다. 빛은 먼저 막에서 일부(Fc)가 반사되고, 나머지가 기본 층에 닿아 평소처럼 반응한 뒤 다시 막을 지나 나옵니다. 우리 셰이더는 이를 "막이 반사한 만큼 기본 층을 줄인다"는 한 줄로 근사합니다.

코팅 세기 1일 때 기본 층이 남는 비율 1 − Fc는 0°에서 0.96, 60°에서 0.93, 80°에서 0.59, 85°에서 0.35입니다 계산값. 정면에서는 코팅이 바탕을 거의 가리지 않고, 비스듬히 볼수록 코팅의 반사가 바탕을 덮습니다. 자동차 차체의 가장자리가 하늘을 비추는 거울처럼 보이는 것이 이 효과입니다.

3-2. 직접광: ShadeLight

Shading.hlsli의 ShadeLight는 기본 층 항(baseTerm)을 평소처럼 계산한 뒤, s.clearcoat > 0이면 코팅 노멀로 GGX 로브 하나를 더 계산합니다. 하프벡터는 노멀과 무관해서 기본 층의 것을 그대로 쓰고, NdotLcc·NdotVcc·NdotHcc만 코팅 노멀로 다시 구합니다. 코팅의 프레넬은 clearcoat · (0.04 + 0.96 · (1 − VdotH)⁵)이고, 결과는 baseTerm · (1 − coatFresnel) + coatTerm입니다. 빛 판정도 둘 중 하나라도 빛을 받으면(NdotL > 0 || NdotLcc > 0) 계산하도록 넓혀 두었습니다. 코팅 노멀과 셰이딩 노멀이 다르면 한쪽만 빛을 받는 픽셀이 있기 때문입니다.

3-3. 환경광: EnvironmentClearcoat

코팅의 IBL은 기본 층과 같은 split-sum을 한 번 더 합니다. EnvironmentClearcoat가 코팅 노멀의 반사 방향으로 프리필터 큐브를 코팅 거칠기 밉에서 읽고, BRDF LUT 항을 F0 0.04, F90 1로 곱합니다(prefiltered · (0.04 · A + B)). 같이 돌려주는 fresnel은 N·V로 구한 값이고, ShadeEnvironment가 environment · (1 − c · fresnel) + c · coatSpecular로 합칩니다. 추가 비용은 프리필터 큐브 샘플 한 번과 BRDF LUT 샘플(또는 EnvBRDFApprox) 한 번입니다. split-sum 자체는 IBL 문서에 있습니다.

3-4. 코팅 노멀과 텍스처

  • 코팅은 기본 층의 노멀 맵을 따르지 않습니다. 코팅 노멀 맵(t18)이 없으면 평평한 노멀 텍스처가 꽂혀 결과가 기하 노멀과 같아집니다. 주석에 glTF 규칙이라고 적혀 있습니다. 거친 바탕 위의 매끈한 막이라는 모델과 맞는 선택입니다.
  • 세 텍스처(t16 세기 R, t17 거칠기 G, t18 노멀)는 분기 밖에서 항상 샘플합니다. 분기 안의 Sample은 그래디언트(밉 선택)가 불균일한 흐름에서 정의되지 않기 때문이라고 주석이 설명합니다.
  • 코팅 거칠기는 기본 층과 같이 0.03 아래로 내려가지 않게 자릅니다. clearcoatRoughness의 기본값은 0이라 실제로는 0.03이 됩니다.
발광과 코팅. 포워드(ShadeForward)는 발광을 ShadeEnvironment 결과 뒤에 더하고, 디퍼드는 G-buffer 패스가 발광을 view.hdr에 먼저 씁니다. 어느 쪽이든 코팅이 발광을 줄이지 않습니다. KHR_materials_clearcoat 규격의 Emission 항목은 "코팅 층은 발광 위에 있다"고 보고 coated_emission = emission · (1 − clearcoat · clearcoat_fresnel)로 어둡게 하므로, 발광하는 코팅 재질에서는 규격보다 정면은 약 4%, 가장자리는 그보다 많이 밝게 나옵니다. 지금 테스트 모델에 발광하는 코팅 재질은 없습니다.

4. 투과와 블렌딩 패스

4-1. 규격의 투과와 우리 근사

KHR_materials_transmission은 빛이 표면을 지나 뒤로 빠져나가는 비율입니다. 제대로 하려면 불투명 장면을 먼저 그린 색 텍스처를 굴절 방향으로, 거칠기만큼 흐리게 읽어야 합니다. 우리 엔진은 이것을 알파 블렌딩으로 근사합니다(Material.h 주석과 구현 기록 5장). 기록에 남은 이유는 장면 색의 밉 사본이 필요한데 RHI에 텍스처 복사·밉 생성 명령이 없었다는 것입니다.

4-2. 불투명도 식

BasicPixelShader.hlsl의 ShadeForward는 블렌딩 재질(blended > 0.5)이면 rgb에 기본색 알파를 미리 곱해 내보내고, 알파는 투과와 시선 프레넬로 따로 정합니다.

fresnelView = FresnelSchlick(F0, F90, N·V).g
opacity     = saturate(alpha · (1 − transmission · (1 − fresnelView)))
output      = float4(finalColor · alpha, opacity)     // 블렌드: One, InvSrcAlpha

투과 1, 알파 1인 유리는 화면 = 반사광 + 배경 × (1 − Fv)가 됩니다. 정면 Fv = 0.04라 배경이 96% 비치고, N·V = 0.2(약 78°)에서는 Fv ≈ 0.35, 0.05에서는 0.78이라 가장자리로 갈수록 거울처럼 됩니다 계산값.

rgb에는 opacity 대신 기본색 알파를 곱합니다. 금속성 0인 투과 재질(예: F_Transmission)의 기본색 알파를 0.25로 내리면, 불투명도는 정면 0.25 × 0.04 = 0.01이고 반사광도 0.25배로 줄어듭니다 계산값. 유리가 거의 보이지 않는 쪽으로 기우는 조합입니다.

AlfaRomeo_1933의 투과 재질 두 개(…_diff_6_2, …_diff_6_3)는 alphaMode: BLEND에 기본색 알파 0.25, transmission 1이지만 glTF에 metallicFactor가 없습니다. GltfImporter.cpp의 ConvertMaterial은 규격 기본값대로 JsonFloat(*pbr, "metallicFactor", 1.0f)를 읽으므로 금속성이 1이 되고, MaterialSurface.hlsli의 transmission · (1 − metallic)이 0이 됩니다. 투과 1이지만 금속성이 기본값 1로 읽혀 실제 투과는 0이 되고, 불투명도 0.25의 일반 블렌딩(금속 반사)으로 그려집니다. 반사광 0.25배이며, F0는 기본색 그대로이고 확산은 없습니다 계산값.

4-3. 블렌딩 패스

  • IsBlended(material) = alphaBlend || transmissionFactor > 0. glTF가 OPAQUE라도 투과가 있으면 블렌딩 패스로 갑니다.
  • PSO(Renderer::GetPipelineFor, 키 비트 11): 블렌드 One / InvSrcAlpha, 깊이는 테스트만 하고 쓰지 않음, RT 1(속도)의 쓰기 마스크 0. 반투명은 속도를 남기지 않아 뒤 표면의 속도가 쓰입니다(TAA 문서와 관련).
  • 순서(Renderer::DrawItems): 불투명 → 하늘 → 블렌딩 항목을 오브젝트 경계 구 중심이 카메라에서 먼 것부터. 한 오브젝트 안의 삼각형끼리는 정렬하지 않습니다.
  • BuildDrawList가 블렌딩 재질에는 그림자 PSO를 만들지 않습니다(빈 핸들). 그림자 맵은 차폐 여부만 담아서 반투명 물체가 통째로 그림자를 드리우게 되기 때문입니다.

6. 디퍼드에서 어디로 가는가

6-1. CanUseDeferred

디퍼드 프레임에서 재질이 G-buffer 패스로 갈지 포워드 패스에 남을지는 Graphics/RendererDeferred.cpp의 Renderer::CanUseDeferred가 정합니다. 규칙과 이유는 디퍼드·G-buffer 문서 8장에 있으므로, 여기서는 재질 확장 기준으로 순서만 그림으로 둡니다.

6-2. GB3: 금속성·F90·코팅·코팅 거칠기

GB3의 네 칸 중 셋(F90, 코팅, 코팅 거칠기)이 확장의 값입니다. 재질 확장 기록도 디퍼드를 만들기 전에 "clearcoat 는 G-buffer 채널이 더 필요"하다고 적어 두었습니다(기록 5장). PS_GBuffer(Shaders/GBufferPixelShader.hlsl)는 SurfaceData를 포워드와 같은 EvaluateMaterialSurface로 만든 뒤 이렇게 나눠 씁니다.

타깃포맷내용확장과의 관계
GB2R8G8B8A8_UNORM_SRGBrgb 유효 F0, a 거칠기ior·specular·specularColor가 다 섞인 결과 F0만 저장
GB3R8G8B8A8_UNORMr 금속성, g F90, b 클리어코트, a 코팅 거칠기F90과 코팅 둘이 여기 들어감
GB1R16G16B16A16_FLOAT셰이딩 노멀·기하 노멀 (옥타헤드럴 둘)코팅 노멀 칸이 없어서 LoadGBufferSurface가 코팅 노멀 = 기하 노멀로 되살림

F0는 rgb 셋이 필요하지만 F90은 스칼라라서 한 칸이면 됩니다. ior·specular 확장은 F0 rgb와 F90 하나로 완전히 줄어들기 때문에 원래 계수를 G-buffer에 넣을 필요가 없습니다. 투과는 LoadGBufferSurface에서 0으로, 발광은 0으로(이미 view.hdr에 있음) 채웁니다.

8비트 양자화의 크기 계산값: GB2는 sRGB라 F0 0.04가 코드 56(되읽으면 0.0395, 한 단계 0.0014)으로 저장됩니다. UNORM이었다면 코드 10(0.0392), 한 단계 0.0039라 sRGB 쪽이 작은 F0를 약 세 배 촘촘하게 담습니다. GB3의 F90과 코팅 값은 1/255 단계입니다. 코팅 거칠기 0.04(알파 로메오 차체)는 10/255 = 0.0392로 저장되고, LoadGBufferSurface가 max(…, 0.03)으로 재질 쪽과 같은 하한을 다시 걸어 둡니다. 디퍼드와 포워드의 화면 비교는 8장 E3에 있습니다. 디퍼드 전체 구조는 디퍼드·G-buffer 문서를 보세요.

8. 실험

E1. Hornet의 유효 F0 예상

USN-Hornet을 놓고 디버그 뷰 9(Specular F0)를 켭니다. 비금속 부품의 F0는 0.0498이라, 디버그 색이 sRGB 타깃에서 인코딩되어 화면 값 약 63이 나와야 합니다. 기본 재질의 0.04는 약 56입니다 계산값. 부품이 255 근처의 흰색으로 보인다면 ior만 읽고 specularColor를 빠뜨린 상태입니다(2-2). 디버그 색의 인코딩은 색공간 문서 E3와 같은 방식입니다.

E2. 클리어코트 켜고 끄기 확인함 (2026-11-16)

알파 로메오에서 클리어코트를 켠 씬과 끈 씬을 같은 카메라로 비교했을 때 씬 뷰 픽셀 13,393개가 달랐고, D3D11과 D3D12의 수가 같았습니다. 디버그 뷰 10에서 차체 재질이 세기 1로 보였습니다. 출처: 재질 확장 구현 기록 4장. 디퍼드 전 포워드 경로에서 잰 값이라, 지금 같은 비교를 하려면 --deferred=0으로 하거나 디퍼드에서 다시 재야 합니다. 같은 기록은 specular 텍스처와 클리어코트 텍스처의 화면 효과는 눈으로 확인하지 못했다고 적고 있습니다(알파 로메오의 코팅은 계수만 있음).

E3. DeferredMaterials: G-buffer 재질과 포워드 재질 확인함 (2026-11-18)

테스트 씬 DeferredMaterials.json은 범프 바닥 위에 G-buffer로 가는 재질 넷(D_Dielectric, D_Metal, D_Clearcoat 코팅 1·코팅 거칠기 0.05, D_Cutout)과 포워드에 남는 재질 넷(F_ClearcoatNormal, F_Transmission, F_Unlit, F_Blend)을 둡니다(디퍼드 기록 7장). 디퍼드와 포워드의 차이는 SSAO를 끄고 42,356 px, 8을 넘는 차이는 75 px, 최대 110이었습니다. 디버그 뷰로 재질 입력을 비교하면 albedo·금속·거칠기·F0·노멀이 모두 최대 1이었고, 큰 차이는 노멀 맵 바닥의 그림자 경계로 추적되었습니다. 다만 이 비교에 F90과 코팅 칸(디버그 뷰 10)은 따로 들어 있지 않았습니다. 출처: 디퍼드 기록 8.1.

E4. Specular 슬라이더 예상

비금속 구의 Specular를 1 → 0.5 → 0으로 내립니다. 그림 1대로 정면 하이라이트와 가장자리 반사가 같이 약해지고, 0에서는 반사가 모두 사라집니다. 확산은 kd = 1 − F라 반사가 줄어든 만큼 아주 조금 밝아집니다. 금속성 1인 구에서는 아무 변화가 없어야 합니다(F0 = 기본색, F90 = 1).

E5. 투과 유리의 가장자리 예상

F_Transmission(투과 1, 알파 1, 거칠기 0.05)을 정면과 비스듬히 번갈아 봅니다. 4-2 식대로 정면은 배경이 96% 비치고 가장자리는 환경 반사가 덮어야 합니다. 같은 재질의 Base color 알파를 0.25로 내리면 반사광까지 0.25배가 되어 유리가 거의 사라지는 것을 볼 수 있습니다(금속성 0일 때의 4-2 계산값 0.01). 알파 로메오 유리는 알파는 같아도 금속성이 1이라 투과가 꺼진 다른 조합입니다(4-2).
